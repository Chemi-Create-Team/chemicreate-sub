# 流体の状態（温度・圧力17段階と物質ごとのID統合）

2026-11-21のユーザー指定による仕様書。[温度・圧力の等級](thermal-grades.md)および[熱交換器](counterflow-heat-exchanger.md)の流体状態と冷却規則を更新する。

## 決定事項

| 項目 | 決定 |
| --- | --- |
| 温度 | 5等級の間をさらに3段に分けた17段階 |
| 圧力 | 温度と同じ17段階。圧力の系統もIDを統合する |
| ID | 物質ごとに1つ。液体窒素・熱い水・蒸気・圧縮空気などは、同じIDで内部データ（温度・圧力）だけが違う |
| 相（液体・気体） | 保存しない。温度・圧力と物質の沸点から決める。見た目も相と温度で変える |
| 相が変わるときの量 | 変わる（今の液化・気化と同じ比率） |
| 水と蒸気 | `minecraft:water`の1つにまとめる |
| 熱交換器 | 並行流は2つの温度の平均、対向流はほぼ入れ替わる |
| ラジエーター | 常温まで少しずつ下げる |

以下で「要確認」と書いた項目は、ユーザーの指定がなく仕様書を書く際に決めたもの。変更してよい。

## 1. 17段階の尺度

温度・圧力とも、0～16の整数レベルで持つ。名前のある等級は4の倍数（0・4・8・12・16）に置く。等級の間の3段は、下から「A寄り」「間」「B寄り」と呼ぶ。

### 温度

| レベル | 表示 | 代表温度 |
| ---: | --- | --- |
| 0 | 極低温 | 4 K（−269 ℃） |
| 1 | 極低温と低温の間（極低温寄り） | −214 ℃ |
| 2 | 極低温と低温の間 | −160 ℃ |
| 3 | 極低温と低温の間（低温寄り） | −105 ℃ |
| 4 | 低温 | −50 ℃ |
| 5 | 低温と常温の間（低温寄り） | −31 ℃ |
| 6 | 低温と常温の間 | −13 ℃ |
| 7 | 低温と常温の間（常温寄り） | 6 ℃ |
| 8 | 常温 | 25 ℃ |
| 9 | 常温と高温の間（常温寄り） | 94 ℃ |
| 10 | 常温と高温の間 | 163 ℃ |
| 11 | 常温と高温の間（高温寄り） | 231 ℃ |
| 12 | 高温 | 300 ℃ |
| 13 | 高温と超高温の間（高温寄り） | 425 ℃ |
| 14 | 高温と超高温の間 | 550 ℃ |
| 15 | 高温と超高温の間（超高温寄り） | 675 ℃ |
| 16 | 超高温 | 800 ℃ |

代表温度は、隣り合う等級の代表値の間を絶対温度で等分したもの。沸点の判定と、配管・タンクの定格との比較に使う。プレイヤーには数値を見せない。極低温の代表値を4 Kにしたのは、液体ヘリウム（沸点4.2 K）も液体として扱えるようにするため（要確認）。

### 圧力

| レベル | 表示 | 代表圧力 |
| ---: | --- | --- |
| 0 | 真空 | 0.1 bar |
| 4 | 常圧 | 1 bar |
| 8 | 加圧 | 8 bar |
| 12 | 高圧 | 60 bar |
| 16 | 超高圧 | 300 bar |

間のレベルは代表圧力の対数で等分する（例：レベル6は約2.8 bar、レベル10は約22 bar）。現行の3等級（常圧・加圧・高圧）はレベル4・8・12に対応する。**真空と超高圧は今回新たに追加する等級**（要確認）。等級の範囲は、真空0.5 bar未満、常圧0.5～2 bar、加圧2～20 bar、高圧20～200 bar、超高圧200 bar以上とする。核融合炉の「超高圧配管」は流量の区分を指す名前なので、この等級とは別物。混同しないよう名前の整理が必要（要確認）。

### 表示

- ゴーグル・バケツ・JEI：「温度 高温と超高温の間（高温寄り）／圧力 加圧／気体」のように、温度・圧力・相を1行で表示する。
- 配管・タンクの定格は今と同じく等級名の範囲で表示する。

## 2. 物質ごとに1つのID

### 内部データ

- 温度レベル（0～16）と圧力レベル（0～16）を、流体スタックのData Componentとして持つ。どちらもない場合は、物質ごとの既定値（多くは常温・常圧）を使う。
- 相は保存しない。毎回、温度・圧力・沸点から求める（3章）。
- 現行の`heat_grade`（0～4）は廃止する。読み込み時に4倍して温度レベルへ移す。

### 統合する流体

| 新しいID（物質） | まとめる旧ID |
| --- | --- |
| `minecraft:water` | 水、温排水`warm_water`、蒸気`steam`、高圧蒸気`high_pressure_steam`、過熱蒸気`superheated_steam`、加圧給水`pressurised_water`、高温炉冷却材`hot_reactor_coolant` |
| 窒素 | `nitrogen_gas`、`liquid_nitrogen` |

| 水素 | `hydrogen_gas`、`pressurised_hydrogen`、`compressed_hydrogen` |

- 残すIDは、基本的に旧IDのうち常温・常圧の側（例：`nitrogen_gas`、`air_gas`）。登録名に「gas」が残るものは表示名だけを物質名にする（ID変更による移行を減らすため。要確認）。
- 旧IDは、読み込み時に「新ID＋温度・圧力」へ読み替える（5章）。
- 圧縮合成原料のように、組成ではなく圧力だけが違うものは、すべて統合の対象。組成が違うもの（合成ガスと合成混合物など）は統合しない。

### 水を`minecraft:water`にまとめることの影響

ユーザーの判断で1つにまとめる。そのため、次の点を受け入れる。

- 気体状態の水（蒸気）も、ほかのMODやCreate本体からは「水」に見える。Createのボイラー・鉢・ミキサーのレシピ、ほかのMODの液体の水を使う処理が、蒸気や熱い水を水として受け取る可能性がある。
- バニラのワールド上の水ブロックは状態を持たない。常温・常圧の水だけを設置でき、それ以外の状態のバケツは設置できない（6章）。
- 対策の候補（要確認）：このMODの装置から出る水は、ほかのMODの受け口へ流れても止めない（Createの配管の仕組み上、止められない）。必要なら、Createのボイラーと鉢だけをMixinで「液体の水だけ受け取る」に限定する。

## 3. 相の決定と量の変化

- **沸点**：物質の常圧の沸点（`FluidMaterials`の表）から、クラウジウス・クラペイロンの式で圧力ごとの沸点を求める。蒸発熱は物質ごとに`chemistry/fluids.json`へ登録し、未登録ならトルートンの規則（88 J/mol/K×沸点）で近似する。
  - 例：水は常圧で100 ℃なので、レベル9（94 ℃）までは液体、レベル10（163 ℃）からは気体になる。高圧（60 bar）では沸点が約270 ℃になり、レベル12（300 ℃）で気体。
- **臨界点**：今回は扱わない。沸点より上はすべて気体とする。
- **量の変化**：温度や圧力の変化で相が変わると、量を換算する。換算比は液体と気体の密度比（現行の`PhaseChange.ratio`と同じ）。例：液体窒素1 mBが気体窒素約700 mBになる。
- 換算で割り切れない分は変換せず、元の相のまま残す。換算によって物質が増えないようにするため。
- **気体の量**：気体のmBは常圧換算量とし、圧力が変わっても量は変えない（今の圧縮と同じ）。
- **混合気体**：混合物全体で1つの温度・圧力を持つ。成分ごとの凝縮（混合気体から水だけが液体になるなど）は今回の範囲外とし、混合物は気体のまま扱う（要確認）。

## 4. 温度と圧力を変える装置

| 装置 | 動作 |
| --- | --- |
| タンク下のブレイズバーナー | 50 tickごとに温度レベルを1上げる。1等級分（4レベル）で200 tickになり、今と同じ速さ。16で止まる |
| 熱交換器 | 下記 |
| ラジエーター | ファンで、通過する流体の温度を常温（8）まで1レベルずつ下げる。常温以下には下げない。処理量は今と同じ |
| 冷却塔 | 水を常温まで下げる（温排水の変換を置き換える） |
| 往復式圧縮機 | 1段で圧力を4レベル（1等級）上げる。温度は変えない |
| 減圧弁 | 1段で圧力を4レベル下げる |
| コールドボックス | 窒素・酸素・ヘリウムを液体になる温度まで下げる（今の液化を、温度を下げる処理に置き換える） |

### 熱交換器

- 2つの流体を1バッチずつ（同じ量で）組み合わせて処理する。処理量は今と同じく構造の大きさで決まり、対向流の1.5倍は廃止する。
- **並行流**（同じ側から入れる）：両方が2つの温度の平均になる。平均が整数にならない場合は、熱い側を切り上げ、冷たい側を切り捨てる（熱を増やさない）。
- **対向流**（向かい合う側から入れる）：熱い側は冷たい側の入口より1つ上まで下がる。冷たい側は熱い側の入口より1つ下まで上がる。温度差が1以下なら変化しない。
- どちらの流体も、どちら側に入れてもよい。熱い方・冷たい方は温度レベルで自動的に決まる。今の「冷やすもの」「冷媒」の表はなくなる。
- 温度が変わって沸点をまたげば相も変わり、量も換算する（例：液体アンモニアが気体になる）。両方の出口に入りきることを確認してから、一度だけ確定する（今と同じ）。
- 同じ温度の2つは処理しない。ゴーグルに「温度差がありません」と表示する。

## 5. レシピ・保存・互換

### レシピ

- 流体の材料は「物質＋条件（温度レベルの範囲、圧力レベルの範囲、相）」で指定する。今の「液体窒素」は「窒素・液体」に、「高圧水素」は「水素・圧力 高圧以上」に書き換える。
- 生成物は、物質と温度・圧力を指定する。指定がなければ物質の既定値。
- ふた付き槽などの加熱条件（加熱・超加熱）は今のまま、ブレイズバーナーの段階で判定する。
- JEIは条件を「窒素（液体・極低温）」のように名前の横へ表示する。

### 混合

- 同じ物質で温度・圧力が違うものを同じタンクで混ぜると、量で重み付けした平均レベルになる（四捨五入）。今の「低い方にそろえる」から変更する。
- 相の違う同じ物質（気体の窒素と液体の窒素）は、混ぜた後の温度で相を決め直し、量を換算する。

### 配管・タンクの定格

- 定格は今と同じく5等級の範囲（圧力は真空と超高圧を加えた5等級）で表示する。
- 流体のレベルの代表値が定格の範囲を外れていれば、今と同じく損傷する（例：レベル13は425 ℃なので高温の範囲内、レベル14は550 ℃なので超高温）。
- 気体の貯蔵倍率（常圧×1、加圧×16、高圧×64）はタンクの定格で決め、今と同じ。超高圧の定格を持つタンクは今はない。
- 配管の定格は液体にだけ適用する。気体は、温度・圧力・相から気体と判定されれば、材質を問わずどの配管でも運べる（バルブを除く）。液体の混合物は最も厳しい成分で判定する。
- 2026-11-21のユーザー指定で、ステンレスボイラーは定格外の流体で損傷しない。ボイラーで損傷するのは銅（Create標準の流体タンクと横型流体タンク）だけ。
- 2026-11-21のユーザー指定で、気体パイプと太い気体パイプを廃止した。保存済みのブロック・アイテム・ブロックエンティティは強化パイプへ読み替える（`CELegacyIds`）。気体ポンプ・大型気体ポンプのレシピは強化パイプを使う。大流量の主管にはステンレス配管を使う。

### 既存ワールドの移行

- 旧ID（2章の表）を、新ID＋温度・圧力へ読み替える。対象はタンク・配管・装置の中身、バケツ、混合物の成分（`MixtureContents`のキー）、ワールドに置かれた流体ブロック。
- 旧IDの読み替え先の状態（要確認、現在の等級をもとにした案）：

| 旧ID | 温度 | 圧力 |
| --- | --- | --- |
| 温排水 | 9（常温と高温の間・常温寄り） | 常圧 |
| 蒸気 | 12（高温） | 常圧 |
| 高圧蒸気 | 12（高温） | 高圧 |
| 過熱蒸気 | 16（超高温） | 高圧 |
| 加圧給水 | 10（常温と高温の間） | 加圧 |
| 高温炉冷却材 | 11（高温寄り） | 高圧 |
| 液体窒素・液体酸素 | 1 | 常圧 |
| 液体ヘリウム | 0 | 常圧 |
| 液体アンモニアなど常温付近で液化するもの | その物質が常圧で液体になる最も高いレベル | 常圧 |
| 熱い工程流体（hot_〜） | 12（高温） | 元の流体の圧力 |
| 圧縮空気・圧縮合成原料・加圧水素など | 元の流体の温度 | 元の流体の圧力等級 |

- 旧IDのアイテム（バケツなど）も新しいバケツへ読み替える。
- 旧`heat_grade`は4倍して温度レベルに移す。

## 6. 見た目・バケツ・ワールド上の流体

- **テクスチャ**：同じIDでも、相によって液体用と気体用のテクスチャを使い分ける（NeoForgeの`IClientFluidTypeExtensions`はスタックごとにテクスチャと色を返せる）。気体は薄い半透明。
- **色**：温度で色味を変える。超高温に近づくほど赤く光り、極低温に近づくほど白っぽく霜がかった色にする。
- **バケツ**：物質ごとに1種類（例：窒素バケツ）。中身の温度・圧力をアイテムのデータとして持ち、名前に状態を添える（「窒素バケツ（液体・極低温）」）。
- **ワールドへの設置**：ワールドの流体ブロックは状態を持たない。設置できるのは物質の既定状態（多くは常温・常圧）の液体だけ。それ以外の状態のバケツは設置しない。気体を設置しようとした場合は、今の有毒・可燃ガスの放出と同じく雲にする（要確認）。
- **クリエイティブタンク**：今と同じくバケツで中身を選ぶ。状態もバケツのデータをそのまま使う。

## 7. 実装の順番

一度にすべてを変えず、次の順に分けて実装し、それぞれで既存の動作を保つ。

1. 温度17段階の導入：既存IDのまま、`heat_grade`を温度レベルへ置き換える。バーナー・ラジエーター・熱交換器を新しい規則にし、表示を変える。
2. 気体と液体の8組の統合：相の決定、量の換算、テクスチャの切り替え、旧IDの移行。
3. 熱い工程流体（hot_〜／cold_〜など）の統合。
4. 水と蒸気の統合（`minecraft:water`）：ボイラー、タービン、復水器、冷却塔、RBMK・核融合炉の給水との接続を確認する。
5. 圧力17段階と、圧力の系統の統合：圧縮機・減圧弁、真空・超高圧の等級。

各段階で、変更した操作のPonder（熱交換器・ラジエーター・バーナー加熱・コールドボックスなど）とJEIの表示を更新する。

## 8. 受け入れ条件

- 物質の総量が、温度・圧力の変化、相の変化、混合、保存・再読込で増えたり減ったりしない（換算比による変化を除く）。
- 熱交換器の並行流・対向流、ラジエーター、バーナーの各規則を、GameTestで温度レベルごとに確認する。
- 旧IDを含む既存ワールドを読み込み、中身・バケツ・混合物の成分が失われず、正しい状態に読み替えられる。
- 水を統合した後も、Createのボイラー・蒸気エンジンと、このMODのタービン・RBMK・核融合炉の給水が動く。
- 相ごとのテクスチャと温度の色を、実際の画面でタンク・配管の窓・バケツについて確認する。

## 範囲外

- RBMK・核融合炉の内部温度・核反応計算は、今と同じく例外として連続値で持つ。
- 連続的な温度・圧力・熱量の計算や、配管の自然放熱・凍結は行わない。
- 圧縮による温度上昇、混合気体の成分ごとの凝縮、臨界点は扱わない。

## 実装で決めた互換処理

- 高温炉冷却材は高圧のまま液体で搬出できるよう、レベル11へ読み替える。レベル12の高圧水は気体になるため、旧セーブの冷却材には使わない。
- 水と蒸気の換算は既存の発電・復水系に合わせて1対1とする。液化・気化を行う既存の8組は従来の量の比率を使う。
- 旧流体ブロックを読み込むと、既定の液体で表現できるブロックは新IDへ置き換わる。状態を表現できない場所では、源を温度・圧力付きバケツのドロップに変換する。流下部分は源のバケツに含まれる。
- 熱交換器は混合気体を気体のまま冷却する。ガス化炉の湿りガスは、冷却後に既存の吸収塔またはタンクのドレン処理を使って分離できる。

## レシピのデータ形式

Createの処理レシピでは、流体材料に `type: "create_refinery_n_reactors:fluid_state"` と `fluid`、`amount` を指定できる。`min_temperature`、`max_temperature`、`min_pressure`、`max_pressure` は端を含む0～16の範囲で、`phase` は `liquid` または `gas`。省略するとその条件を問わない。生成物の `components` に `create_refinery_n_reactors:temperature_level` と `create_refinery_n_reactors:pressure_level` を使える。

`process` の工程表では、流体材料の `condition` オブジェクトに同じ範囲を指定する。生成物では `temperature` と `pressure` を指定する。
