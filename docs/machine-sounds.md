# 設備の運転音

原子炉、核融合炉、蒸気タービンと処理設備は、実ワールドでの稼働に合わせて運転音を出します。音量はMinecraftの「サウンド設定」→「ブロック」で調整できます。字幕を有効にすると、稼働している設備の種類も表示します。

形成した設備のコントローラーが1つの音を担当します。同じ槽の壁、タービンの複数ローター、ラジエーターの各セルから重複して鳴らしません。単に置いた部品、静的なタンクや配管、停止中の処理設備は対象外です。

| 音源 | 対象と再生条件 |
| --- | --- |
| 原子炉の低い運転音 | 形成したRBMK炉の核反応出力がある間。小型・従来型に共通 |
| 核融合炉の駆動音 | 形成した炉で加熱・磁石への実給電、または核融合出力がある間 |
| 高圧タービン | 形成した高圧段で、いずれかのローターが蒸気から仕事を取り出している間 |
| 低圧タービン | 形成した低圧段で、いずれかのローターが仕事を取り出している間 |
| 圧縮機 | 往復式コンプレッサーに実処理流量がある間 |
| 撹拌・遠心機構 | 形成した撹拌反応槽・ガス遠心分離機が処理中 |
| 高温処理 | 予熱器、ふた付き槽の触媒床、電解炉、ガラス固化炉、転炉の実加熱・反応・吹錬中 |
| 流体処理 | 触媒・吸収棚段を装着した槽、分留塔、フィルタープレス式電解セルの処理中。復水器・自然通風冷却塔の放熱中、再処理設備の抽出中、燃料電池の発電中も含む |
| 冷却ファン | 形成したラジエーターバンクのファンが実際に回転している間。流体が空でも回転音は鳴る |
| クレーン | 形成した門型クレーンが作業中 |
| フレア | 着火したフレア先端が実際にガスを燃焼している間 |

自然通風冷却塔には、モーター式ファンの音を割り当てていません。流体・熱を処理している間の流体音を使います。

停止、構造破損、距離外、チャンクのアンロード、ワールドの切替、音量ゼロで再生を終了します。再び有効な稼働状態が同期され、範囲内に入ると再開します。Ponderでは実ワールドでの挙動を説明し、教材の仮想ワールドから実稼働音を鳴らすことは前提にしていません。

## 探索と再生の上限

音の位置から32マス以内を対象にし、近い設備を優先して最大24音を再生します。カメラ周辺3チャンク以内の読み込まれたチャンクを分割して調べます。探索は5 tickごとで、新たに開くチャンクは最大4、候補BlockEntityは最大128です。未ロードのチャンクを読み込んだり、毎tick全BlockEntityを走査したりしません。

再生中は取得済みのコントローラーの状態を確認します。タービンの構造と電解槽列の所有者は毎秒再確認し、失効した設備の音が残るのを防ぎます。ファン回転数はラジエーターの既存処理周期で、既に登録された最大8個のファンから取得・同期します。

## 音源と開発用確認

音源は外部録音を使わない独自合成の11種類で、各6秒・モノラル・22,050 HzのOgg Vorbisです。次のコマンドで生成と数値・参照チェックを行えます。音源の生成・検証にはVorbis対応のlibsndfileが必要です。

```sh
python3 tools/generate_machine_sounds.py
python3 tools/generate_machine_sound_resources.py
python3 tools/validate_machine_sounds.py --require-definitions
```

`CEMachineSounds`が音イベントを登録し、`MachineSoundSource`が既存の稼働状態を音に対応付け、`MachineSounds`がクライアント内の探索と停止を管理します。サーバー側に音の再生状態や追加の加工在庫は持ちません。

開発用の統合クライアント確認に`createplant.machineSoundClientCheck=true`を指定すると、`SoundClientCheck`が実モーター・有限水入りファンバンクを使います。停止、実SoundEngineでの開始、同一設備の重複防止、停止・再始動、ブロック音量、距離、実チャンクのアンロード・再ロード、構造破損、後始末を確認します。結果はゲームディレクトリの`machine-sound-client-result.json`へ出力します。通常プレイではこのfixtureを生成しません。

デコード・波形の数値検査と、クライアントの再生状態の確認は別です。[統合試験報告](reports/powders-compact-reactor-sounds.md)に結果を記録しています。音声機器のない検証コンテナではOpenALのNo Outputを使い、実SoundEngineでの開始・停止・再始動・ミュート・距離・チャンク再読込・構造破損を確認しました。物理スピーカーからの実聴評価は行っていません。
