# 汎用混合液・混合気体

内部部品のないふた付き槽へ異なる液体を入れると、1つの混合液として保持します。水・自Mod・他Modの液体を流体レジストリIDで扱います。気体は液体と混ざらず、気体同士で混合気体（キャリア `gas_mixture`）になります。専用の混合ブロックやGUIは追加しません。既存の反応を使う場合は、その工程の内部部品と入力口を使用します。

混合液はCreateの通常パイプ・ポンプ・タンクで保管・輸送できます。すべての成分が配管・タンクの材質と温度・圧力等級に適合する必要があります。混ぜたことで酸などの制限を回避することはできません。キャリアの `chemical_mixture` は配管・タンク内で保持する流体で、専用バケツやワールドへ置く液体ブロックは持ちません。開放端はキャリアの排出を受け付けません。

総量と各成分量は整数mBです。抜き出す側を最大剰余法で割り当て、残る側は元の各成分から差し引きます。槽・Createタンクを分割するときも同じ補完関係を使い、成分ごとの量を保ちます。純粋流体への自動復元は `MixtureHelper.createStack(contents, true)`、または `MixtureFluidTank` の `unwrapPureOutput` で選べます。

色は各成分の本来の色をmB量で加重平均します。水のスタック色が白の場合は標準の水色を使用します。ゴーグルは4行以内で総量と主成分を表示し、多い場合は残りの成分数を示します。Display Linkの「混合液の成分」は、量の多い順に全成分の名前・mB・割合（小数第1位まで）を渡します。成分数に合わせた大きさのDisplay Boardを使ってください。

## 混合気体

気体は成分ごとのmB（割合）を持つ1つの混合気体として運びます。混合気体の種類ごとの実装はなく、どの気体の組合せでも同じ共通処理で扱います。

- タンク：気体を貯める等級付きタンク（ガス受け・ガスタンクコンテナ・伸縮ガスホルダーなど）へ別の気体が入ると、1つの混合気体になります。容量は通常の気体と同じ定格倍率です。抜き出すと各成分を量の比で取り出します。液体は混合気体に入りません。
- 配管：混合気体はすべての配管・ポンプで運べます（気体の定格は従来どおり）。配管の合流点で別々の気体を混ぜることはせず、混ざるのはタンクと装置の中です。
- 装置の入口（`GasMixturePort.inlet`）：混合気体の各成分を装置へ渡し、装置が使う成分だけを取り込みます。使わない成分は装置の素通しバッファ（`GasPassThrough`、最大64,000 mB）に入り、気体の出口から出ます。使える成分が1つもない混合気体は受け付けません。素通しバッファのない装置（フレア・水性ガスバーナー）は、すべての成分を使える場合だけ受け付けます。
- 装置の出口（`GasMixturePort.outlet`）：そのポートが出す気体の生成物と素通し分を、量の比で1つの混合気体として出します。気体が1種類だけなら純粋な流体のままです。液体の生成物は別に出します。
- 例：ふた付き槽で硫黄を空気で燃やすと、二酸化硫黄500 mBと窒素1900 mBが1つの混合気体として出ます。これを吸収塔の最下段へ送ると二酸化硫黄だけが吸収され、窒素は最上段の側面から出ます。
- 放出：混合気体が漏れたり装置が壊れたりしたときは、成分ごとに有毒・可燃ガスの雲になります。

適用している装置：撹拌槽・ふた付き槽・横置き熱交換器、吸収塔、反応塔、分留塔、アンモニア分離槽、転炉、電解セル、燃料電池、核融合炉の流体ポート、極低温コールドボックス、リリーフスクラバー、ラジエーター、往復式圧縮機、ガス化炉、燃料サイクル装置、湿式処理槽、ガス遠心分離機、フレア、水性ガスバーナー。

## 実装API

- `MixtureContents(Map<ResourceLocation, Integer>)`：唯一の量の正本です。0以下の量を取り除き、ID順の不変マップにします。`merge`・`split`・`totalAmount` と永続化／ネットワークのCodecを備え、int合計のオーバーフローは拒否します。
- `MixtureHelper.extractContents` / `createStack`：単一流体とキャリアを相互変換します。キャリアの成分合計とスタック量の不一致、未知のID、キャリアの入れ子は受け付けません。
- `MixtureFluidTank(int capacity, boolean unwrapPureOutput, Runnable onContentsChanged)`：異種液体を受ける標準の流体ハンドラーです。保存と同期はFluidStackのCodecとData Componentを使い、槽の保存用NBTは通常のコンテナとしてだけ使います。シミュレーションは在庫も通知回数も変えません。
- `MixtureData`：温度等級・放射性核種などの各成分のData Componentを保持する補助データです。量を重複して保存しません。同じ流体IDの異なる温度や核種の混合には既存の混合則を使い、他Mod独自の互換性のないプロパティ同士は拒否します。
- `MixtureGoggleHelper.describe`：全成分の表示リスト、`appendSummary`：4行までの概要を作ります。

混合した瞬間の化学反応や混合物の蒸留レシピは追加していません。今後の反応・分離は `extractContents` と `components` で在庫を読み、`split` と `merge` で物量を確定し、`createStack` で残量・生成物を返す形で接続できます。装置側の再評価はタンクの `onContentsChanged` から開始できます。コードの共通処理だけで新しい流体の組合せに対応でき、流体ごとの専用ブロックを追加する必要はありません。

## Createとの接続

ふた付き槽の既存在庫に混合を接続しています。処理用内部部品のある槽とその他のCreateタンクでは、異なる純粋流体を自動で混ぜず、すでに作られたキャリアを保持・輸送します。Createの流体識別の変更はキャリアの配管ルーティングと連結判定に限定し、グローバルなFluidStackの成分比較とハッシュは維持します。

Createの1mBプレビューは全成分を表せないため、キャリアの場合は元の成分情報で材質の適合を判断します。FluidStackのコピー・縮小、ネイティブタンクの充填、分岐の残量、タンクの分割を限定的なMixinで接続しています。成分の生データを独自CompoundTagへ保存する経路はありません。
