# 指示書：転炉（酸素製鋼とAOD）

この文書は、Codexへの作業依頼です。作業の前に `AGENTS.md` と `DESIGN.md` を読み、その規約に従ってください。特に、マルチブロックの[構造とライフサイクル](../../DESIGN.md)、入出力、Ponder の決まりを守ってください。

## 背景と決定事項

- 鋼（Createの鋼材ブロック `create:industrial_iron_block`）は、今はパドル法（パドル鉄を5回プレス）だけで作れます（`docs/specs/steel-unification.md`）。
- ユーザーの決定：
  - 新しいマルチブロック「転炉」を作る。パドル法との違いは、次の4点。
    - 規模：1回でまとめて作る。
    - 歩留まり：鉄が少なくて済む。
    - 加熱：要らない。
    - 前提：酸素が要る（中盤以降）。
  - 同じ転炉で、吹き込む気体を替える。酸素なら鋼、アルゴンならステンレス鋼（AOD精錬）。撹拌反応槽のAODレシピは、材料が上限を超えて読み込まれていなかったため、2026-11-06に削除済み。
  - 副産物は転炉ガス（一酸化炭素）。工業用加熱器の燃料にする。
  - パドル法は、序盤の少量向けとしてそのまま残す。
- 数値は、ユーザーが了承した案です。釣り合いが悪いと分かったら変えてよいですが、理由をレポートに書いてください。

## 全体の約束

- 作業ブランチは `main` です。プッシュの前に `git fetch origin main` → `git rebase origin/main` を行い、強制プッシュはしないでください。
- 既存の仕組みを再利用してください。新しいクラスは、転炉に必要なものだけにします。
  - 構造の判定と形成：当時の吸収塔・反応塔の実装（撤去済み）を参考にした。所有者の形成・解体・保存・再読み込みも、同じやり方に揃える。
  - 流体の温度：`FluidThermal`
  - 有毒ガス：`ToxicGas`
  - 火傷：`HotSurfaces`
  - 回転：Create の `KineticBlockEntity`
- 監査（`docs/reports/chat-feature-overhaul-audit.md`）で見つかった不具合を、繰り返さないでください。
  - どの部品を壊しても、所有者がすぐ止まること。
  - 中身が消えたり増えたりしないこと（所有ブロックを壊したときに一度だけ出す。有毒な気体は雲にする）。
  - 見た目と当たり判定を一致させること。
  - Create の開いた鉢には気体が入らないこと。気体を使う工程は、鉢のレシピにしないこと。
- 表示する文言は翻訳キーにし、英・日・中の3言語を入れてください。Ponder を中国語に訳すなら、全文を訳してください（`validate_ponder_language.py` が確かめます）。

## 1. 構造

- 9×9の底面で高さ11、可動炉体は最大幅5×5のマルチブロック（2026-11-06にユーザーが旧5×5×7から変更）。床や足場は作らず、支柱と桁で炉体を懸垂します。
- 構成ブロックは既存のものを優先します。
  - 外周の4本の支柱、上部外周・十字桁、トラニオン高さの側面桁は、Createの鉄骨`create:metal_girder`をそのまま使います。
  - 各支柱の独立基礎は磨かれたブラックストーンレンガ、トラニオン受けは銅ブロックです。銅は酸化段階とワックスの有無を問わず使えます。
  - 酸素ランスまでの縦配管はCreateの流体パイプ、原料口までの縦搬送はCreateのシュートを使います。
  - 新しいブロック「転炉の炉殻」は、可動炉体の当たり判定、左右トラニオン、ランス、原料口、転炉ガス口、出鋼口にだけ使います。炉殻の作業台レシピには、鋼材ブロックと耐火物（ジルコニア、またはレンガ）を使ってください。
- 左トラニオンの1か所だけが所有ブロックとなり、在庫・状態・処理を持ちます。ほかの炉殻部品は所有者に問い合わせるだけにします。
- 入出力（すべて Create の標準の搬送で使えること）：

| 場所 | 役割 |
| --- | --- |
| 上面中央のCreate流体パイプと酸素ランス | 気体の入口。酸素（気体、または液化酸素）かアルゴン。液化酸素は1 mBを酸素の気体699 mBとして数える（`PhaseChange` の比） |
| 上面右のCreateシュートと原料口 | 原料の入口。シュート、ファンネルなどCreate標準搬送から入れる |
| 背面上部 | 転炉ガスの出口。標準流体Capabilityで配管へ出す |
| 前面の出鋼口 | 製品の出口。傾いているときだけ出る |

- 回転：側面のどれかに Create のシャフトをつなぎ、回転で炉を傾けます。
  - 傾けている間は、原料と気体を受け付けず、出鋼口から製品を出せる。
  - 立てている間に吹錬（気体を吹き込んで反応させる）する。
  - 傾きの状態は BlockState か同期した値で持ち、クライアントは補間して描きます（毎フレームのパケットは使わない）。
- 見た目：炉の外殻・トラニオン（傾ける軸）・ランスが分かるモデルにします。傾きは、可動部を Flywheel の Visual か BlockEntityRenderer で描きます。当たり判定は、立った状態の炉の形に合わせてください。

## 2. 吹錬（1チャージ）

| 吹き込む気体 | 原料 | 気体 | 製品 | 副産物 | 時間 |
| --- | --- | --- | --- | --- | --- |
| 酸素（製鋼） | 鉄インゴット48、粗鉄24（鉄鉱石・深層鉄鉱石も可） | 酸素64,000 mB（鋼材1個あたり1,000 mB） | 鋼材ブロック64 | 転炉ガス8,000 mB | 800 tick |
| アルゴン（AOD） | 鉄インゴット112、クロムインゴット32、ニッケルインゴット16 | アルゴン1,600 mB | ステンレス鋼インゴット192 | なし | 800 tick |

- 新しいレシピ型（例：`converter`）を作り、上の2つを JSON にします。JEI に表示してください（JEI なしでも動くこと）。
- 1チャージの原料と気体がそろい、製品と副産物の置き場が空いているときだけ、開始時に消費を確定します。途中で止まった場合や満杯の場合に、増えたり消えたりしないこと。
- 加熱は要りません。吹錬中の炉は高温（例：1,900 K）として扱い、`HotSurfaces` で触れると火傷します。
- 撹拌反応槽のAODレシピは削除済みです（読み込まれていなかった）。AODの文書（`docs/metals.md`、`docs/distillation-plant.md`）は「転炉で行う予定」になっているので、転炉の内容に書き直してください。
- 転炉のレシピJSONが読み込まれることを、`CraftingRecipeGameTests.everyRecipeFileOfTheModLoads` が確かめます。材料の数に上限があるレシピ型を使うなら、上限に収めてください。
- 酸素とアルゴンの量の根拠（2026-11-06）：空気分離塔の質量を直した（コミット `43671be`）。空気1,000 mBから酸素210 mB分、アルゴン10 mBが出る。
  - 製鋼1チャージの酸素64,000 mBは、空気約305,000 mB（3×3の塔で約170秒）に当たる。液化酸素なら約92 mB。
  - AOD 1チャージのアルゴン1,600 mBは、空気160,000 mBに当たる。
  - 遊んで重すぎる・軽すぎると分かったら変えてよいが、理由をレポートに書くこと。
- 原料の入口は、1チャージ分（製鋼72個、AOD 160個）をためられる大きさにする。

## 3. 転炉ガス

- 新しい気体「転炉ガス」（`converter_gas`、一酸化炭素）を登録します。登録する場所：
  - `FluidPhase`：一酸化炭素の物性（分子量28、沸点81.6 K など）。
  - `ToxicGas`：強さ1で、色を決める。
  - `FluidHazards`：腐食はなし。
  - バケツ・翻訳。
- 工業用加熱器の燃料にします。
  - 今の燃料：軽油34,000 J/mB、ガソリン32,000 J/mB、重油38,000 J/mB（`docs/thermal-equipment.md`）。
  - 加熱器の燃料口が気体を受け付けるか確かめ、受け付けるようにします。
  - 発熱量は、一酸化炭素の燃焼熱（283 kJ/mol）と、このMODの気体1 mBの物質量から求めます。1チャージ分の転炉ガスで加熱器をどれだけ動かせるかを、レポートに書いてください。
- 転炉ガスの出口が使えない（満杯・何もつながっていない）ときは、転炉を止めます。ガスを勝手に捨てたり、雲にしたりはしません。

## 4. 解体・保存

- 所有ブロックを壊したとき：
  - 原料と製品はアイテムとして落とす。
  - 気体は、酸素・アルゴンは捨てる。転炉ガスは有毒ガスの雲にする。
  - 吹錬の途中なら、そのチャージは失われる（開始時に消費済み）。この点を文書に書きます。
- ほかの部品を壊したとき：所有者はすぐ止まり、次の tick で構造を確かめ直します。中身は残します。
- 保存と再読み込みで、状態・進み具合・傾き・在庫が変わらないこと。

## 5. Ponder と文書

- 新しい Ponder「転炉で鋼を作る」：
  - 組み方 → 原料と酸素を入れる → 吹錬 → 回転で傾けて出鋼する → 転炉ガスを工業用加熱器へ送る。
  - アルゴンでステンレス鋼を作ることも示します。
  - 炉殻・鋼材ブロック・ステンレス鋼インゴットから開けるようにします。
- 文書：
  - 新規 `docs/converter.md`。
  - `docs/metals.md`（鋼とステンレス鋼の節）、`docs/distillation-plant.md`（酸素とアルゴンの用途）、`docs/thermal-equipment.md`（燃料）、`docs/toxic-gas.md`（転炉ガス）、`PONDER_GUIDE.md`。

## 確認と完了

GameTest で、少なくとも次を確かめてください。

- 酸素で鋼材ブロック64個と転炉ガス8,000 mBができ、アルゴンでステンレス鋼192個ができる。液化酸素を入れても同じ量の酸素として数える。
- 原料か気体が足りないとき、製品か転炉ガスの置き場が満杯のときは、始まらず、何も減らない。
- 立てている間は出鋼しない。傾けている間は受け付けない。
- 吹錬の途中で部品を壊すと止まり、中身は残る。所有ブロックを壊すと、中身が一度だけ出て、転炉ガスは雲が1つになる。
- 保存と再読み込みで、状態が変わらない。
- 工業用加熱器が転炉ガスを燃料として燃やす。
- 撹拌反応槽のAODレシピがない。鉢のレシピが気体を要求しない（既存の `noBasinRecipeAsksForAGas`）。
