# 指示書：等級化の後始末と、遊ぶ目的の追加

実装の結果と、この指示書から変えた点（B1の2段目を加圧浸出にしたことなど）は`docs/reports/goal-map-implementation.md`にあります。

この文書はCodexへの作業依頼です。作業の前に `AGENTS.md` と `DESIGN.md` を読み、その規約に従ってください。数値は目安です。釣り合いが悪ければ変えてよいですが、変えた理由をレポートに書いてください。

- 作業ブランチは `main` です。段階ごとにコミットしてください。プッシュの前に `git fetch origin main` と `git rebase origin/main` を行い、強制プッシュはしないでください。
- 原子炉（`nuclear/`、`FuelChannelBlockEntity`、`FuelPoolBlockEntity`、`CraneDriveBlockEntity` など）のJavaは、この文書が名指しする箇所以外は変えないでください。
- レシピ・アセット・翻訳・Ponderの文は、関係する `tools/generate_*.py` を正本として生成してください。翻訳は英・日・中の3言語です。
- 新しい流体やアイテムは、どうしても必要なときだけ足してください。まず既存のものと既存の設備（撹拌反応槽、電解セル、パルス式溶媒抽出塔、燃料チャネルの照射など）で済ませます。

温度・圧力の等級化（`docs/specs/thermal-grades-codex-spec.md`）は完了しました。レビューでは、全GameTest 520件のうち519件が合格しています。失敗は以前からある `afouledprocessstopsthenresumesafteronemanualbrush` の1件だけです。クライアントでもPonder 140シーンを確認しました。その結果、残骸がいくつか見つかりました（A章）。

## B. 遊ぶ目的の追加

### 方針
- 各段階に、普段の遊びが楽になる外向けの見返りを1つ以上付けます。素材を作るだけで終わる段階をなくします。
- 柱は2本です。**鉱石の収率**（B1）と**回転力の供給**（B2）です。どちらも序盤から最後まで「次の段階に進むほど得をする」という動機が続きます。
- 見返りはCreateの遊び方に合わせます。道具や防具の強化、電力による汎用加工機は足しません。
- すでにある見返りは作り直さず、案内（B6）で目立たせます。

### 今ある見返り（作り直さない）
| 仕組み | 見返り |
| --- | --- |
| 工業製品の出荷票（`industrial_delivery/`） | 燃料・合金・ゴム・肥料・建材・樹脂を出荷して、エメラルドと経験値を得る |
| ANFO爆薬・発破薬・門型クレーンの採掘 | 範囲採掘 |
| 蒸気タービン（低圧・高圧・強化） | 回転力（SU） |
| 燃料電池 | Electro Energeticsの電力 |
| 硝酸アンモニウム → 火薬、樹脂 → 革・ベルト、アルミナ → 紙やすり | バニラ・Createの素材 |

### B1. 鉱石の収率（新規・最優先）
Createの粉砕と洗浄だと、原石1個からインゴット約1.75個です。これを工程を進めるごとに上げます。

| 段階 | 工程 | 原石1個あたりのインゴット（目安） |
| --- | --- | --- |
| Create標準 | 粉砕 → 洗浄 | 約1.75 |
| 酸浸出 | 粉砕済み鉱石 ＋ 硫酸 → 撹拌反応槽で浸出液 → 電解セルで金属 | 約2.5 |
| 溶媒抽出 | 浸出液 → パルス式溶媒抽出塔で精製し、副産物も回収 → 電解セル | 約3.5（＋副産物） |

- **対象：** Createの粉砕済み鉱石（鉄・銅・金・亜鉛）と、このMODの鉱石のうち金属になるもの。共通タグ（`c:` の名前空間）で受け、他MODの鉱石にも効くようにします。
- **浸出液：** 金属ごとに流体を増やさないでください。1種類の「金属浸出液」流体に、どの金属かをデータコンポーネントで持たせる方式を第一案にします。Createの配管・タンクで中身が混ざらないこと（成分の違う液体を同じタンクに入れない）を確かめてください。無理なら金属ごとの流体にして、その理由をレポートに書きます。
- **副産物（溶媒抽出）：** 銅 → 金のナゲット、鉄 → ニッケル（ペントランド鉱の代わり）など、少量だけにします。副産物だけで本来の鉱床が要らなくなる量にしてはいけません。
- **使う設備：** 撹拌反応槽のレシピ（`recipe/pressure_reaction/`）、電解セル、パルス式溶媒抽出塔のレシピ（`recipe/solvent_extraction/`）。新しい設備は作りません。
- **酸の扱い：** 硫酸は消費します。廃液は今ある洗浄排水の処理系に流します。
- **確認：**
  - GameTestで、原石1個から各段階の収率が表どおりになること（端数の扱いを含む）。
  - 浸出液が混ざらないこと。
  - 一度に処理したときに複製も消失も起きないこと。
- **Ponder：** 「鉱石を増やす」を新しく作り、浸出 → 電解 → 溶媒抽出の配置と流れを見せます。

### B2. 回転力の段階（既存の数値を計測して調整）
Createの終盤で一番困るのは回転力（SU）です。発電の段階を、次の段階に進む価値がはっきりわかる差にします。

1. 次の構成を、決まった設置の大きさで組み、GameTestで実際のSUを計測して表にします。
   - Createの蒸気エンジン（最大段階）
   - 低圧タービン
   - 高圧タービン
   - 強化タービン
   - RBMK（タービンを含む全体）
   - 核融合（全体の正味の出力）
2. 目安：設置面積あたりの正味SUが、段階ごとに前の段階の約3〜4倍になること。核融合は正味で黒字（自分の磁石の給電を差し引いても余る）にします。
3. 数値を変えるのは、タービン側の設定値や、炉からタービンへの蒸気量の換算だけです。原子炉の炉心計算は変えません。
4. 計測した構成、変更前後のSU、条件をレポートに残してください（`AGENTS.md`の最適化の節にある計測の書き方に従います）。

### B3. 肥料（ハーバー・ボッシュ法の見返り）
- 硝酸アンモニウムと硫酸アンモニウムを、骨粉のように作物へ使えるようにします。効果は**周囲3×3の作物を1段階成長**させることです。
- 使い方は、手で右クリックすることと、Createのデプロイヤーで使うことの両方です。実装は `item/` に置き、骨粉と同じイベントで成長させます。
- 骨粉より明らかに得なのは範囲だけにします。1回の成長量は骨粉と同じです。
- 確認：GameTestで、3×3が成長することと、デプロイヤーから使えることを確かめます。Ponderは「肥料」を1シーン作るか、ハーバー・ボッシュ法のPonderに1手順足します。

### B4. 燃料（調査のみ）
低硫黄軽油などの液体燃料で、Createのブレイズバーナーや蒸気エンジンを動かせないか調べてください。
- Create 6.0.10のソースで、液体燃料を受け付ける拡張点があるかを確かめます。
- 拡張点がない場合は、Mixinで無理に足さないでください。調査結果と案をレポートに書くだけにします。

### B5. 最終目標：核融合の中性子照射による資源合成
- 核融合炉の中性子で**照射ターゲットから希少資源を合成**できるようにすることを最終報酬にします。
- 今ある照射の仕組み（リチウム照射ターゲット棒 → 照射済み）はRBMKの燃料チャネル（`FuelChannelBlockEntity`）の中にあり、原子炉のJavaなので変えられません。そこで、核融合炉の増殖ブランケットのカートリッジ（`lithium_lead_blanket_cartridge` → `spent_blanket_cartridge`）と同じ差し替えの流れに、照射用のカートリッジを1種類足せるかを調べてください。
- 第一案は、ネザライトの欠片です。照射カートリッジの材料に古代の残骸以外の素材（例：金とチタン）を使い、核融合炉を長時間運転して少量だけ得られるようにします。
- **ここはユーザーの最終決定待ちです。** 実装はB1〜B3の後にしてください。決まるまでは、レシピの案とバランスの見積もり（ネザライトの欠片1個あたりの運転時間と消費資源）をレポートに書くだけにします。

### B6. 案内を目的の順に組み直す
- 実績ツリー（`guide/`）と説明書（`tools/generate_manual.py`）を、設備の作り方の順から目的の順に組み直します。
  1. はじめに（鋼と撹拌反応槽）
  2. 鉱石を増やす（B1）
  3. 回転力を増やす（タービン → RBMK）
  4. 農業（B3）
  5. 採掘（爆薬・クレーン）
  6. 出荷（出荷票）
  7. 最終目標（核融合、B5）
- 各章の最初のページには「この章を進めると何ができるようになるか」を1文で書きます。
- 実績の説明文にも、作る物の名前だけでなく見返りを書きます（例：「鉱石が2.5倍になる」）。
- `ManualGameTests` のページ数と実績のIDの一覧も更新してください。
- 英語のページがはみ出さないことを、既存の折り返しチェックで確かめます。
