# 実装指示書：雲の範囲と水蒸気のもや（分担A）

この作業では、実装（Java・クライアント描画・テスト・Ponder・翻訳）とテクスチャの作成を行います。作業前に`AGENTS.md`と`DESIGN.md`を読み、そこにある規約（生成元が正本、Ponder必須、mod ID不変、旧データの互換、完了レポート、コミットとプッシュ）に従ってください。

対象：Minecraft 1.21.1、NeoForge 21.1.219、Create 6.0.10、Java 21。mod IDは`create_refinery_n_reactors`です。

## 分担

ガスの雲の作り直しは、2つに分けて進めます。この指示書は分担Aです。

| 分担 | 担当 | 内容 |
| --- | --- | --- |
| A（この指示書） | Codex | 汎用の「雲の範囲」の仕組み、もやの描画、保存と同期、水蒸気の雲、ガス回収ダクトとガス検知器の対応、プロセスガスの記録の廃止 |
| B | 別の担当者 | 既存の`ToxicGas`（ステータス効果）と`FlammableGas`（爆発）を、分担Aの雲に載せ替える |

- 分担Aでは、`safety/ToxicGas.java`、`safety/ToxicGasEffect.java`、`safety/FlammableGas.java`、それらのテストを**変更しないでください**。どの流体にどんな効果があるかも、分担Aでは扱いません。
- 分担Aで作る雲は、それ自体では生き物にも周りのブロックにも何もしません。範囲を持ち、描かれ、問い合わせに答えるだけです。分担Bが後からこの問い合わせを使います。

## 目的

ブロックの隙間をたどって決まったマス数の範囲を作り、半透明のもやとして描く、汎用の「雲」を作ります。最初の利用者は水蒸気です。

- 高圧蒸気の管が壊れたときや、フレアから蒸気を出したときに、白いもやが部屋に広がって見えるようにします。
- 今の「プロセスガスの記録」（`ProcessGasIncidents`、1マスに白い煙が出るだけ）を、この雲に置き換えます。
- ガス回収ダクトとガス検知器を、新しい雲に対応させます。

## 1. 雲の見た目の設定（登録式）

流体ごとに、雲をどう広げてどう描くかを登録する仕組みを作ります（例：`GasCloudStyles`）。

| 設定 | 内容 |
| --- | --- |
| 埋める向き | 床側から／天井側から |
| 色 | 色付きのもやとして描く場合の色。描かない場合はなし |
| 屋外での消え方 | 長さを何分の1にするか |

- 分担Aで登録するのは**水蒸気だけ**です（通常・高圧・過熱）。「天井側・白・屋外では長さの6分の1」にします。
- 登録のない流体では、雲を作りません。
- 分担Bが他の流体を登録できるよう、登録は公開の静的メソッドにします。

## 2. 雲の範囲

### 範囲の作り方

- 雲を出す位置から、通れるマスだけをたどって範囲を作ります。
  - 出す位置が設備などのブロックなら、その6方向の隣で通れるマスから始めます。
- **マス数**：`clamp(8 + 量 / 20, 8, 512)`。目安は1,000 mBで約58マス、10,000 mBで512マスです。
- **たどる順番**：
  - 「床側」の雲は低い段を優先し、同じ段では出した位置に近い順に埋めます。
  - 「天井側」の雲は高い段を優先します。
- **たどれる範囲**：出した位置から水平±8、上下±4のマス（17×9×17の箱）に限ります。

### 通れるかどうか

- マスAから隣のマスBへ向きdで進むとき、次の両方を満たせば通れます。
  - Aの当たり判定が、dの軸に沿った断面を塞いでいない。
  - Bの当たり判定も、同じ断面を塞いでいない。
- 「断面を塞ぐ」とは、当たり判定をその軸に沿って投影したとき、1×1の面が埋まることです。
  - 閉じたドア、トラップドア、つながった板ガラス・鉄格子は面を塞ぐので通しません。
  - 開いたドアは向きが変わって面を塞がないので通します。
  - 柵、ハーフブロックの横、空気などは通します。
- 液体が入っているマス（水源・流水）は通しません。
- 判定結果は「ブロックの状態×軸」ごとに覚えておき、同じ状態は再計算しません。当たり判定は`state.getCollisionShape(EmptyBlockGetter.INSTANCE, BlockPos.ZERO)`で取ります。

### 作り直し

- 範囲内でブロックが置かれた・壊れたら「作り直しが必要」と印を付け、最大100 tickに1回まとめて作り直します。
- 印がなくても100 tickごとに作り直し、量が残っている間は少しずつ広がって見えるようにします。
- 作り直しでブロックを読むのは、範囲の外枠の中だけにします。

### 屋外と消え方

- 範囲を作るときに、空が見えるマス（`canSeeSky`）を1つでも含めば屋外とします。作り直すたびに判定し直します。
- 雲の長さは、20秒＋5 mBごとに1 tick、最大2分です。屋外では登録した割合で短くします。
- 時間とともに残りの量を減らし、0になったら雲を消します。

### 合流

- 新しい雲を出す位置（または開始マス）が既存の雲の範囲に入っていて、同じ流体なら、その雲の量を増やして範囲を作り直します。
- 違う流体どうしは混ぜず、別の雲にします。

## 3. 描画（クライアントのみ）

- 色のある雲を、雲の範囲内で重なり合う薄いもやとして描画します。床側の雲は各層の下側、蒸気など天井側の雲は上側に寄せます。
- 1マスにつき2枚の傾斜した面を使います。周囲のマスも雲に含まれるところでは、もやが隣のマスまで流れます。
- 近くのもやはゆるやかに向きを変えながら同じ方向へ流れます。個々の筋は時間差で生まれ、曲がりながら広がり、薄くなって消えます。
- 雲の範囲が変わったときに描画に使う場所を作り直します。残りの量の同期値を補間して、雲全体の濃さを表示します。
- `textures/entity/gas_mist.png`（64×32）は輪郭が透明に溶ける横長の霧の模様です。流体ごとの色を掛けて使います。
- 48ブロックより遠い雲は描画しません。近づくと徐々に濃くします。
- カメラが色のある雲の範囲に入ったら、`ViewportEvent.ComputeFogColor`と`ViewportEvent.RenderFog`で、画面の霧の色を雲の色に、霧の距離を3〜4ブロックにします。
- パーティクルは使いません。

## 4. 実装の形

- 範囲の作成・通れるかどうかの判定・ビット列の扱いは、独立したクラスにします。
- 雲は専用のエンティティ`gas_cloud`にします。チャンクと一緒に保存・読み込みされます。
  - 毎tickの処理は、経過時間を数えることだけです。範囲の作り直しは最大100 tickに1回です。
- **保存するもの**：流体ID（成分などのデータ付きの流体なら、そのデータも）、残りの量、長さ、経過時間、範囲（外枠の原点と大きさ、マスごとの有無のビット列）。見た目の設定は流体から引き直します。
- **クライアントへ送るもの**：範囲のビット列、流体ID、残りの割合。
  - 範囲が変わったときだけ送り、残りの割合は1秒に1回まで更新します。
  - `SynchedEntityData`の`COMPOUND_TAG`などを使い、毎tickは送りません。
- エンティティの当たり判定の箱は範囲の外枠にします。視界外の雲を描画しないようにするためです。

### 分担Bが使う問い合わせ

雲のエンティティ（またはそれを扱うクラス）に、次の公開メソッドを用意します。分担Aの中では、回収ダクトと検知器がこれを使います。

| 問い合わせ | 内容 |
| --- | --- |
| 雲を出す | `GasClouds.release(level, pos, fluidStack)`。登録のない流体なら何もしない。合流もここで行う |
| 範囲内か | ブロック位置、または正確な座標（「床側」の一番上の層の厚さを考慮）が範囲内か |
| 近い順のマス | ある位置から、通れる判定でつながった範囲内のマスのうち、最も近いもの |
| 量を減らす | 雲から指定量を取り出し、取り出した流体を返す。0になったら雲を消す |
| 一覧 | ある範囲の箱に入っている雲の一覧 |
| 毎秒の通知 | 雲ごとに1秒に1回呼ばれる処理を、外から登録できる仕組み（分担Aでは何も登録しない） |
| 作り直しの通知 | 範囲を作り直した直後に呼ばれる処理を、外から登録できる仕組み（分担Aでは何も登録しない） |

## 5. 置き換える仕組みと既存の設備

### プロセスガスの記録（`ProcessGasIncidents`）

- 記録をやめ、クラスと保存データを削除します。既存ワールドの保存データ（`create_refinery_n_reactors_process_gas_incidents`）は読み込まず、そのまま捨てます。
- 高圧蒸気の管が壊れたとき（`PipeGasFlow`）は、管の位置に水蒸気250 mBの雲を出します。
- フレアから蒸気を出したとき（`FlareTipBlockEntity`）は、出した量の水蒸気の雲を出します。フレアの蒸気以外の処理は変えません。
- **未処理プロセスガス**（`raw_process_gas`）は、新しく作られなくなります。
  - 既存ワールドのタンクやバケツに残った分のために、流体・バケツの登録と、大型吸収塔の洗浄レシピは残します。
  - JEIとクリエイティブタブからは隠します。

### ガス回収ダクト

- 記録の代わりに、新しい雲から流体を取り出します。
  - 吸込口から4ブロック以内で、通れる判定でつながっている範囲のマスを対象にします。
  - 10 tickにつき最大250 mBを雲の量から減らし、その流体のままバッファへ入れます。
- バッファは4,000 mBで、入るのは1種類の流体だけです。別の流体の雲は、バッファが空になるまで取り出しません。
- ゴーグルに、取り出している流体の名前を表示します。
- 取り出した流体は、ノズルからパイプで送り出せます。
- ファンの条件、保存、ドロップは今のままにします。既存ワールドのバッファに残った未処理プロセスガスは、そのまま搬出できます。

### ガス検知器（`GasDetectorBlock`）

- 新しい雲を検知します。
  - 検知器の周囲4ブロックに範囲のマスがあれば、最も近いマスとの距離と雲の残りの量から、信号を0〜15で出します。
  - 通れる判定でつながっていないマス（壁の向こう）は数えません。
- 今の、バニラの効果の雲を使う検知は、そのまま残します（分担Bで置き換えます）。プロセスガスの記録による信号は削除します。

## 6. 負荷の上限

- 1つの雲のマスは最大512、たどれる範囲は17×9×17の箱です。
- 範囲の作り直しは、雲1つにつき最大100 tickに1回です。
- 1チャンクに置ける雲の数を制限します（例：8）。上限を超えたら、近くの雲に合流させます。
- 1 tickで作り直す雲の数に上限を設け、超えた分は次のtickへ回します。
- **計測**：水蒸気の雲を同時に32個出した状態で、変更前後のtick時間とフレーム時間を比べ、結果をレポートに残します。

## 7. Ponder

- Ponder「プロセスガスの検知と回収」を作り替えます。
  1. 高圧蒸気の管が壊れて、白いもやが部屋に広がる。
  2. 閉じたドアの手前でもやが止まり、ドアを開けると向こうへ広がる。
  3. ガス検知器が反応し、レッドストーンランプが点く。
  4. 回収ダクトがもやから水蒸気を取り出し、パイプで送り出す。
  5. 屋外では早く薄まって消える。
- 説明文は`tools/data/ponder_lessons.json`に日英中で書き、`tools/generate_ponder_language.py`で翻訳を作り直します。

## 8. テスト（GameTest）

- **埋める向き**：閉じた部屋で、水蒸気の範囲は天井の段から埋まる。テスト用に「床側」の設定を一時登録した流体では、床の段から埋まる。
- **ドア**：閉じたドアの向こうに範囲のマスがなく、開けて作り直すと広がる。
- **壁**：壁の向こうのマスは範囲に入らない。
- **マス数と箱**：量に応じたマス数になり、17×9×17の箱を出ない。
- **合流**：隣で出た同じ流体の雲は、1つの雲になって量と範囲が増える。違う流体は別の雲になる。
- **屋外**：空の見える場所では長さが登録した割合で短くなる。
- **保存**：保存して読み込んだ雲の範囲・量・経過時間が同じ。
- **登録のない流体**：雲を作らない。
- **水蒸気**：高圧蒸気の管を壊すと水蒸気の雲が出る。フレアから蒸気を出すと水蒸気の雲が出る。
- **回収ダクト**：水蒸気の雲から水蒸気を取り出し、雲の量が同じだけ減る。別の流体の雲は、バッファが空になるまで取り出さない。壁越しの雲からは取り出さない。
- **ガス検知器**：雲の残りの量と距離に応じて信号が変わり、雲が消えると0に戻る。壁越しの雲には反応しない。
- **旧データ**：未処理プロセスガスの入ったバッファやタンクを読み込んでも、搬出と洗浄ができる。プロセスガスの古い保存データがあっても、エラーにならない。
- 既存の`ProcessGasRecoveryGameTests`は、プロセスガスの記録を直接確かめている箇所を、新しい雲の確認に書き換えます。`ToxicGasGameTests`と`IndustrialGasSafetyGameTests`は変更せず、そのまま通ることを確認します。
