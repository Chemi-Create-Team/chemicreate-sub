# 指示書：1.0に向けた全機能のオーバーホール

この文書は、Codexへの作業依頼です。作業の前に `AGENTS.md` と `DESIGN.md` を読み、その規約に従ってください。

## 目的

このMODは身内のサバイバル用で、近くサバイバルを始めます。1.0として区切りを付ける前に、すべての機能を点検し、**サバイバルで遊んで困る不具合をなくす**ことが目的です。

- 新しい機能は足しません。仕様を変えるのは、不具合を直すのに必要な場合だけにします。
- 前回の監査（`docs/reports/chat-feature-overhaul-audit.md`）と、その対応（`docs/reports/chat-feature-overhaul-fixes.md`）のやり方を引き継いでください。前回は追加機能だけでしたが、今回はMOD全体が対象です。

## 範囲と、直してよいもの

### 報告だけにする機能（直さない）

次の機能で不具合を見つけたら、**報告だけ**にしてください。コード・データ・アセット・翻訳・テストは変更しません。直し方の案は、報告に書いてかまいません。

| 機能 | 主な場所 |
| --- | --- |
| RBMK原子炉（炉心・燃料チャンネル・制御棒・プラグ・物理計算・自動制御） | `nuclear/`、`CENuclear`、`FuelChannel*`、`RodCap*`、`ControlRod*`、`ReactorCore*`、`tools/generate_rbmk_assets.py` |
| 原子炉の制御卓・計器盤・記録計・炉心図 | `ReactorControlConsole*`、`ReactorConsole*`、`ReactorChartRecorder*` |
| 使用済み燃料プール | `FuelPool*`、`nuclear/FuelPoolStructure`、`tools/generate_fuel_pool_assets.py` |
| 核融合炉と制御卓 | `fusion/`、`CEFusion`、`Fusion*`、`tools/generate_fusion_assets.py` |
| 門型クレーン（採掘場のマーカーを含む） | `CECrane`、`Crane*`、`QuarryMarker*`、`tools/generate_crane_assets.py` |
| ウラン燃料の製造工程（鉱石からペレット、遠心分離機の濃縮、燃料棒、再処理のレシピ） | `CEUranium`、ウラン関係のレシピ、`tools/generate_uranium_assets.py` のウランの部分 |

気をつける点：

- 次のものは、名前が似ていても**原子炉関係ではありません**。直してよい側です。
  - 化学の「反応槽」（`lidded_vessel`に触媒充填バスケット・撹拌翼・分離棚段・遠心ロータ柱を入れる設備。`ReactorMachine*`も処理を担当する）。
  - 燃料電池（`FuelCell*`）。
- 両方が入っているファイル（翻訳ファイル、`ponder/tutorials.json`、`tools/generate_uranium_assets.py`（撹拌反応槽・吸収塔も含む）、`CECreativeModeTabs` など）は、原子炉関係でない部分だけ変更してよいです。
- 共通の仕組み（`thermal/`、`transport/`、`safety/` など）を直すと、原子炉関係の動きが変わることがあります。その場合は、直す前に影響を報告に書き、原子炉関係の既存テストがすべて通ることを確かめてください。原子炉関係の動きを変えないと直せないなら、直さずに報告だけにします。

### 直してよい機能

上の表以外のすべてです。化学・石油化学・ソーダ工業・金属・電解・転炉・鋼・圧縮機・タンク・配管・熱設備・タービン・有毒ガス・安全装置・Ponder・JEI・文書などが入ります。

## 点検すること

各項目で見つけたものを、重さ（重大・高・中・低）と一緒に記録してください。

### 1. サバイバルで最後まで進めるか（最優先）

- 何もない状態から、すべての設備・素材を、サバイバルで手に入る材料だけで作れるか。レシピの依存をたどる自動の点検（GameTestか `tools/` のスクリプト）を作ってください。
- 次のものに頼る経路がないか確かめます。
  - クリエイティブ専用の素材（例：液体空気は作り方がない）。
  - 作る順番が循環している工程。
  - 読み込まれないレシピ。
- 鉱石が実際のワールドで生成されるか。高さ・量・バイオームの設定が、文書と合っているか。

### 2. 物の消失・増殖

- 設備を壊す・満杯になる・途中で止める・保存して読み込み直す・チャンクがアンロードされる、という操作で、アイテム・流体・気体・エネルギーが消えたり増えたりしないか。
- 前回見つかった種類の不具合（中身が無言で消える、部品を壊しても処理が続く、など）が、ほかの設備に残っていないか。
- 置いている部品（電極板・触媒・カートリッジなど）が、ブロックを壊したときに落ちるか。

### 3. 水と環境

- 形が1ブロックに満たない設備（`noOcclusion` の登録、約51か所）が、流れる水で壊れないか。壊れるなら、安全弁と同じく `forceSolidOn` などで直してください（直してよい側だけ）。
- 有毒ガス・火傷・凍傷が、意図した場面だけで起きるか。

### 4. 表示と翻訳

- 英・日の翻訳が揃っているか。キーがそのまま出る場所がないか。
- ゴーグル・Display Link・JEIの表示が、実際の動きと合っているか。
- Ponderの説明が、今の仕様と合っているか（数値・手順・作り方）。

### 5. 性能

- 多数を並べる設備（配管・タンク・鉢の電解槽・ラジエーターなど）で、毎tickの重い処理や、無駄な全探索がないか。
- 必要なら、台数を決めて計測し、変更の前後を比べてください（AGENTS.mdの最適化の節）。

### 6. 文書

- 各設備の文書（`docs/`、`INDUSTRIAL_SYSTEMS.md`、`DEVELOPMENT_CHEMISTRY.md`、`PETROCHEMISTRY.md`、`README.md`、`PONDER_GUIDE.md`）が、今の実装と合っているか。
- 削除した機能の記述が残っていないか。

### 7. コードの不具合（バグ）の点検

上の1〜6とは別に、**すべてのクラスのコードを読んで**不具合を探してください（原子炉関係も読み、報告だけにします）。少なくとも次を見ます。

- **処理の誤り**
  - 条件の取り違え、境界値（0・満杯・上限ちょうど）の扱い、単位の取り違え（mB・kg・Pa/bar・K/°C・J/W・tick/秒）。
  - 整数の切り捨てで量が合わなくなるところ。
- **クラッシュの原因**
  - null、配列の範囲外、0での割り算、NaN・無限大が保存データや計算に入るところ。
  - ほかのModのブロックや流体が来たときに落ちるところ。
- **サーバーとクライアントの分け方**
  - 共通のコードからクライアント専用のクラスを参照していないか。専用サーバーで起動して確かめます。
  - クライアント側で物を消費・生成していないか。
- **保存と同期**
  - 書き込んだ値をすべて読み込んでいるか。読み込みで値の範囲を確かめているか。
  - 古い保存データや壊れた保存データで落ちないか。
  - 変化したときに必要な相手へ同期しているか。
- **Capability（搬入・搬出）**
  - 面の扱いが正しいか（`null` の面を含む）。
  - SIMULATEで中身が変わらないか。
  - 戻り値（受け入れた量・取り出した量）が実際と合っているか。
  - 構造が変わったあとに、古いハンドラーが残っていないか。
- **キャッシュ**：無効にする条件の漏れ（構造の変更、チャンクのアンロード、レシピの再読み込み、ディメンションの移動）。
- **イベントとMixin**
  - 登録漏れ・二重登録。
  - Createや他Modの更新で外れやすいMixin（対象のメソッドが存在するか。`require` の設定は合っているか）。
- **ログ**
  - 起動時・ワールド読み込み時・全件テストの実行中に出るエラーと警告を、すべて洗い出す。
  - 例：読み込まれないレシピ・ルートテーブル・タグ・モデル・テクスチャ、翻訳キーの抜け、Mixinの警告、例外のスタックトレース。
  - このMODが原因のものは直し（直してよい側だけ）、ほかのModや環境が原因のものは、その旨を報告に書きます。

見つけた不具合ごとに、再現の手順（またはコード上の根拠）と、起きる結果を報告書に書いてください。

## 作業の進め方

- 作業ブランチは `main` です。プッシュの前に `git fetch origin main` → `git rebase origin/main` を行い、強制プッシュはしないでください。
- **先に点検して報告書を作り、そのあと直す**順で進めてください。修正は、内容ごとに小さな日本語のコミットに分けます。
- 1つ直すごとに、その不具合を再現するテストを足し、失敗することを確かめてから直してください（前回の監査の対応と同じやり方）。
- 生成ファイルは `tools/generate_*.py` を直して作り直してください。ただし、生成スクリプトが今のアセットより古い場合があります（作り直すとテクスチャやPonderの構造が古いものに戻った例がありました）。作り直したら差分を見て、関係のないファイルが変わっていたら元に戻してください。
- 前の作業のときに受けた「全件テストを省略してよい」という指示は、今回は**当てはまりません**。最後に必ず全件を流してください。

- `bash gradlew build runGameTestServer` を全件と、`-PwithJei=false` でも全件流し、両方の結果を報告書に書く。

- 報告書の実装コミットの欄は、まず `COMMIT` と書いてコミットします。そのあとハッシュに置き換え、もう一度コミットします。リベースでハッシュが変わったら、プッシュの前に書き直してください。
