# Mod分離の計画（2026-11-28）

方針：化学の本体と、アドオン2つ（原子炉・製鉄、物流・採掘）の計3つに分ける。コードは未変更。

| Mod | Mod ID | 表示名 | Gradle |
| --- | --- | --- | --- |
| 本体（化学） | `create_refinery_n_reactors`（今のまま） | Create: Refinery 'n' Reactors | `core/` |
| 原子炉・製鉄 | `create_rnr_atomics` | Create: Refinery 'n' Reactors - Atomics & Steel | `atomics/` |
| 物流・採掘 | `create_rnr_logistics` | Create: Refinery 'n' Reactors - Logistics & Mining | `logistics/` |

依存の向きは一方通行：**アドオンは本体に依存する。本体はアドオンに一切依存しない**（コード・データ・レシピ・Ponder・JEIのどれでもアドオンの物を参照しない。本体だけで起動・プレイできる）。アドオン同士も依存しない（連携は「両方入っていれば有効」の任意連携にする）。

## 1. 分け方

### 本体（化学）
- Mod ID は今の `create_refinery_n_reactors` のまま。本体側のブロックは既存ワールドでそのまま残る。
- 入れるもの
  - 流体と気体、温度・圧力・二相流・ガス雲などの共通の仕組み
  - 電解槽、反応塔、吸収塔、分留塔、熱交換器、圧縮機、ガス化炉、ふた付き槽・撹拌槽
  - 配管・ポンプ・タンク・計装（PID、流量計など）・安全設備
  - CDG（原油・燃料）と CEE（電力）の連携
  - 鉱石と基本素材（鋼、ステンレス、ニッケル、クロムなど）。全部の Mod が使うので本体に置く。
  - 蒸気タービン一式（復水器、冷却塔を含む）、ステンレスボイラー
  - 電池、燃料電池、送電鉄塔
  - 農業（噴霧器、肥料、農薬）
- 必須依存：Create、CDG、CEE（今と同じ）。

### アドオン1：原子炉・製鉄（`create_rnr_atomics`）
- 入れるもの
  - 原子炉（RBMK）、燃料サイクル、再処理、ガラス固化、遠心分離、放射線
  - 核融合
  - 製鉄：転炉、トーピードカー、連続工場（圧延機、ロータリーキルン、巻取機など）、大型プレス
  - 炉の保守用クレーン

### アドオン2：物流・採掘（`create_rnr_logistics`）
- 産業用アーム、出荷ボード、採石場、発破、リレー計算機

### 決定済み（2026-11-28）
- タービン、冷却塔、ステンレスボイラーは本体。電池・燃料電池・送電鉄塔は本体。農業は本体。
- アーム・採石場・出荷ボード・リレー計算機などは物流・採掘のアドオン。
- 大型フライホイール（色違い16種）はタービン側として本体に仮置き。不要なら削除候補。
- キュービックプレスは製鉄側として原子炉・製鉄のアドオンに仮置き。

## 2. 今の結びつき（調査結果）

ファイル名・パッケージ名で機械的に分けた目安（GameTest を除く）。

- 原子炉・製鉄側：166ファイル、約2万行。本体側：642ファイル、約6万4千行（この時点ではタービン等を原子炉側に数えた目安。物流・採掘側は未集計）。
- アドオン → 本体の参照：202件。問題ない（アドオンは本体に依存してよい）。
- **本体 → アドオンの参照：328件。これを0にするのが分離の本体の作業。**
  - 多いところ：`MachineReadings`（ゴーグル・表示）、`ElectrolysisClient`、`CreatePlantJeiPlugin`、`PowerPlantClientCheck`、`CreatePlant`（登録の起点）、`MachineSoundSource`、`AssemblyPlan`（施設建設機）、`ElectrolysisPonderPlugin`、`ProcessPorts`、`CERecipeTypes`、`CEDisplays`、`FacilityAchievements`、クリエイティブタブ。
- 前例：`CELegacyIds` が旧 Mod ID からの ID 変換（`addAlias`）を既にやっている。NeoForge 21.1.219 の `DeferredRegister.addAlias` も確認済み。

## 3. やり方

### 手順1：1つの Mod のまま、本体 → アドオンの参照を切る（一番大きい）
本体に「登録口」を作り、アドオン側の部品が自分で登録するように向きを逆にする。

- 登録（ブロック、アイテム、BE、流体、レシピ型）：アドオンのものは `CENuclear`、`CEFusion`、`CEConverter` などのクラスに既に分かれている。これらをアドオン側の起点から呼ぶようにして、`CreatePlant` から外す。
- ゴーグル表示・Display Link（`MachineReadings`、`CEDisplays`）：表示する値を返す仕組みを本体に置き、アドオンの BE が自分で実装する。
- JEI、Ponder、音、実績、クリエイティブタブ、施設建設機の設計図（`AssemblyPlan`）：本体側に一覧の登録口を作り、アドオンは自分のプラグインやイベントから登録する。
- レシピの関係：本体の普通のレシピがアドオンの素材を必須にしていないか確認する。連続工場の素材を使う「別ルート」のレシピ（`*_from_thick_plate` など）はアドオンへ移す。
- 各段階で GameTest（今 819 件）を全部通す。

### 手順2：Gradle をマルチプロジェクトにして物理的に分ける
- 同じリポジトリに `core/`、`atomics/`、`logistics/` を作る。アドオンは `core` に依存。別リポジトリにすると、本体の変更とアドオンの追従が噛み合わなくなりやすい。
- Java のコードをパッケージごと各アドオンへ移す。
- リソース：アセット、データ（レシピ、実績、ルートテーブル、タグ）、言語ファイル（en/ja/zh）、Ponder の文章を分ける。
- `tools/` の生成スクリプトも、どちらの出力先に書くか分ける。

### 手順3：既存ワールドの ID を引き継ぐ
- アドオンは起動時に、旧 ID `create_refinery_n_reactors:<名前>` から新 ID `<アドオンID>:<名前>` への別名（`addAlias`）を、ブロック、アイテム、BE、流体ごとに登録する（`CELegacyIds` と同じ方法）。
- アドオンを入れないと、そのブロックはワールドから消える。リリースノートに明記する。

### 手順4：確認
- 本体だけで起動、本体＋アドオンで起動、の両方で GameTest を通す。
- 分離前のワールドを本体＋アドオンで開き、原子炉・製鉄のブロックと中身が残ることを確認する。
- 本体だけで開くと、本体側のプラント（電解槽・反応塔など）が壊れないことを確認する。

### 手順5：リリース
- 本体は 0.6.0、アドオン2つは 0.1.0 から。
- 手順1〜5は、先に原子炉・製鉄を分け、同じ手順で物流・採掘を分ける。
- 移行の手順（両方入れてから一度ワールドを開く）を書く。

## 4. 注意点
- アドオン同士のつながり：クレーン（原子炉側）が産業用アーム（物流側）を参照している（`CraneDriveBlockEntity`、`CranePonderScenes`）。キュービックプレスにもアームの連携点（`compat/CubicPressArmPoint`）がある。共通部分を本体へ移すか、任意連携にする。
- 一番手間がかかるのは手順1。いきなりファイルを移すと、コンパイルが通らない期間が長くなる。
- ファイル名からの機械的な仕分けなので、`RodCapBlockEntity` や `Factory*` のように混ざっているものは個別に見る必要がある。
- 両方の Mod が使う流体（硫酸、硝酸、水素など）は本体に置く。アドオン専用の流体（ウラン系など）だけ移す。
