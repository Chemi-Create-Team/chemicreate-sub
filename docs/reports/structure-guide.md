# 未成立マルチブロックの最小構成ガイド（ゴースト表示） 完了レポート

## 調査結果
- 構造判定は装置ごとに別実装：`HaberBoschStructure`（反応塔）、`ReactorStructure`（縦型の反応槽・分離塔）、`TankStructure`（タンク外殻の円筒）、`GasHolderStructure`（球）、`SteamPlantStructure`、`HorizontalThermalStructure`、`GasCompressorBlockEntity.scan`、`HighPressureTurbineMultiblock` など。共通の基盤はない。
- 描画に使える既存の仕組みはなく、`RenderLevelStageEvent`（NeoForge 21.1）を使った。

## 実装
- `guide/`（共通・描画なし）：`GhostLayout`（候補1つ分の全セルと「正しい」判定）、`StructureGuide`（アンカー検出と候補生成）、`GuideSelector`（候補選択）、`TowerGuide`、`ReactorGuide`。
- `client/StructureGuideRenderer`（クライアント専用、`ElectrolysisClient`から登録）：周囲3チャンク以内のブロックエンティティを0.5秒ごとに走査し、計画をキャッシュする。毎フレームはキャッシュ済みの不足セルだけを、実際のブロックモデルで半透明（不透明度40%）に描く。`RenderType.translucentMovingBlock`と、アルファを掛けるラッパーを使用。ワールドの変更、ブロックエンティティ、保存データ、サーバー処理は追加していない。
- 既存の成立判定は変更していない。`ReactorStructure.matches`（既存の`part`の公開版）を判定と共有し、塔は`HaberBoschStructure`の定数（山3〜12個）と同じ規則から候補を作る。

## 最小構成の選び方
1. 候補は構造規則が許すサイズすべて（反応塔は山3〜12個＝全高5〜14、反応槽は1〜4段、分離塔は2〜4段）。
2. 各候補で、設置済みの正しいブロックを流用し、不足セル数を数える。
3. 一部が未ロード、または置換できない別のブロックがある候補は除外（ブロックを壊させる案内はしない）。
4. 不足が最少の候補を採用し、同数なら全体が小さい候補。全て除外なら何も表示しない。
- 既存の山が積まれていれば、それより低い候補は上蓋の位置に山が来て除外されるため、自然に最低限の高さになる。

## 表示条件
- 反応塔：底面中央の反応塔の真上に山があり、未成立のとき。反応槽・分離塔：縦型で未成立のとき。成立するとアンカーの条件を満たさなくなり、次の走査で消える。コントローラが壊れれば消える。

## 確認
- `runGameTestServer` 297件成功（最小の塔、既存の山による高さの下限、設置済みブロックの流用、障害物で非表示、成立後に非表示、反応槽の候補数）。専用サーバーでも読み込み可能。
- 実クライアントで未完成の塔に半透明のゴーストが描かれることを撮影で確認（窓なしの塔モデル）。

## 未対応・制約
- 対応は反応塔と縦型の反応槽・分離塔のみ。タンク外殻（円筒、位置が自由）、ガスホルダー（球）、蒸気設備、ガス圧縮機、横型の加熱器・熱交換器、タービン、蒸留塔、電解槽は未対応（それぞれ別の判定で、アンカーと候補生成の実装が必要）。
- 反応塔は山を1個置くまでガイドが出ない（底面中央が特定できないため）。
- ゴースト同士の内側の面は消していないため、重なって濃く見える。反応槽の実表示は未撮影。
- 走査は0.5秒間隔で、設置後の更新に最大0.5秒かかる。
- 実装コミット：b95df3b

## タンク外殻への対応（追加）
- `guide/TankGuide`：`TankStructure`と同じ規則（直径4〜32、壁の高さ2〜64、床は円形の全セル、壁は輪郭のセル、内部は空気、壁の上の層に外殻なし）から候補を作る。床・壁は外殻ブロックのゴースト、内部と上の層は「空けておくセル」（描画せず、塞がれていれば候補から除外）。
- 位置は自由なので、周囲±31の床の高さの外殻のうちx、zの順で最小のものを基準に、直径ごとに1つの配置を作る（円の最小セルは直径に依らず同じ位置の列にあるため、実際に組んだ円と一致する）。高さは最小（2）と、既存の外殻の最大の高さの2通り。
- 成立済みのタンクの外殻はガイドの起点にしない（クライアントでは制御用の外殻しか成立を知らないため、成立済みの形状に含まれる外殻を除外）。同時に案内するのはプレイヤーに最も近い1か所。
- 選択器：不足数が現在の最良を超えた候補はその場で打ち切る（直径ごとの全セル走査を避ける）。
- 確認：`runGameTestServer` 299件成功（1個の外殻から最小のタンク、既設の外殻の流用、塞がれた候補の除外、成立済みタンクには出ない）。実クライアントで未完成のタンクに半透明の外殻ゴーストが描かれることを確認（撮影の構図は粗い）。
- 制約：別の位置に組まれた複数の外殻の塊は、最小のx・zの外殻を基準にするため、その並びに合う配置しか流用しない。高さは2と既存の最大の高さのみを候補にする（途中の高さは候補にしない）。
- 実装コミット（タンク外殻）：5072caa

## ガスホルダー（球）への対応（追加）
- `guide/GasHolderGuide`：`GasHolderStructure`と同じ規則（直径4〜16、殻は球のセルのうち外に面するもの＝Create工業用鉄ブロックまたは既存のガスホルダー殻、内部は空気）から候補を作る。殻は工業用鉄ブロックのゴースト、内部は「空けておくセル」。
- 成立前の球にはブロックエンティティがなくコントローラが存在しないため、「工業用鉄ブロックを手に持っている間だけ、周囲12マス以内の最も近い工業用鉄ブロックを起点に出す設置プレビュー」とした。起点は周囲±15の工業用鉄ブロックのうち、最も低く、次にx、zの順で最小のもの（最下層のその位置は直径に依らず同じ殻のセル）。
- `StructureGuide.anchors`を追加し、ブロックエンティティではなくプレイヤーから起点を決める構造に対応（既定は従来どおりブロックエンティティ）。案内は1か所。
- 確認：`runGameTestServer` 300件成功（1個の鉄ブロックから最小の球、完成した殻の1か所の欠けだけを表示、手に持たなければ出ない）。実クライアントで球のゴーストが描かれることを確認（構図は粗い）。
- 制約：手に工業用鉄ブロックを持つと、装飾目的の工業用鉄ブロックの近くでも出る。成立済みの球の殻は別ブロック（ガスホルダー殻）に置き換わるため対象外。
- 実装コミット（ガスホルダー）：d86420f
