# 水蒸気のもやと雲の範囲（分担A）

実装コミットは `26673126ad7585cd80aa1f27b62601202b48caa9`。検証環境は Minecraft 1.21.1、NeoForge 21.1.219、Create 6.0.10、JDK 21。

## 実装

- `CloudVolume` がブロックの隙間をたどり、水平17×17・高さ9の箱に、最大512マスの範囲を作る。初期マス数は `min(512, 8 + mB / 20)`。各ブロックの当たり判定を軸ごとに投影した結果を再利用する。検知と回収には、現在のブロック状態から求めた4ブロック以内の通れるマスを使う。
- `GasCloud` は流体スタックの成分、残量の計算に必要な時刻、経過tick、範囲のビット列をエンティティNBTに保存する。範囲は100 tickごとに作り直し、1ディメンションあたり1 tickに最大4件を処理する。範囲は変更時、残量表示は最大毎秒1回同期する。1チャンクの発生地点は最大8件で、上限では同じ流体と成分の雲に合流できる。
- `GasCloudStyles` の登録対象は通常・高圧・過熱の水蒸気。既定値では天井側から範囲を埋め、屋外の寿命を6分の1にする。高圧蒸気管が破損すると水蒸気250 mB、フレアは実際に排出した蒸気をもやにする。回収ダクトは元の流体と成分を保持して取り出す。旧未処理プロセスガス入りのダクトは搬出でき、大型吸収塔の洗浄にも使える。バケツ・流体の登録を残し、新規入手用の表示をクリエイティブタブとJEIから外した。
- クライアントは範囲の外面だけを描き、範囲か表面の高さが変わったときに描画用の面を作り直す。時間で模様をずらす32×32の周期ノイズは `tools/generate_process_gas_recovery.py` が生成する。日本語・英語・中国語のPonderでは、破損、ドア、警報、回収、屋外での消散を示す。

## 問い合わせ

- サーバーでは `GasClouds.release(level, pos, stack)` が蒸気を出し、`GasClouds.in(level, aabb)` が重なる雲を返す。各雲の `contains(BlockPos)` と `contains(Vec3)` で占有を確認できる。近いマスは `cloud.volume().nearest(origin, CloudVolume.reachable(level, origin, reach))` で調べられる。`cloud.extract(limit)` はサーバーで残量を減らし、取り出した流体スタックを返す。
- `NeoForge.EVENT_BUS` の `GasCloudEvent.Sample` は最大毎秒1回、`GasCloudEvent.Rebuilt` は範囲更新直後に蒸気の雲を通知する。見た目の登録は `GasCloudStyles.register` で蒸気の等級ごとに上書きできる。今回のルートは水蒸気専用で、有毒・可燃ガスの既存処理は従来の入口を使う。

## 検証

- 通常GameTest 633件と、関連GameTest 38件がすべて合格。既存の `ToxicGasGameTests` と `IndustrialGasSafetyGameTests` を含む。新しいテストでは壁とドア、床側と天井側への配置、最大サイズ、流体と成分ごとの合流、屋外の寿命、NBT、実際の配管破損とフレア排気、検知器・コンパレーター・電動ポンプの連動、ダクトからCreateのメカニカルポンプ経由で気体タンクへの移送、旧バッファの搬出と洗浄を確認した。
- Gradleビルド、JARの展開、3言語の翻訳、Ponder構造の静的検証に合格。RTX 4060の実クライアントで日本語Ponderを開き、ガラスで囲った部屋に表示されるもやを確認した。カメラをもやに入れた状態での霧距離の実測は未実施。

### 32か所の比較

RTX 4060で、同一のシード42のフラットワールド、1280×800、描画距離・シミュレーション距離8、同じ固定カメラで2方式を順に動かした。32か所へ2,000 mBずつ80 tickごとに供給し、各方式で100 tickの準備後に160 tickを計測した。旧方式は変更前 `85e55f4` の `ProcessGasIncidents` を検証用クライアントだけで動かした。各方式の全観測点で32か所が稼働した。tick時間は統合サーバーのPre/Post間、フレーム時間は連続する描画終了の間隔。結果はこのワールドとカメラ位置での比較になる。
