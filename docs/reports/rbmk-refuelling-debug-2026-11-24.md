# RBMKと燃料プールの燃料棒交換を検証

実装コミットは `50a4180`。対象はMinecraftのRBMK燃料チャネル、燃料プール、門型クレーン。 [操作ガイドと練習用ワールド](../playtests/rbmk-refuelling-practice.md)

## 修正

- 使用済み燃料の熱が、冷水でも蒸発に使われていた。残留熱はまず保有量と比熱に応じて水温を上げる。100 ℃に達した後の熱は2,260 J/mBで水を蒸発させる。90 ℃以上か、ラック1枚あたり22,000 mB未満では燃料を受け入れない。既存のラック在庫と水を維持し、従来の端数熱は次回の加熱で使う。
- プールに温度の異なる水を補給できるようにした。タンク内部で水量加重の実温度を保存し、配管へは既存の温度段階で公開する。ゴーグルには実温度を0.1 ℃刻みで表示し、Display Linkからも水温と水量を読み取れる。
- クレーンはキャップ・ラックのブロック座標と各区画の中心座標を使い、水平範囲に入る区画だけを扱う。使用済み燃料を取り出す前に、搬送可能な空きラックを確かめる。停止理由に到達範囲外と対応燃料不足を追加した。
- クレーンが引き抜いた使用済み燃料棒のアイテムデータを保存し、共通のアイテム搬入口でプールへ入れる。燃料棒のデータと放射能の記録が保持される。従来のワールドにあるデータなしの吊り具も既存の燃料棒として回収できる。
- ゴーグルに引抜・プールへ降ろす・新燃料を取り出す・炉へ装荷の各状態と、吊り具の中身を表示する。Ponderにレール高さ、水位、新燃料の入れ方、空き枠、制御盤の自動モードを追記した。

## 主なコードとデータ

- `block/entity/FuelPoolBlockEntity.java` と `compat/display/MachineReadings.java` にプールの水温と取り扱い条件を実装。
- `block/entity/CraneDriveBlockEntity.java` に到達範囲、使用済み燃料データの保存、待機理由と吊り具表示を実装。
- `gametest/CraneGameTests.java` と `gametest/FuelPoolGameTests.java` で温度、蒸発、補水、範囲外、保存復元後の搬送を確認。

## 検証

- 修正前の対象GameTestは17件合格。旧試験は水温を設定したつもりでも実際は設定されない関数を使っており、冷水の蒸発を正常としていた。試験では実温度と搬送結果を確認するよう修正した。
- `check jar runGameTestServer` が成功し、GameTest全750件が合格した。温度の異なる水の補給、90 ℃以上での停止と冷却後の再開、90 ℃未満の水の昇温、100 ℃での蒸発、到達範囲外の残置、キャップとラックの搬送、制御盤からの一時停止と再開を確認した。
- 実クライアントで92,000 mBの水を使う2×2プールと小型RBMKを組んだ。上向きドロッパーで新燃料1本を投入し、レバーで初回の自動交換を開始した。283 tickで使用済み燃料1本をプールへ、新燃料1本を炉へ移した。新燃料が小型炉用のまま、使用済み燃料の材料データが保持されたことを確認した。吊り具の残数は0本、水は92,000 mB。配布ZIPを別のゲームディレクトリに展開し、ワールドを読み込んで再試験した。交換前の水と2本の棒が保存され、同じ283 tickで同じ結果になった。
- 交換Ponderの文と翻訳キーを日英中で確認した。全体の翻訳検証スクリプトは既存のPVCガイドの書式で止まり、同じエラーが修正前でも再現した。交換Ponderの再生は今回の実機確認には含めていない。
- クライアントはRTX 4060を使用した。終了時の環境のNVIDIA EGLエラーに先立って、実機の計測結果と交換前の配布セーブが保存済み。オフライン検証でJEIは無効。長時間運転と複数人の同時操作は未確認。
