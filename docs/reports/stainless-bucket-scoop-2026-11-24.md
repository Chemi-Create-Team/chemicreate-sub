# ステンレスバケツで汲めなかった溶液をタンクに残す

実装コミットは `dc1a72c`。

Create 6.0.10は空のバケツを満たせると見なして、バケツのハンドラーが受け入れを拒否してもタンクから1,000 mBを引いていた。攪拌槽のハッチでは、汲めなかった空バケツが固体の原料欄に入る経路もあった。

`CreateBucketFillingMixin` はステンレスと耐食合金の空バケツについて、バケツ側が受け入れられる量を事前に照会する。`StatefulBuckets.fillFromTank` は `LiddedVesselBlock` と `PlantFluidTankBlock` の直接操作で、実際の流体ポートからNeoForgeの容器操作で移す。攪拌槽のハッチからは液体の払い出し口を使う。受け入れ拒否や1,000 mB未満の場合、流体とバケツがその場に残る。クリエイティブではタンクの内容を消費せずにサンプルを得られる。

ゲーム内で熱酸に分類される硫酸ジルコニウム溶液には耐食合金バケツを使う。Ponderの日英中の字幕に熱酸に必要なバケツを追記した。

- 変更前の専用サーバーで、1,500 mB入りの攪拌槽が拒否された汲み取り操作で500 mBになることを再現した。
- Java 21で `check jar` と関連GameTest 65件が成功した。攪拌槽とステンレスタンクでの拒否時の保持、耐食合金バケツによる1,000 mBの取り出し、500 mBだけ残ったときの拒否、重ねたステンレスバケツでの苛性ソーダの取り出しを確認した。
- 全GameTest、クライアントでの右クリックとPonder再生、実機のCreate注液口は未実施。Create注液口が使う受け入れ量の照会はGameTestで確認した。
