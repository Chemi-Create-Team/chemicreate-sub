# 奥行き1ブロックの蒸気タービン断面

実施日: 2026-11-13。実装コミット: `30e76586b6210306fc7d79c5bb6db7fd82093e34`。

依頼文の最後の「高圧」は「低圧」の意味と解釈し、高圧・中圧・低圧の3種類で実装した。確認用の選択質問を提示し、作業中にもこの解釈を明示した。背景の工場ではなく、添付画像の八角形の円筒外装・継ぎ目・金属フランジをタービンの形状へ反映した。

## 実装内容

| アイテム | 1個の占有サイズ（幅×高さ×奥行き） | 製作 |
| --- | --- | --- |
| 高圧タービン断面 | 3×3×1 | メカニカルクラフター9×9 |
| 中圧タービン断面 | 5×5×1 | メカニカルクラフター9×9 |
| 低圧タービン断面 | 7×7×1 | メカニカルクラフター9×9 |

Create 6.0.10の実依存JARで`AllRecipeTypes.register`が`ShapedRecipePattern.setCraftingSize(9,9)`を設定することを確認し、3レシピともその上限を使用した。既存のケーシング・羽根・端部・普通のシャフトを材料にし、新しい製造装置は追加していない。

同じ種類・軸の断面を並べると、最大16断面の圧力段になる。端面へ同じアイテムを置くと中心を合わせて1ブロック延長し、外側の端だけをシャフト周囲まで自動で塞ぐ。手動で端蓋を取り付ける操作は不要。異なる種類は別の圧力段になり、普通のCreateシャフトと標準の流体配管で高圧→中圧→低圧へ接続する。

外装は鋼鉄の八角形、軸方向のフランジ、水平の合わせ目、銅の締結部・配管フランジ・支持部を備える。固定メッシュをサイズごとにキャッシュし、端面だけを隣接状態で切り替える。既存の鋼鉄・銅テクスチャを共通材質として参照し、大きな面は分割して16px相当の密度を保つ。シャフトは普通のCreateモデルと外部軸の回転速度を使い、内部の羽根は既存の回転描画を再利用する。角を落とした衝突形状を使い、新断面には旧式の窓切替を設けない。

Shift＋レンチまたは破壊で1断面ずつ回収する。途中を外すと残った端面が自動で閉じ、撤去した断面だけの流体を放出する。隣の断面の在庫は維持する。所有情報と圧力段はNBTへ保存し、部分ロード時は共有処理を拒否する。

日英中の名称と説明、クリエイティブタブ、中圧段の登録・描画、Ponderの配置・接続・回収手順を更新した。既存の運転・循環・安全の教材も3段の断面と台座を示す。通常の手順は[操作説明](../steam-turbine-units.md)、画像・起動設定・ログは[検証記録](../quality/turbine-sections/README.md)を参照。

## 状態と物理計算

- `block/TurbineUnit.java`: 奥行き1の占有領域、種類、連結、完全性・ロード状態、形状、保存・回収。配置前に障害物・権限・エンティティを確認し、失敗時は巻き戻す。
- `item/TurbineUnitItem.java`: 底の中央での設置と、軸方向の面からの延長操作。
- `block/entity/TurbineUnitPort.java`: 同じ圧力段の実ローター在庫を共有し、容量は16,000 mB×断面数とする。ポート数では増えない。SIMULATEでは消費しない。
- `block/entity/SteamTurbineBlockEntity.java`: 形成した断面がそれぞれ自分の在庫を消費し、実仕事を回転容量へ反映する。排気は各ローターの在庫から一度だけ移送する。低圧下面から実際の復水を排出する。
- `thermal/TurbineThermal.java`: 既存の膨張式・効率・流量上限を使う。高圧の設計排気圧の下限は`√(炉の圧力×大気圧)`、中圧はさらにその値と大気圧の幾何平均（約2.9 bar）。実際の下流圧・内部排気圧も考慮する。中圧では凝縮させず、低圧だけが既存の30 ℃復水・排熱を処理する。新断面は自分の膨張段の仕事を応力容量として提示する。
- `client/TurbineSectionRenderer.java`: 円筒、フランジ、自動端面、普通のシャフトと内部羽根の描画。
- `ponder/TurbineUnitPonderScenes.java`: 9×9クラフト、1断面、延長、3段接続、復水と回収を示す。
- `tools/generate_turbine_sections.py`: アイテムモデル、3レシピ、日英中の名称・教材文言の再生成。

試験で、中圧排気が旧来の「高圧以外は水」という判定で水へ変換され、低圧が受け取れない問題を見つけた。低圧だけを水とする判定へ修正した。保存試験では、搬出専用ハンドラーが入口を公開しないため、入口を空と誤認する試験側の集計も修正し、実在庫の量と熱で検査した。

## 検証結果

`build runTurbineUnitGameTestServer`は成功し、専用タスクの3件すべてが合格した。教材の台座・文言を最終調整した後の`build`も成功した。

| 試験 | 結果 |
| --- | --- |
| 3種類×X/Z軸、1ブロックの奥行き、障害物拒否、所有情報の保存・再読込、3種類の9×9レシピ読込 | 合格 |
| 連結・分割時の端面、3断面48,000 mBの共有容量、SIMULATE、実搬入、保存後の量・熱、途中の回収と隣の在庫維持 | 合格 |

運転試験は高圧・中圧・低圧を各1断面、入口に700 Kの蒸気16,000 mBを投入し、140 tick後に評価した。以下は最後の試験の実測であり、定常運転時の定格出力ではない。

## 制約と未確認事項

- 実クライアントは描画・教材状態検査を完了した後、既知の`libEGL_nvidia.so.0`内のSIGSEGVで終了した。`runClient`全体の正常終了とは区別して記録した。
- 全GameTest、原子炉・発電機負荷を含む長時間プラント試験、サバイバルでの手動9×9クラフト、16断面上限・チャンク境界での手動プレイは未確認。
- 前版の固定長ユニットから新断面への自動変換は追加していない。配置済みの旧機体は撤去・再設置が必要。新しい所有情報は保存形式Version 2を使う。
- 個別の新圧力段は形成と圧力差で動作する。旧型の「高圧と低圧を1組として判定する」条件を、新断面の稼働条件には使わない。連結配管と共通軸はプレイヤーが設計する。
- 復水の排熱上限と熱処理は既存実装を維持した。今回の短時間試験は冷却塔を含む連続運転の検証ではない。
