# 設備ごとの駆動音と原子炉クレーンの完走確認

実装コミットは `1b2b31ab34a3d8a29359cbfaaf45e31d25cf14fb`。検証日は2026年11月19日。Minecraft 1.21.1、NeoForge 21.1.219、Create 6.0.10、Java 21で確認した。

## 駆動音

- 設備音を35種類追加し、加圧ガスと高圧ガスの2種類を含めて46ループを登録した。タービン、二種の原子炉、冷却塔、ボイラー、復水器、反応塔、蒸留塔、気液分離設備、電解設備、圧縮・回転設備、二種のクレーンなどに、それぞれの動きに合わせた音を割り当てた。材質違いの機械式ポンプは同じ機構音を使い、9種の材質それぞれの音程と回転数を反映する。音量はMinecraftの「ブロック」で調整する。字幕は日英中に対応する。
- `MachineSoundSource` は既存の稼働・回転・燃焼状態を使う。稼働する集合設備は制御部から鳴らし、タービンのローターや一つの放熱器バンクの各部品からは重複再生しない。`MachineSounds` は近いチャンクを優先して探し、同じ圧力帯の配管音を8ブロックの間隔で選ぶ。プレイヤーごとの同時再生は全体24音、内訳の配管音は4音まで。加圧・高圧ガスの可聴距離はそれぞれ16・20ブロック。
- `FluidRoutes` は既存のCreate搬送で送り先が実際に受け入れた量を同じ経路上で観測する。`PipeGasFlow` は圧力の既存区分と8・32・128 mB/tを境目とする4段階を記録し、追跡中のクライアントへ値の変化だけを送る。停止は最後の移送から10 tickを目安とする。同期枠は8 tickで、音量と音程はクライアントで補間する。配管音の値はワールドに保存せず、音のための在庫や別の配管網も持たない。
- `tools/generate_machine_sounds.py` で合成したモノラルOgg Vorbisを同梱した。追加のループは4秒で、端に0.18秒のクロスフェードを設けた。`tools/validate_machine_sounds.py` でデコード、ピーク、直流成分、ループの継ぎ目、字幕、音源参照を検証する。気体配管Ponderに流動音の説明を加えた。

## クレーンの完走を妨げていた条件

- `FusionReactorControllerBlockEntity` では、通常停止時に磁石が放電せず、加圧給水だけではブランケットが100℃以下に届かなかった。プラズマと磁石を切ると、既存の通常放電と、毎tick最大0.25 Kの受動冷却が進む。クレーンは交換可能な状態になるとAUTOで保守を続ける。炉の安全条件とPonderの手順を揃えた。
- `CraneDriveBlockEntity` では、使用済みの照射カートリッジを新品候補から外し、新品が1個入ったスロットを使用済み部品の回収先にも使えるようにした。RBMKでは使用済み燃料棒だけを選び、照射済みリチウム標的は燃料キャップの既存出力に残す。燃料棒を吊り上げた状態では空き区画を探して装荷を優先し、格納庫が詰まったときは回収先を空ける表示を出す。

## 検証と範囲

| 検証 | 結果 |
| --- | --- |
| 建設機、クレーン、制御盤、発電所のGameTest | 32件。有限資材で両炉とクレーンを施工。RBMKの途中停止・保存データの再読込・動力復帰・再開と、核融合炉の通常停止待ち・途中停止・部品2種の回収を確認 |
| 核融合炉と燃料供給のGameTest | 16件。フライホイール給電を含む |
| 配管、圧力、分離器、ポンプ、放熱器のGameTest | 23件。減圧弁前後で異なる音の区分が観測されること、通常圧・無流量・供給切れで無音になること、音の値が保存に含まれないことを確認 |
| 音源と字幕 | 46種類のデコード・信号・参照と、日英中の翻訳検査が合格 |
| 実クライアント | RTX 4060のクライアントで46音源の登録、有動力ファンの開始・停止・ミュート・距離・アンロード、高圧配管の開始・停止と多重再生防止、大口径機械式ポンプの音程0.73を確認。日本語Ponderの気体配管と核融合保守の2シーンも合格 |
| 本体 | Gradleの `build` とJAR展開検査が合格 |

複数のクラスを同時に実行した初回の試験ではフライホイール給電が一度0 Wで失敗した。対象の2クラスを単独で実行すると、変更前（`9cf16c0`）と変更後の双方で16件が通った。同時実行時の原因は特定していない。RBMKの再開検査はBlockEntityの保存データを読み直し、Createのモーターを接続し直して動力を復帰させる構成。実チャンクのアンロード・再読込は音のライフサイクルで確認した。核融合の保守試験は熱と磁場が残る状態から始め、最大出力での長期運転は行っていない。音の実機確認には仮想OpenAL出力を使った。スピーカーでの聴感と全設備の同時運転は未確認。
