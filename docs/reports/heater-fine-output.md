# 電熱線ヒーターの微細出力調整

実施日：2026-11-13。実装コミット：`b21692e9a16660b46ef0834b0913c9576d2c91c2`。

## 変更内容と使い方

電熱線ヒーターの前面に銅製ダイヤルを追加した。素手でダイヤルの左半分を右クリックすると−0.1％、右半分で＋0.1％、Shift中は±1％。設定範囲は0～100％で、0％は停止。水平4方向の配置に対応する。ゴーグルでは設定割合、実際の電力、運転中の電圧、直上のふた付き槽の温度を確認できる。Display Linkにも出力割合と槽温度を追加した。ダイヤル指針はクライアントで補間する。

温度を見ながら出力を合わせる手動調整であり、設定温度への自動追従ではない。設定は保存され、更新前の設定を持たないヒーターは100％になる。新しいGUIは追加していない。鋼材・銅の既存材質を使ったダイヤルモデル、日英中の説明、ヒーターPonderと槽を示す構造も更新した。

## 電力と熱の計算

出力割合を `f`（0～1）とするとEE回路の等価抵抗を `40/f Ω` にする。0％は開回路。実際の供給電圧を `V` とすると消費電力は `V²f/40 W`。400 Vの理想条件では0.1％が4 Wに相当する。電線損失があるため実測は少し低い。回路が解いた抵抗と電圧を組で記録し、設定変更の境界で別の抵抗から電力を逆算しない。

ふた付き槽への熱は実入力から蓄えた有限のエネルギーを使い、同一tickの合計を `P/20 J` 以下に制限する。蓄熱上限5,000 J、蓄熱の0.5％/tickの損失は従来どおり。小さい出力でも熱を渡し、絞った後に蓄熱を一度に放出しない。停止・停電中は渡さない。

Createの鉢・ボイラーに渡す通常加熱3.5 kW、強加熱14 kWの段階判定は維持する。これを下回る細かな加熱は、ふた付き槽の熱収支に適用する。放熱より小さい出力では、通電中でも槽温度は下がる。

主要ファイル：

- `block/ElectricHeaterBlock.java`：前面の操作判定。
- `block/entity/ElectricHeaterBlockEntity.java`：出力・蓄熱・保存・同期・温度表示。
- `compat/electro/ElectricUtilityDevice.java`：実際に計算された抵抗・電圧の受け渡し。
- `block/entity/VesselClimate.java`：加熱段階未満の有限熱を受け取る経路。
- `client/ElectricHeaterRenderer.java`、`models/block/electric_utilities/heater_dial.json`：動く指針。

- `gametest/HeaterOutputGameTests.java`：操作・保存・実配線・低出力の熱収支・同一tick制限の4試験。
- `tools/generate_electric_utilities.py`、`ponder/ElectricUtilityPonderScenes.java`：モデル、翻訳、Ponder構造と操作説明。

## 試験結果

400 VのEEクリエイティブ電源と銅線を接続し、ヒーターの真上に水1,000 mBを入れた1×1のふた付き槽を設置。各設定を80 tick（公称4秒）測定した。外気への放熱を切り分けるため、各測定開始時に同じ水の状態を与えた無加熱の比較槽も置いた。

| 設定 | 実入力 W | 水の正味変化 J | 比較槽との差 J |
| --- | ---: | ---: | ---: |
| 100％ | 3,991.702 | +15,737.200 | +15,921.873 |
| 50％ | 1,997.924 | +7,665.410 | +7,969.231 |
| 50.1％ | 2,001.915 | +7,614.652 | +7,985.172 |
| 1％ | 39.999 | −255.414 | +159.547 |
| 0.1％ | 4.000 | −392.241 | +15.954 |
| 2.5％ | 99.995 | −3.107 | +398.856 |
| 0％ | 0 | −397.425 | 約0 |

比較槽との差は放熱込みの差分であり、熱ポートで直接積算した値ではない。設定は順に変更しているため、測定ごとの初期温度は異なる。50％と50.1％の正味変化をそのまま比較せず、実入力と比較槽との差を参照する。0％の差分約0.000059 Jは比較計算の微差で、熱受け渡しメソッドの返却は0。全測定値は[measurements.json](../quality/heater-output/measurements.json)。

50→50.1％で実入力が約3.992 W増え、0.1％でも有限の加熱を確認。約33 ℃付近の2.5％では4秒間の正味変化が約−3 Jとなり、手動で放熱に近い出力へ合わせられた。この設定で長時間の一定温度保持を証明したものではない。

関連GameTestは **51/51件合格**（4.835秒、Gradle全体35秒）。新規4件のほか、電動ポンプ、既存ヒーター、原子炉、槽の沸騰、気液二相、Display Link、Ponder関連を回帰確認した。保存43.7％の復元、旧保存の100％、4方向のクリック、上下限、0％、同一tickの二重払い出し防止、古いEE計算結果の失効を確認した。

```sh
env JAVA_HOME=/workspace/.createplant-jdk21 PATH=/workspace/.createplant-jdk21/bin:$PATH JAVA_TOOL_OPTIONS=-XX:ActiveProcessorCount=2 bash gradlew --no-daemon -I docs/quality/heater-output/server.gradle build runGameTestServer
```

翻訳検証は日英中2,579キー、Ponder言語検証は142シーンに合格。チュートリアル検証も98追加シーン・519説明・238リンクと構造参照に合格。ビルド済みJARの新規指針モデル・描画クラス・日英中キーを検査した（[jar-audit.json](../quality/heater-output/jar-audit.json)）。

RTX 4060で実クライアントを起動し、日本語Ponderの描画・翻訳検査が1/1件合格。[実画面](../quality/heater-output/dial-ponder.jpg)と[実行結果](../quality/heater-output/client-result-ja_jp.json)を保存した。合格後のクライアント終了時に既知のNVIDIA `libEGL_nvidia.so.0` SIGSEGVが再発し、Gradleのクライアントタスクは終了コード134。サーバー試験の成功と、この終了時障害を分けて記録する。

## 未確認事項・次回の注意

- 全サイズ・全流体・全外気条件での温度保持と長時間の手動運転は未確認。必要出力は内容物、外気、槽の寸法、ほかの熱源でも変わる。
- 実画面は日本語Ponderの1方向。操作判定はサーバー試験で4方向を確認したが、全方向の表示を撮影したわけではない。
- 自動温調、目標温度入力、能動冷却は今回の実装に含めない。
- 大量設置時の性能測定と全GameTest一括実行はしていない。
- モデル再生成は既存の `tools/generate_electric_utilities.py` を使う。既存のDisplay Linkキー順とEEの計算時抵抗の受け渡しを維持すること。
