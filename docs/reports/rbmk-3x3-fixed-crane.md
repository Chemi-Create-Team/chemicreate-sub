# RBMK 3×3チャネル・固定長クレーン実装レポート

実装コミット：`330c65a0`（`Redesign RBMK core and fixed service crane`）

## 実装内容

- 燃料チャネル束、上部キャップ、燃料プールラックを1ブロック当たり3×3＝9区画へ変更した。
- 最大炉心を有効直径13 m、その外側を厚さ2 mのバイオロジカルシールドで囲む外径17 mとした。円形細分マスクは有効1,005区画、既定配置は燃料894本・制御棒111本である。
- 縦構造を、炉心下5 mの給水細管束、下部遮蔽2 m、炉心7 m、上部遮蔽2 m、上部細管束12 m、運転床キャップの順に変更した。燃料集合体は7＋2＋12＝21 mである。
- 炉心下7 mは給水細管束の連続を必須にし、最下部の冷媒入力部から全接続列へ水を分配する。上部側面の厚さ2 mを貫く冷媒出力部から蒸気と残留水を搬出する。
- 冷媒入力部の1回の大容量fillで列を飛ばすカーソル更新不具合を修正し、接続列の合計容量を公開した。
- 原子炉保守マストを太部10ブロック＋細部5ブロックの固定長へ変更した。レールをキャップ／プール水面の15ブロック上へそろえ、マスト深度14のまま橋とトロリーだけを前後左右へ動かす。燃料集合体そのものの取出し・挿入アニメーションは独立して上下する。
- 採掘モードは従来どおりロープを上下させる。Ponderでも保守の固定マストと採掘ロープを別モードとして表示する。
- 燃料プールを21 m集合体＋上部余裕1 mの深さ22 m、壁高23 m、1セル9本、容量23,000 mB、受入水位22,000 mBへ変更した。
- 低彩度の鋼・真鍮・銅色を使う16×16テクスチャ、3×3モデル、Ponder、日本語／英語文言、設計文書を更新した。専用GUIは追加していない。

## 寸法と計算

- `CHANNEL_GRID = 3`、`RODS_PER_BLOCK = 9`。
- `CORE_HEIGHT = 7`、`UPPER_SHIELD_HEIGHT = 2`、`SUSPENSION_HEIGHT = 12`、`LOWER_SHIELD_HEIGHT = 2`、`LOWER_SERVICE_HEIGHT = 5`。
- 上部キャップは炉心最上段から15ブロック上、燃料集合体は21 m、下部構造は7 mである。
- 円形炉心は13×13物理ブロックを39×39細分格子として切り、円外区画を無効化する。137本の物理列に1,005区画を保持し、細分位置を個別BlockEntityにはしていない。
- 固定マストは太いセグメント9個＋太い先端1個＝10、細いセグメント5個＝5として描画する。レール座標から対象上面まで15ブロック、保存深度は14である。
- 放射線遮蔽判定は側面・上下とも連続2ブロックを要求する。給水細管束と上部管も、各列を貫く遮蔽部材として扱う。

## 既知事項と未検証

- 全GameTestの初回実行は231件中228件成功だった。今回対象の燃料プール待機時間失敗は修正後の限定実行で成功した。残る2件は既存の小型コンプレッサー実ポンプ試験と酸配管破損試験で、今回の炉・クレーン変更とは無関係である。新規試験追加後の全232件実行はチャンク保存が長時間化したため途中で停止しており、全件完走とは報告しない。
- クライアント自動検証は結果保存と `CLIENT QUALITY PASSED` の後、終了時だけNVIDIA `libEGL_nvidia.so.0`でSIGSEGVとなり、Gradleの終了コードは134だった。ゲーム処理・撮影・ワールド保存は完了している。
- Create Mavenの証明書期限問題を避けるため、検証時だけ取得済み依存を一時flatDirから解決した。この設定はリポジトリへ含めていない。
- 最大炉1基の形成・保存・描画は確認したが、複数の最大炉を常時稼働した際のMSPT、FPS、割当量は計測していない。
- 登録IDと既存の保存キーは維持したが、旧4×4炉・26 m集合体・27 mプールは新寸法へ組み直す必要がある。旧レポート `rbmk-15m-integrated-channels.md` は当時の履歴であり、現仕様は本レポートと各設計文書を正とする。

## 次回の注意

- マストを可変長へ戻さず、原子炉保守タスクでは`depth`と`travel`を常に`SERVICE_MAST_DEPTH`へ固定する。
- 上部キャップとプール水面の高さを変える場合は、レール高差15、Ponder構造、クライアント統合試験を同時に更新する。
- 細分数や炉体径を変える場合は、円形マスク、既定燃料／制御数、保存配列、モデル、プール、クレーンの位置計算を一組として確認する。
- 冷媒入力のカーソルはfillループ中に更新しない。全列を走査した後、実行時だけ最後に受入れた列の次へ進める。
