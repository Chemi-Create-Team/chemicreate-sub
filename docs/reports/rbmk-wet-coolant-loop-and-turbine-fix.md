# RBMK混相冷却ループと蒸気タービン起動修正

2026-11-04。実装コミット：`79501afdc209c2847cd0590d8c8faa9d3eb000d5`。このレポートだけを追加する文書コミットは、その後に保存する。

## 実装概要

- バイオシールド冷媒入力部をブロック登録、アイテム、レシピ、loot、タグ、モデル、テクスチャ、翻訳から削除した。旧ブロック用の互換登録は残していない。
- 給水細管束へブロックFluid Capabilityを追加した。露出面へCreateパイプを直接接続すると、水だけを受け入れ、接続済みの細管束網の上にある全燃料列へラウンドロビンで分配する。最大13×13×7＝1,183個の正規構造を含む最大2,048ブロックまで探索し、未ロードチャンクを越えて搬送しない。
- 炉心出口を、水と蒸気を選別できる2タンクから、比エネルギーを持つ1本の混相流へ変更した。バイオシールド冷媒出力部は全水換算質量を一緒に搬出し、炉内へ液体分だけを残さない。
- 既存の2層以上の気液分離器に原子炉水モードを追加した。上層側面から混相流を入れ、上面から蒸気、底面から液体水を取り出す。アンモニアモードとは排他的で、水モードでは下層側面の冷却ジャケットを使わない。保存・再読込、圧力表示、ゴーグル表示、SIMULATEを含めて対応した。
- 蒸気タービンが負荷接続済みまたは過負荷履歴のあるシャフトで起動できない循環依存を修正した。蒸気を消費せず次tickに可能な仕事を予測し、そのStress Capacityを先にCreateの動力網へ公開する。実際の蒸気消費は従来どおり構造、過負荷、過回転、安全条件を満たす場合だけ行う。
- RBMK、気液分離器、復水器、タービン循環のPonderと日英翻訳、設計文書、平坦ワールド用テスト設備を新しい経路に更新した。

## 蒸気と水の割合

水換算量は水・蒸気とも1,000 mB＝1 kgとする。炉心が保持する比内部エネルギーを `u`、比熱を `cp = 4,180 J/(kg K)`、常圧沸点を `Tb = 373.15 K`、蒸発潜熱を `L = 2,257,000 J/kg` とし、搬出時の蒸気質量比を次で求める。

`x = clamp((u - cp × Tb) / L, 0, 1)`

搬出質量 `m` に対し、蒸気は `m × x`、液体水は `m × (1 - x)` である。沸点未満は全て水、常圧二相域は100 ℃のまま潜熱が割合を決め、過熱域は全て蒸気になる。炉心から分離器までは総質量と総UをFluidStackのComponentに保持し、分離器で整数mBへ分ける。丸めで残ったエネルギーは残存パケットへ引き継ぐため、最終的な質量と総Uを失わない。

意図する配管は次の閉ループである。

`炉心出口 → 気液分離器 → [底面の水 → 冷却] + [上面の蒸気 → 高圧タービン → 低圧タービン → 復水・冷却] → 合流 → 給水細管束`

## 制約・未検証

1. 各ポートと機械、質量・エネルギー収支はGameTestし、閉ループの全経路はPonderで描画したが、サバイバルの実ワールドで全設備を1本の稼働配管として長時間連続運転する手動試験までは行っていない。
2. 混相流は既存Fluid IDと比エネルギーComponentを使う。蒸気が少しでも含まれる場合の搬送用IDはsteamだが、純蒸気ではない。Componentを破棄する外部MODの独自搬送経路は割合を維持できない可能性がある。標準Create配管を前提とする。
3. 水物性は既存設計どおり一定比熱・一定潜熱の近似で、IF97ではない。二相域で温度だけを見ると常に100 ℃なので、実際の割合は保存した比エネルギーから求める。
4. 廃止した冷媒入力部はプレリリース方針に従って互換ブロックを残していない。旧ワールドに置かれている同IDブロックの自動置換は行わない。
5. クライアント品質検査自体は90シーンと3枚の撮影まで成功した。その後、`mc.stop()`による終了処理中にコンテナ側NVIDIA EGLライブラリ `libEGL_nvidia.so.0` がSIGSEGVし、Gradleプロセスの最終終了コードは134になった。検証結果JSONと画像はクラッシュ前に正常保存され、Java/Mod側の実行中例外ではない。

## 次の開発で注意

- 原子炉出口からタービンへ直結せず、必ず気液分離器の上面steamポートを使う。底面waterポートは別の冷却枝へ送る。
- タービンStress Capacityの予測は在庫、排気余量、圧力、熱経路のstamp、tickでキャッシュする。予測でFluidStackを消費したり、過回転中に容量を公開したりしない。
- 気液分離器の原子炉水モードで、アンモニアのsettleや冷却ジャケット処理を重ねない。相分率を容器の満水率から再計算せず、炉心出口が運んだ比エネルギーを使う。
- 給水細管束の探索はロード状態の変化でも無効化される。未ロード位置を水が通過したものとして扱わない。
