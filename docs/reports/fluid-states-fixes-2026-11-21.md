# 流体の状態（17段階・ID統合）の不具合修正と気体パイプの廃止

2026-11-21。[流体の状態](../fluid-states.md)の実装（`02abdd6`、`1728cea`）を取り込んだ後、全GameTestで52件が失敗した。ユーザー指定により、原因ごとに直し、並行流の熱交換器では蒸気が1回で水に戻らない仕様のまま工程とPonderを対向流に合わせた。同時に気体パイプを廃止した。

実装コミット：`6082590`、`eb3e6e8`、`b3ad09f`、本レポートと同じコミット

## 修正したコードの不具合

| 不具合 | 原因 | 修正 |
| --- | --- | --- |
| 蒸気が漏れても雲にならない | 雲の見た目を流体IDで探しており、`minecraft:water`になった蒸気が見つからない | `GasCloudStyles.id(FluidStack)`：その状態を表す旧ID（気体の水なら`steam`）の見た目を使う |
| 気体がどの配管でも通るという規則が消えていた | `PipeMaterial`から気体の除外、混合物を最も厳しい成分で判定する処理、説明の範囲表示が削除されていた | 3つとも戻した。気体かどうかは温度・圧力から決まる相で判定する。圧力の範囲表示は5等級（真空0.5 bar未満～超高圧200 bar以上）に更新 |
| 他MODの燃料などの温度が20 ℃→25 ℃に変わる | 状態データのない流体も17段階の代表値に丸めていた | データのない流体は本来の温度・圧力を返す。物質の既定状態と同じならデータを付けない（`FluidState.setTemperature/setPressure`）。混合物は常にデータを持つ |
| 加熱で既定温度に戻ると古い温度が残る | 既定状態を「データの削除」で表すが、`applyComponents`のパッチには削除が含まれない | `TankHeating`、`FluidThermal.processComponents`で温度・圧力を明示的に設定 |
| 空気の容積倍率が消えていた | `ThermalFluidTank.storageRatio(stack)`が空気の常圧＝容積と同量の規則を失っていた | 元に戻した |
| 型で気体を判定する箇所が蒸気を液体扱い | `FluidMaterials.gas(stack.getFluid())`が水を常に液体と判定 | フレア、往復式圧縮機、反応塔、ふた付き槽、撹拌槽、鉢、可燃ガス、散布具など15か所を`FluidState.gas(stack)`へ |
| 転炉で液体酸素が使えない | 液体酸素も`oxygen`のIDになり、気体の材料として量のまま判定されていた | 液体の状態を先に判定し、従来どおり気化量で換算 |
| RBMKの出口からポンプで取り出せない | 出口が要求を流体IDだけで探しており、`water`＋状態の要求が旧IDに一致しない | 各相の旧IDと状態ごと照合する |
| 熱交換器が湿りガスの水を分けない | 実装の書き換えで凝縮水タンクへの分離が消えていた | 熱い側が沸点以下まで冷えたら蒸気分を水として凝縮水タンクへ、冷えた水性ガスには凝縮の印を付ける（従来の処理） |
| 浸出槽が圧縮空気を使えない | 混合気体の入口が圧縮空気を成分に分けてしまう | レシピが混合物そのものを使う場合は分けずに渡す（`ReactorMachineBlockEntity.usesWhole`） |
| `FluidStack`作成ごとの同期処理 | 旧IDの判定が`synchronized`のキャッシュを通っていた | クラス読み込み時に決まる表だけを読む。混合物の旧ID判定もストリームをやめた。性能は未計測 |

## 気体パイプの廃止

- `gas_pipe`・`large_gas_pipe`のブロック、アイテム、ブロックエンティティ、モデル、レシピ、ルートテーブル、翻訳、生成スクリプトを削除した。
- 保存済みのブロック・アイテムは強化パイプへ、ブロックエンティティは`material_pipe`へ読み替える（`CELegacyIds`）。旧mod IDの名前空間も同じ。
- Ponderの構造ファイル10件の気体パイプを強化パイプに置き換えた。「気体パイプと管の太さ」は「気体の搬送」とし、太いパイプの手順を削除した。
- 気体ポンプは強化パイプ＋銅板、大型気体ポンプは強化パイプ4本で作る（強化ポンプと同じ材料にならないように）。
- 大流量の主管にはステンレス配管を使う（太い気体パイプの4倍流量は廃止）。

## 仕様変更に合わせて書き直したテスト

- 熱交換器：並行流の平均・対向流の1段手前、処理量は同じ（4方向）。湿りガスの凝縮は対向流で確認。
- 冷媒：アンモニアは−33 ℃より冷たい冷媒でだけ凝縮する。ファンは常温までしか冷やさないので、常圧のアンモニアは液化しない。
- 同じ物質の異なる状態は平均で混ざる（ボイラーの残り蒸気）。
- 旧`heat_grade`の直接参照、5等級になった圧力計、圧縮1段＝圧力4段。
- 旧IDの登録（クリエイティブタブ、有害ガス一覧、バケツ、サバイバル到達性）は、旧IDを移行用として扱う（`StatefulBuckets.retired`）。
- テスト側の誤り：状態を落とすヘルパー、温排水を水と二重に数える集計。

## 確認

- 失敗していた28クラスを個別に実行し、すべて合格。
- 全GameTest：714件すべて合格。
- 途中で`compactTowerConvertsWarmWaterAndPreservesItsInventory`だけが全件実行時に失敗した。原因は別のテスト（`allTowerSizesDetectConnectCoolAndRevalidateAfterReload`）がテンプレートの外に冷却塔を建て、隣のテスト領域を上書きしていたこと。テスト配置が変わって表面化した既存の問題で、そのテストを他の大型テストと同じく専用のバッチにした。
- 硫黄サイクルのテストワールド（実クライアント、Xvfb）：合格。修正前と同じ値（tick 1,135で硫酸1,000 mB・水素1,000 mB、配管・ポンプ20か所の損耗なし）。

## 未確認・注意

- 性能は計測していない。同期の削除は推測による改善で、tick時間の比較はしていない。
- 気体パイプを置いた既存ワールドの実ファイルでの読み込みは未確認（エイリアスのみ）。
- 並行流の熱交換器では蒸気は1回で水に戻らない。工程は対向流か2回通す必要がある。
- スライム冷却材など沸点が登録されていない流体は既定の100 ℃で沸騰扱いになる。
