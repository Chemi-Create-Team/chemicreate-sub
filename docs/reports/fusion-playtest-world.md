# 核融合炉テストワールド

2026-11-08。ユーザーの「核融合炉をテストできるワールドを作ってほしい。自分で操作する」という依頼に対応。

実装コミットID：`d6be17c9`（追加）、`fad5fd2e`（現行炉への追従）。

## 実装

`-Dcreateplant.fusionPlaytest`を指定したときだけ動く開発用のワールド生成を追加した。新しいクリエイティブ・スーパーフラット・ピースフルのワールドに、現行の11×11×8（2×2流路）の核融合炉と運転に必要な設備を実ブロックで組む。通常のゲーム起動には影響しない。

| 部分 | 構成 |
| --- | --- |
| 炉 | `FusionStructure.cells()`どおりに配置。制御盤は(0, -56, 0)（地表から中央面の高さ）、内向きは南。ブランケットカートリッジとダイバータカセットは装着済み |
| 制御卓 | 3×2の物理制御卓。マスターは(7, -60, -2)、北向き。電動発電機の東面のDisplay Linkと接続済み |
| 給電 | 制御盤の北面に電動発電機、その北に大型フライホイール。チェーンドライブの列を介して、256 RPMのクリエイティブモーター36台（約151M SU）で駆動 |
| 真空 | 真空ポンプの西に256 RPMのクリエイティブモーター |
| D₂・T₂・液体He・He排気・He灰 | 各ポートの外側にCreateポンプとクリエイティブ液体タンク（供給側は無限供給、排出側は無限に吸収）。液体Heは4.2 K |
| 冷却水 | 3×3のクリエイティブ水タンク → 超高圧配管 → ポンプ → 冷却水入口。冷却水出口 → ポンプ → 超高圧配管 → クリエイティブタンク（排出）の一過式 |
| その他 | チェストに予備のブランケット2個・ダイバータ2個・レンチ。スポーン時にゴーグルを装備 |

### 判断した点

- 磁石充電中の電動発電機は最大120 MWを消費する（1 SU＝1 W相当で約126M SU）。クリエイティブモーター1台は既定設定で16,384 SU/RPM、つまり256 RPMで約4.2M SUしか出せない。設定値は変更せず、36台を並べて対応した。
- 上下に並んだD₂口とT₂口は、通常の配管だと隣接して自動で合流する。そこで両口の前を接続面固定の「ケース入り配管」にして、左右に振り分けた。大型フライホイールの円盤（直径約5.5マス）の面も避けた。
- 冷却水は、超高圧配管が隣にあるポンプだけが主管の流量（65,536 mB/t）で送れる仕様（`PassiveFluidNetworkMixin`）である。このためポンプとタンクの間に超高圧配管を1マス挟んだ。1マスのクリエイティブタンクは1 tickに8,000 mBしか渡せず、400 MWでは除熱が足りなかったため、3×3にした。
- タービン・フラッシュドラム・冷却塔は含めない。炉単体の操作試験用である。

## 主なファイル

- `src/main/java/net/createplant/client/FusionPlaytestWorld.java`：ワールド作成・配置・自動確認。
- `src/main/java/net/createplant/ElectrolysisClient.java`：プロパティ指定時だけリスナーを登録。
- `tools/create_fusion_playtest.ps1`：`-Mode world`（手動用ワールドを保存）、`-Mode verify`（制御卓から自動で試運転）。

## 検証

`tools/create_fusion_playtest.ps1 -Mode verify`（Windows 11、実クライアント）で合格した。制御卓のスイッチだけを、実際の操作順に押した。

| 項目 | 結果 |
| --- | --- |
| 形成・リンク・供給（tick 200） | 炉の形成、制御卓のリンク、D₂・T₂・液体He・冷却水の到達を確認 |
| 真空完了 → 極低温スイッチ | tick 1,502 |
| コイル5 K未満 → 磁石スイッチ | tick 3,904 |
| 充電完了 → プラズマスイッチ | tick 12,405 |
| 燃焼開始 | tick 12,907 |
| 6,000 tick保持 | 400 MW、電動発電機40 MW、過負荷なし、緊急停止なし |
| 冷却 | 入口・出口とも65,536 mB/t。出口バッファは満杯にならず一定（1,134,464 mB）。ブランケットは102.1 °Cへ収束し、最後の500 tickの上昇は2 K未満 |

最初は9×9×7版で合格したが、プッシュ前に取り込んだリモートの変更で炉が11×11×8へ変わっていた。制御盤の高さを`FusionPhysics.MIDPLANE`から計算するよう直し、新しい炉で再検証して同じ値で合格した。

途中の不合格と修正：

- 1回目：自動操作中の画面がタイトルに戻され、別ワールドが開かれて中断した。ワールドを離れた場合に分かりやすいエラーを出すようにした。
- 2回目以降：冷却水が通常流量128 mB/tに制限されていた。その後は1マスのタンクの8,000 mB/tが上限になっていた。前述の配管・タンクの変更で解消した。

`-Mode world`で手動用ワールド`createplant-fusion-playtest-1794117634914`を生成した。tick 200の形成・リンク・供給の確認に合格し、未起動（`vacuum_off`）の状態で保存した。

## 未検証・制約

- 先に作った9×9×7版の`createplant-fusion-playtest-1794117352421`は旧構造のため、現行コードでは形成しない。使用しないこと。

- 手動用ワールドでは、自動確認と同じ配置・同じ手順を使っている。ただし、そのワールド自体を燃焼まで運転したわけではない。
- 100%出力、緊急ダンプ、クエンチ、ブランケット交換、再点火は今回の自動確認に含まない。
- 冷却は20 °Cの無限水源による一過式で、設計の200 °C入口とは異なる。ブランケット温度は実プラントより低く出る。
- 始動電源をクリエイティブモーターで代用しているため、タービン軸への切り替えは試験できない。

## 再実行

```bash
powershell -ExecutionPolicy Bypass -File tools/create_fusion_playtest.ps1 -Mode world
powershell -ExecutionPolicy Bypass -File tools/create_fusion_playtest.ps1 -Mode verify
```

結果は`run/fusion-playtest-result.json`（Git管理外）に出力される。
