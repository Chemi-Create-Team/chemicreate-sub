# 生産量・理論上限・改善箇所の表示

実装コミットは `02cf283ff8dd4c85894d9d79658a2df0aea3d061`。

## 操作と対象

技師のゴーグルを着けて装置を見ると「現在の生産量 / 理論上限」と改善箇所が最大4行に収まる。Create標準のディスプレイリンクの装置計測から、流体・アイテム・出力それぞれの現在値と上限、およびボトルネックを1リンクずつ選べる。横型・縦型ボイラーと水蒸気ガス化炉のPonderに見方を追記した。英語、日本語、簡体字中国語に対応。

- 蒸気・熱設備は横型ボイラー、Createタンクの配管出力式ボイラー、蒸気タービン、熱交換器、冷却塔、復水器水箱、ラジエーター、極低温液化機。
- 加工設備は水蒸気ガス化炉、ふた付き槽・撹拌反応槽、反応塔・分離塔、アンモニア分離器、吸収塔、分留塔、遠心分離カスケード、湿式処理設備、転炉、キュービックプレス、往復圧縮機、ガス回収ダクト、電解槽・電解炉、パルス抽出塔・ガラス固化炉。
- エネルギー生産設備は燃料電池、RBMK、核融合炉。出力の種類は燃料電池が電力、蒸気タービンが軸動力、炉が熱出力。

## 計算と計装箇所

- `block/entity/ProductionMonitor.java` に、確定した生産量を積む1秒バケットと直近最大20ゲーム秒の平均を設けた。流体はmB/s、固体は個/秒、仕事量はJを時間で割ってkWとする。複数の製品がある場合は同じ単位の製品の合計を表示する。搬出された分も平均に残り、古い生産は集計窓から外れる。区間をまだ観測していない時点は「計測中」。計測履歴はワールド保存に追加せず、ゴーグルへは集約値と診断だけを同期する。
- 横型は下段の幅を列数とし、各列の長さを熱源数に換算する。1段階あたり80,000 J/sと蒸気等級のJ/mBから高圧・過熱の流量上限を計算し、大きい方を列数倍する。縦型は底面の幅の二乗を熱源枠数とする。給水と蒸気の確定投入は `HorizontalTankBlockEntity`、`TankBoiler` で集計する。
- `GasifierBlockEntity` の標準構造は1バッチ、500 mBを40 tickで250 mB/s。標準レシピが一つの場合は予熱中も理論上限を設定する。塔、槽、遠心分離機、電解槽、冷却機などは、それぞれの層数・断面・段数・電極枠・ファン数と処理間隔を既存処理の計算に合わせる。確率製品の定格は全速の平均収量を使う。転炉は連続吹錬の定格で、手動出湯中の時間も実測値には反映する。
- 改善箇所はボイラーの給水・熱源・出力、塔の触媒・ハッチ、槽の汚れ、稼働中の原料不足・搬出制限、回転・動力、電極・出力設定など装置が観測できる制約から表示する。停止や構造不成立はその旨を出す。RBMKの上限表示には既存の運転定格を使う。
- `compat/display/ProductionReadings.java`、`MachineReadings.java`、`MachineDisplaySource.java` と `mixin/GoggleOverlayMixin.java` がCreateと接続する。既存ディスプレイリンクの選択インデックスを保持するため、新項目を末尾に追加した。

## 確認と制約

- Gradleの `build` と専用サーバーの関連16クラス、108件が成功した。横型は長さ3の理論上限、端以外からの読み取り、加熱不足、配管搬出中の物量保存を確認した。ガス化炉は予熱中の定格と加熱診断、確定した生産の計測、時間経過後のゼロ復帰を確認した。
- Ponder言語・翻訳・チュートリアルの検証を実施した。RTX 4060で日本語クライアントを起動し、横型の稼働時95.7 / 159.57 mB/sと熱源診断、給水切れ時の表示切替、ガス化炉の250 mB/sの定格と原料診断を確認した。既存の汎用クライアントチェッカーは、常温のCreateタンクの既存概要を3行と期待する箇所で止まったため、その後の全項目ウィジェット幅の確認は完走していない。
- 在庫・配管・弁、採掘、洗浄剤を消費するだけのスクラバー、およびCreate標準加工機のレシピには、この生産定格は追加していない。レシピ特定が必要な設備では、初回のレシピ特定まで上限は未確定。停止時に最後の適用レシピの定格が残る設備がある。配管網全体の詰まり位置を探索する機能や、すべての装置・負荷規模でのクライアント確認は今回の範囲外。
- 配布JARは8 MiBに収まるようZIPの圧縮だけを変更し、全エントリーの内容が標準ビルドとバイト単位で一致することを確認した。
