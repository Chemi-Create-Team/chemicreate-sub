# ふた付き槽：混合・密閉反応・保守

作業日：2026-11-09。基準コミット：`c17ae68d`。実装コミット：`768a049b`（`Add sealed vessel processing, pressure and automated maintenance`）。

## 実装範囲

ふた付き槽を、実際の在庫・温度・圧力を持つ密閉反応容器へ拡張する。独自GUIや新しい駆動ブロックは追加しない。工程用の最小構造は既存の2×2、通常保管は1×1から利用できる。

- 側面の通常レンチ操作で、槽全体の検査窓を切り替える。上面のレンチは内部部品の取り出し、下面は軸方向の変更。保存・連結にも窓の状態を引き継ぐ。
- Createの標準アイテム能力・DirectBeltInputBehaviourと流体能力を公開する。ファンネル・ベルト・ポンプ・気体配管を使用する。
- 在庫は材料9スロット、製品4スロットと既存の触媒。通常保管と攪拌槽は任意のアイテムを受け入れる。攪拌槽の自動搬出は製品のみ、開いたハッチからの手動回収では材料も取り出せる。
- 攪拌羽根を取り付けると、既存の加圧反応とCreateのMixingレシピを処理する。実際のBlaze Burnerの加熱段階、材料、動力、製品容量を確認する。容器の残り（空バケツ・ガラス瓶など）も同じトランザクションに含める。
- 実際の液体・気体・アイテムを同期して描画する。処理中のみ内容物が周回する。透明窓は既存の接続外装モデルを切り抜き、壁の厚みを残す。
- 密閉気体を回収でき、過圧時には有限量の排出・音・処理停止で応答する。既存の圧力計を側面へ直接取り付け、流れがない時の圧力も観測する。
- 固形原料を使う加圧反応の成功バッチと指定された重質流体反応が汚れを蓄積する。これは保守負荷の指標で、無料の副産物や独立した物質量ではない。
- 開いたハッチをブラシで清掃でき、標準のDeployerでも同じ操作を行う。底のドレンと実際の洗浄水で排水を生成し、下面のパイプから排出する。
- 氷・雪・冷媒を使う冷却と低温条件を加える。窓の霜は内容物の温度から描画する。

## 熱と気液の扱い

Blaze Burnerは通常燃焼で10 kJ/t、超加熱で25 kJ/tを上限に内容物へ伝熱する。過圧停止中はこの伝熱を止める。氷・雪ブロックは260 Kから273.15 Kまでの顕熱と融解潜熱を使い切ると水になる。氷塊は9個分、青氷は81個分で、消費済み熱量を保存し、床の未ロードで復活させない。液体窒素は隣接する既存タンクと熱交換し、温まり、沸騰して窒素ガスになる。冷却による凍結熱の蓄積を製氷に使い、冷えた水だけで無限に氷を作らない。

物理タンクと各工程バッファは保管先を分けている。工程バッファの圧力計算容積は8,000 mB、圧縮気体の受入枠はその256倍。槽の計器は最も高い区画圧力を示す。水・蒸気は既存の`WaterPhase.solve`から液相と気相を求め、上面では乾き蒸気だけを取り出す。残液と取り出した蒸気の質量・熱量を保存する。液面描画には同じ計算による同期済みの液相・気相のキャッシュを使う。

洗浄水を別流体の排水に変える際は、水parcelの総熱量を排水の熱容量で割って温度を決める。1 mB未満の蒸気に相当する潜熱も、排水の顕熱として保持する。

## 次回の注意

- Ponderの`modifyBlockEntity`は静的なsection meshを再描画しない。窓NBTを切り替えた後は公開APIの`WorldSectionElement.queueRedraw`を明示する。通常worldのModelData更新とは別に確認する。
- Createの`CTModel`は、内側も`BakedModelWrapperWithData`でないと内側のモデルデータを集めない。窓のモデルはその拡張点を使う。
- ふた付き槽の通常貯蔵と7つの工程バッファは異なる保管先。液体・気体能力のスロット数だけを前提にせず、各槽の内容と容量を読む。
- 通常槽の材料は連結時に共有在庫へ移す。工程流体・汚れ・排水を持つコントローラーの移動は既存の構造ガードを維持する。
- 気体ネットワークのノード容量は圧力を計算する物理容積と、圧縮した気体の受入枠を区別する。
- ネイティブクライアントはNVIDIA RTX 4060で確認する。既知の終了時`libEGL_nvidia.so.0`異常が起きた場合、表示確認の成否とプロセスの終了結果を分けて報告する。
