# 反応を連続的に進める

2026-11-23。ユーザー指定：「機械の反応が連続じゃなくて数秒たったら原料を消費して断続的に出すっていう仕様のせいで音もおかしいしわかりづらい。連続的に反応させて」。あわせて、電解セル・タービン・RBMK・核融合・配管の計器のゴーグルも同じ構成にする。

## これまで
反応機は、1サイクル（最大10秒）の間は何もせず、終わった瞬間に原料を一度に消費して生成物を一度に出していた。原料が少しずつ届くと、1バッチ分たまるまで止まり、稼働／停止が切り替わる。音は「稼働中」の状態に連動するので、これも途切れていた。

## 変更
- 新規 `chemistry/ReactionFlow.java`：バッチのどこまで進んだか（0〜1）から、そのtickで消費する量と作る量を整数の mB で出す。原料は切り上げ、生成物は切り捨てで、生成物が原料より先に出ることはなく、1バッチ分進めればレシピの量どおりになる。
- `ReactorMachineBlockEntity`：
  - 固定レシピ（吸収塔など）：毎tick、速度から決まる量（段数×回転数÷サイクル）を、原料・生成物の空き・ガスの空きの範囲で変換する。
  - 撹拌槽・蓋つき容器：流体だけのレシピ（固体の原料や確率の生成物を持たないもの）を同じように連続で進める。許される量にならなければ、1/2、1/4…と刻みを減らす。
  - 固体を使うレシピは従来どおり1バッチずつ（固体は小数で減らせないため）。
- `ReactionTowerBlockEntity`：触媒反応を毎回の処理（5 tick ごと）で少しずつ進める。触媒の消耗は、バッチが1つ終わるごとに次の層に1回。固体を使う反応（トレー上の固体）は従来どおり。
- `FractionatingColumnBlockEntity`：蒸留と空気分離を連続にした。進み具合は従来の `progress` をそのまま使う（保存も同じ）。
- 状態：原料が1バッチ分に足りなくても、少しでもあれば「稼働中」のまま。なくなったら止まる。
- 検査：`GoggleSpecGameTests.aReactionConvertsAWholeBatchInSmallSteps`（250 mB を入れて 100 mB を作るバッチを不揃いな刻みで進め、合計がレシピどおりで、生成物が先に出ないことを確かめる）。

## ゴーグル
- 電解セル、蒸気タービン、核融合炉、RBMK 制御卓：最上段を `稼働中` / `⚠ 停止中: 状態` にそろえ、元の行をその下に並べた。
- 配管の計器：名前の行を省き、計測値を最上段に出す。

## 未確認・注意
- コンパイルもゲーム内も確認していない（構文チェックのみ）。
- 既存のGameTestのうち、サイクル途中の槽の中身（途中で空のまま、など）を確かめているものは、連続になったので結果が変わる可能性がある。サイクルを終えた後の合計は変わらない。
- ガス化炉・電解の工程・固体を使うレシピは従来のまま。
