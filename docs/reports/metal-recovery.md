# 汎用金属の3倍・2倍回収ライン

実装コミット：`3f75c3726b0de21a6a18fcea8a21888bc9f8b14e`

2026-11-16。ユーザーが選択した「専用マルチブロック」の方針で実装。鉄・銅・亜鉛・錫を対象とし、金の化学回収を廃止した。

## 実装

原石1個をCreateで粉砕した鉱石1個が倍率の基準。鉱石ブロックの追加原石や幸運は別。共通工程は次のとおり。

| 工程 | 入力 | 出力・条件 |
| --- | --- | --- |
| 希硫酸調製 | 硫酸250 mB、水750 mB | 希硫酸1000 mB。Createのミキサー |
| 加熱浸出 | 粉砕済み鉱石1、希硫酸250 mB | 濁った浸出液1000 mB。既存3×3撹拌槽、32 RPMで200 tick |
| 沈降分離 | 濁った浸出液1000 mB | 精製溶液1000 mB、鉱滓スラッジ1。200 tick、電気・回転不要 |
| 電解採取 | 精製溶液1000 mB | インゴット3、再生希硫酸250 mB。既存電解セルで20 kJ／ニッケル極板14 kJ |
| 晶析 | 精製溶液1000 mB | 金属塩結晶2、排水250 mB。400 tick、電気・回転不要、底の加熱中は停止 |
| 結晶加熱 | 結晶1 | 対応インゴット1。かまど・溶鉱炉・Createのファン加熱 |

電解と晶析は同じ精製液を消費する選択分岐。電解側は希硫酸を浸出槽へ循環でき、晶析側は酸を再生しない。実際の金属別電解条件や化学量論を厳密に再現する数値ではなく、ゲーム内の共通工程。

沈降槽は5×3×3、晶析槽は3×3×4。底面・外周・空洞・制御部・上部液体出口・下部固体出口を実際に判定する。晶析槽は3段目外周の冷却部も必須。向きに合わせて成形し、制御部正面から投入、上部出口から液体、下部出口から固体を標準能力で搬出する。形成待ちの探索は20 tick間隔・固定体積内に限定し、チャンクを強制ロードしない。外装は処理用tickerを持たず、在庫・進捗は制御部だけが保持する。

満杯・加熱・解体では原料を先払いせず停止。修復・保存再開で未払いバッチの進捗を保持する。空洞へのブロック設置も隣接部材から検知する。制御部を壊すと全在庫を含むブロックアイテム1個へ保存。電解セルには各セルの金属在庫、陰極側の金属搬出、陽極側下部の再生酸搬出を追加し、既存の水・重水・塩水・HF電解を維持した。

錫石鉱石・深層錫石鉱石、原料・粉砕済み鉱石・錫インゴット、4金属の結晶・濁った浸出液・精製液、廃泥を追加。錫石は新規のオーバーワールド区画で生成する。金の旧流体・バケツ・浸出／還元レシピ、旧酸素加圧浸出／水素還元を削除した。鉄・銅・亜鉛の既存溶液IDは精製液として維持する。

## 制約と対象外の検査

- 実チャンクのアンロードを繰り返す長期運転、多人数の長期負荷、性能比較は未実施。高速化の数値的な主張はしない。音声デバイスがなく聴取は未確認。
- GPUの画面確認・ワールド保存後にNVIDIAネイティブ終了クラッシュ（exit 134）が発生する環境。検証結果JSONの成功と`runClient`全体の終了失敗を区別している。
- 全体の`RecipeVisibilityGameTests`は、今回変更していない冷却流体の代替候補5件を要求する旧監査で失敗する。現行`PlantProcess.acceptedFluids`は入力自身だけを返す。同じく工場全体の旧JEI追跡監査は合成ガス→Haber–Boschの触媒追跡で失敗した。対象外を改変せず記録し、新画面の確認は独立した`recipeScreenCheck`で実施した。
- 全体の`validate_visual_identity.py`は、既存9素材（`heated_unfinished_steel`、`pig_iron`、`steel_slag`、高低圧タービンユニット、`iron_pipe`、`jacketed_pipe`、照射カートリッジ2種）の分類漏れで停止する。今回追加した原料・錫・廃泥・4結晶の分類とテクスチャは追加確認した。
- 廃止した金の液体・バケツを持つ開発ワールドは登録削除の影響を受ける。互換専用登録は残していない。金の通常精錬・Create処理は維持。
