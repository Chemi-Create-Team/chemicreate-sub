# RBMK最大炉・制御室・Display Link 運転サイクル実機試験レポート

## 結果

最大サイズ（直径13m円筒、燃料397・制御棒51）のRBMKを、実際のMinecraftクライアントで「起動→臨界→危険→AZ-5停止→再起動」の2周運転した。制御室は標準Display Link（炉の上部キャップを情報源、制御卓の盤面を対象）で接続し、別のDisplay Linkでディスプレイボードにも出力を送った。2周とも完走し、全局面で制御卓は`linked`、制御卓の状態は炉本体の状態と一致、Display Linkの表示値は炉の出力と一致した。

## 追加した試験

- `tools/create_rbmk_playtest.ps1 -Scenario cycle`（`RbmkPlaytestPlant`の`CYCLE`ステージ）。クレーンと採石の工程は飛ばす。
- 炉の南側に制御室（卓・計器パネル・炉心マップ）とディスプレイボードを置く。炉心中央の上部キャップ2か所に標準Display Linkを置き、1つは制御卓の盤面、もう1つはボードを対象にする。
- 各周: 制御棒を引いて臨界（出力12MW）→保持→さらに引いて危険域（出力が定格の30%超、燃料1300K超、過熱、即発臨界のいずれか）→AZ-5の赤石ブロックで停止→解除して全挿入→再起動。
- 各局面で、炉本体・制御卓・キャップのDisplay Link読み・ボード用Display Linkの出力を記録する。接続は開始200tick後に確認し、未接続なら失敗にする。
- 制御棒の追従が遅れる間は調整を待つ。待たないと設定値だけが先に下がり、出力暴走する。

## 制約と注意

- 制御卓の値は4Hzの計測スナップショットなので、出力が急に変わる局面では炉本体より遅れる（最大で約15%、2周目の危険局面）。2周目の危険局面では炉が`prompt_critical`、制御卓がまだ`supercritical`と表示した。
- 危険局面は炉が実際に危険域へ入った時点でAZ-5を押す設計で、爆発までは進めていない。爆発までの経過は既存の`plant`シナリオが扱う。
- 最初の実行（調整の待ちなし）では1周目の起動で最大7,145MW、燃料437Kまでの出力暴走と自動スクラムが出た。これは調整側の問題で、棒の追従を待つ条件を入れて解消した。炉の挙動は修正していない。
- 実機で確認したのは接続・状態・数値の一致と運転の流れのみ。ディスプレイボードに表示される文字そのもの（フラップの描画）は、Display Linkが出力した文字列と画面の撮影（`run/screenshots/rbmk-plant-console.png`）でしか確認していない。ボードの内部状態は読んでいない。
- 時間は最大100tick/秒に加速して実行している。
- ビルドの`build`・GameTestは今回再実行していない（試験ツールのみの変更）。

## 5x5制御盤(496c468)後の再試験

試験の制御室を10幅の壁(`WALL_WIDTH`/`WALL_OFFSET`)に合わせて再実行した。2周完走、全局面で制御卓は`linked`、状態は炉と一致、ボード出力は炉の出力と一致した。1周目は従来と同じ(臨界11.93MW、危険121.19MW、停止3.97MW、最高燃料307K)。
ただし2周目の「保持」で出力が4101MW(定格の約10倍)、燃料1353Kまで上がった(棒設定72、反応度+0.17$)。AZ-5後は893Kまで下がり破損はしなかった。原因は未調査で、試験の調整側か、局所出力分布の追加(`localRodPower`)かは切り分けていない。
