# クァーリーの水・溶岩の自動排水

2026-11-18（JST）。実装コミットは `966cbde74db93bd9b2fe97bb816fd81104536c3a`。

## 動作

`QuarryDriveBlockEntity` は先に採掘する列を確認し、水源・水流と溶岩源・溶岩流を空気に置き換える。列全体を同じtickで処理し、残った隣接源から排水途中の列に水源が再生成されるのを抑える。排水対象はレール間の掘削範囲内の水・溶岩ブロック。水没したブロック、内容物、別種の液体を保持する。

液体を確認する列の探索は駆動部ごとに1tick最大256マス。排水の書き換えは1tick最大1列分。排水中も既存の動力・レッドストーン条件とチャンク読み込みを使い、ゴーグルに排水中と表示する。

`NextLiquidRow` に排水位置を保存する。旧セーブでは最上段から既存の採掘位置まで液体だけを確認する。採掘済みの旧機体も信号を入れると一度確認し、`Layer` と `Cell`、掘削跡の固体ブロックや在庫を保全したまま終了する。

Ponder の `quarry_frame` では、レール間にある水と溶岩を採掘前に抜く場面を追加した。説明は日本語・英語・中国語に対応する。

## 検証

Java 21、Minecraft 1.21.1、NeoForge 21.1.219、Create 6.0.10。Gradle `build` と専用サーバーの `QuarryGameTests,QuarrySpeedGameTests` 全17件が成功した。

- 囲った水と溶岩の源・流れを排水し、溶岩の下も採掘する。範囲外の水源は維持する。
- 完了済みの旧NBTを読み、信号停止中は液体を保持する。稼働後は排水位置の保存・再読込、既設ブロック、水没チェストと内容物の保持、排水後のチケット解放を確認する。
- 既存の搬送・隣接枠・採掘速度試験と、Ponder の言語・チュートリアル検査を再実行した。

範囲外の供給源からの再流入には通常の液体の流れが適用される。本番ワールドでの動作と、多数台同時稼働時の負荷は未計測。
