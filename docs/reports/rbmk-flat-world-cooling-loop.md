# RBMK最大炉・制御盤・冷却復水ループのフラットワールド試験場

## 内容

`tools/create_rbmk_playtest.ps1 -Scenario loop` で、フラットワールドに最大炉(燃料397・制御棒51、制御棒全挿入、冷却水満水)、5x5制御盤、標準Display Link、ディスプレイボードと、次の冷却ループを建てて起動する。起動後は自動操作をしない(ゲームを開いたままにする)。

- 炉の蒸気出口 → ポンプ(クリエイティブモーター駆動) → 上空の配管 → ラジエーター8セル(各セルのファンは256rpmのモーター)の東端から流入 → 西端から復水
- 復水 → ポンプ → Create流体タンク(6,000 mB入り) → ポンプ → 炉の給水口

`-Dcreateplant.loopCheck=true`(`JAVA_TOOL_OPTIONS`)を付けると、制御棒を自動で引いて運転し、タンク量・炉内水量などを `run/rbmk-plant-result.json` に記録する。

## 実測(確認モード、定格397MW)

- 出力10〜40MWで運転すると、タンクが6,000→8,000 mBへ増え、のち6,000 mBへ戻った。蒸気出口ポンプ→ラジエーター→タンクと、タンク→給水口の両方向の水移動を確認した。
- ボイド率は約15,800 tickから上がり始め、約27,000 tickで出力が急上昇して過熱(`overheat`)、炉心が失われた。ラジエーターの凝縮量が炉の蒸気発生に追いつかず、蒸気が炉内に残って正のボイド係数で暴走したと見ている。制御棒を全挿入にしても止まらなかった。

## 制約・未確認

- ラジエーターの凝縮能力は `UA×(100℃−外気温)`、1セル約0.1MW(8セルで約1MW)。炉の最低臨界出力(10MW級)に対して桁違いに小さく、この設備では出力を約1MW以下に保たないと蒸気を処理できない。設備の仕様であり、今回は変更していない。
- 蒸気だけが凝縮して水槽へ戻る定常運転(1MW級)は確認していない。
- ゲーム内の見た目(配管の接続、ファンの回転)は目視していない。

## Codexの混相流・給水細管束直結への追従(2026-11-05)

給水口はシールド入力部ではなく、露出した給水細管束への標準パイプ直結になったため、試験場の給水配管の終端を上下接続の標準パイプにした。確認モードで20,000 tick運転した結果は次のとおり。

- 水槽は6,000→2,247 mBへ減り(配管内へ移動)、炉が沸騰を始めた約18,500 tick以降は復水が戻って5,447→8,000 mBへ増えた。炉内水量は3,136,000→3,126,275 mBへ減り、蒸気が炉から出て復水して水槽へ戻る流れを数値で確認した。
- 出力は最大37MW、最高燃料温度は430K、ボイド率は0.21まで上がった。ラジエーターの凝縮が追いつかず上昇を続けていたが、この20,000 tickでは過熱・破損は起きなかった。
- 気液分離器・タービンは入れていない(ラジエーター直結の簡易ループ)。

## 炉に水が入らない不具合の修正(2026-11-05)

原因は2つ。(1) 給水細管束にブロックエンティティが無く、Createの配管(`FluidPropagator.hasFluidCapability`は先にブロックエンティティを取得する)が流体の接続先として認識せず、ポンプで送った水が配管内で止まっていた。(2) 試験場の配管を既定の全方向開放の状態から作っていたため、空気側へ開いた端から水が漏れていた。

- `FeedBundleBlock`に状態を持たない`FeedBundleBlockEntity`を付けた(流体ポートは従来どおりブロックのCapability)。GameTestに、配管が接続先と認識することの確認を追加した。
- 試験場の配管は、接続しない面を閉じた状態で置くようにした。
- 確認: 炉の水を42,000 mB抜いた状態で運転すると、水槽の6,000 mBがすべて炉へ入り(炉内 3,094,000→3,100,000 mB)、漏れは無くなった。原子炉関連GameTest 13件は成功。全GameTestは再実行していない。

## 気液分離器つきの循環へ作り直し(2026-11-05)

Createのポンプは約16ブロックまでの配管しか押せないため、各区間にポンプを置く構成にした。蒸気だけをラジエーターへ送る。

1. 炉の出口(混相流)→ポンプ → 東側を下る配管(途中にもポンプ) → 気液分離器(2×2×2、上層の側面から流入)。
2. 分離器の上面の蒸気 → ポンプ → 北側の通路(途中に2台) → ラジエーター8セルの東端から流入し、西端から復水。
3. 復水 → ポンプ → 水槽。分離器の底面の水 → ポンプ → 同じ水槽。
4. 水槽の南側から出す給水管 → ポンプ → 炉の給水細管束の下面。

別の系統の配管が上下に隣り合うと、Createの配管は勝手につながって短絡する(給水管と分離器の水の配管で起きていた)。給水管は水槽の別の側から出して離した。
ポンプはCreateの回転方向で流れの向きが決まるため、起動20 tick後に逆回転のポンプを検出してモーターの向きを直す。

### 確認(確認モード)
- 炉の水が分離器と水槽へ出て給水で戻る循環を数値で確認した(炉内水量・水槽量が連動して増減)。
- 炉を臨界まで運転すると、同じ出力10〜30MWでも以前(ラジエーター直結)よりボイド率が低く抑えられた(最大0.019、直結では0.2超)。
- ただし約15,600 tickで出力が急上昇して炉心を失った(最高燃料温度は382K)。確認用の自動調整が棒を戻さないためと見ているが、原因は切り分けていない。
- ラジエーターの凝縮能力(8セルで約1MW)は変えていない。出力を上げるには並列の行を増やす必要がある。

## 列ごとの流量のばらつきの修正(2026-11-05)

出口と給水が、1回の要求量を1本の列からまとめて出し入れしていたため、列ごとの流量計が大きく振れていた。`nuclear/EvenShare`で、1回の量を全列へ均等に分け(満杯・空の列の余りは他の列へ回す)、出口(`ReactorCore.takeMixed`)と給水(`FeedBundleBlock`)の両方で使うようにした。

- 同じ条件(平坦ワールドの循環、炉停止中の1,200 tick)で、列ごとの流量の最大値は変更前 6.4〜19.2 mB/t、変更後 1.10〜1.15 mB/t(平均は約0.95 mB/t)。
- 流量0の列が16本あるのは、有効な冷却チャネルが無く容量0の外周の列で、変更前後とも同じ。
- 原子炉関連のGameTest 13件は成功。全GameTestは再実行していない。1回の出し入れで全列を調べるため、列数が多い最大炉での処理時間は計測していない。
