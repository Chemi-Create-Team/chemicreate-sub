## 実装内容

### 4区画の独立描画

- `RBMKPlugRenderer`で、上部キャップ1ブロック内の北西・北東・南西・南東を別々に描画する。
- 各区画で`PoseStack.pushPose()`し、既存の区画中心へ移動してから、その区画固有のY変位だけを加え、描画後に`popPose()`する。
- 既存の燃料・制御・空制御用PartialModelをそのまま使う。BlockStateモデル、PartialModelのJSON、テクスチャは変更していない。

### 局所過圧と350 kgプラグの運動

`PlugPhysicsSimulator`が4区画の状態をまとめて持つ。温度`T_i`、流量`F_i`、制御棒挿入率`R_i`から、次の無次元局所過圧を求める。

`HeatGen = max(0, (T_i - 373.15) / (1500 - 373.15)) × (1 - 0.65 R_i)`

`Cooling = max(0, F_i) / 64`

`P_local = max(0, (HeatGen - Cooling) / 0.85)`

- `P_local < 1`ならY変位は厳密に0。
- 閾値以上では、ブロック座標と区画番号から決めた固有の角速度・位相・連続値ノイズを使い、`max(0, sin(ω_i t + φ_i) + Noise)^4 × A(P_local)`を評価する。
- 4乗波形により、着座時間を長く、一瞬の跳ね上がりを鋭くした。350 kgのプラグ向けに振幅を調整し、最大変位は0.35 mに制限した。
- 区画ごとの位相とノイズは独立だが決定的で、同じ座標・時刻・圧力ならサーバーとクライアントが同じ波形を得る。

### 減圧・同期・演出

- サーバーの`RodCapBlockEntity.tick()`だけが温度・流量・制御棒深度を読み、減圧量、開放、着地を判定する。レンダラーは状態を変更しない。
- 変位が5 cmを超えると、その区画に一時的な減圧量を積む。閉じている間は毎tick減衰するので、プラグが浮き続けず、圧力が戻ると再び間欠的に跳ねる。
- 減圧量はワールド保存NBTへ、実効局所圧力はクライアント同期NBTへ保存する。圧力同期は閾値横断または0.04以上の変化時、位置ごとに分散して最大4 Hzに制限した。
- 変位が0より大きい区画には、3 tickごとに上向き速度を持つ`ParticleTypes.CLOUD`を送る。
- 前tickで変位が正、現在tickで0になった着地時に、低めのランダムピッチで`SoundEvents.ANVIL_LAND`を再生する。
- 最大変位を含むようにBlockEntityの描画境界を上へ拡張した。

## データの割当て

| 入力 | 現在の割当て |
| --- | --- |
| `T_i` | その2×2束を保持する燃料チャネルの実測燃料温度 |
| `F_i` | 束の実測流量を有効区画数で割った1区画分の流量 |
| `R_i` | 制御区画はその区画の棒の実深度÷7 m、燃料区画は0 |

上部キャップから下端の燃料チャネルを探す処理はキャッシュし、全14段の上部管経路の再確認を10 tickごとの遅延tickへ移した。毎フレームのレンダラーと毎tickの減圧計算が構造全体を繰り返し走査しない。

## 制約

- 現在の炉心シミュレーションは温度と流量を2×2束単位で保持するため、同じ束の4区画で`T_i`と元の流量は共通である。区画差は有効／無効、区画別の制御棒深度、固有位相・ノイズにより生じる。将来、炉心が棒ごとの温度・流量を持てば、入力配列へそのまま差し替えられる。
- `P_local`はPaではなく、既存データから演出と減圧判定を作る無次元の疑似圧力である。
- 減圧フィードバックはその区画の疑似圧力を一時的に下げる。束内に区画別の蒸気在庫がないため、共有冷却材から見かけの蒸気質量を差し引いてはいない。
- 実物の約3 mという長さは既存モデルを変更せず表現する条件のため形状へ反映せず、最大0.35 mのY移動だけを描画する。
- この機構は警告と小さな減圧であり、既存の圧力管破損・炉心爆発判定を置き換えない。
