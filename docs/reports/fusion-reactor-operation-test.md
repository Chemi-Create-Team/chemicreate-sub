## 確認した仕様上の注意点：ドラム約23 bar以上で一次冷却が止まる

### 現象

蒸気喪失の区間で、ドラムの水が1,463,000 mBから約114,000 mBまで減り、炉の冷却水出口に1,027,968 mB、入口に約508,000 mBが滞留した。ブランケットは229.6 °Cのまま冷えなかった。蒸気の再開で圧力が下がると全量がドラムへ戻った。

### 切り分け

| 確認 | 結果 |
| --- | --- |
| 滞留中の炉出口ポンプ5台 | すべて256 RPM、過負荷なし、配管の流路は完成 |
| ドラムの受け入れ（SIMULATE） | 1,000 mBを受け入れ可能 |
| 水の総量 | 変化なし。消失ではなく炉内バッファへの移動 |
| 流れた圧力 | 22.54 barでは滞留なし（通常昇温時）。21.84 barが上限の短縮試験でも滞留なし |
| 止まった圧力 | 23.29〜23.99 barの区間では滞留 |

ポンプと配管の故障ではない。[PassiveFluidNetworkMixin](../../src/main/java/net/createplant/mixin/PassiveFluidNetworkMixin.java)と`PressureSections.plan`では、ポンプはポンプ入口の圧力に揚程を足した圧力までしか容器へ押し込めない。炉の出口ポートの圧力は大気圧（1.013 bar）として扱われ、ポンプはドラム圧のほぼ全量を揚程で賄う必要がある。実測の閾値は22.54〜23.29 barの間である。揚程の式から閾値を理論計算して一致させるところまでは確認していないため、この因果は実測と実装からの判断である。

一方、低温側はドラムから大気圧扱いの炉入口へ下るため流れ続ける。これがドラムの水が炉へ移動した理由である。一度この状態に入ると、水を抜いてもドラム圧は飽和圧のまま下がらないので、蒸気を再開するまで解消しない。

### 影響

- 安全側には倒れる。今回は電源喪失で既に燃焼が止まっており、爆発も水の消失もなかった。
- 最大ドラム圧24.16 barは、熱の収支で決まった値ではなく、この揚程の頭打ちで抑えられた値と考えられる。定格50 barに対する余裕として読まないこと。
- 通常運転の20.10 barから閾値までの余裕は約3 barしかない。
- 外部電源を維持したまま蒸気だけを失う場合は、冷却水出口が満杯になった時点で燃焼が止まるはずだが、この経路は未試験である。

修正するかどうかは設計判断である。候補は、炉の出口ポートに冷却水の圧力を持たせること、またはこの閾値を文書化してポンプの直列配置などで揚程を確保することである。

## 蒸気喪失の停止の仕方

蒸気を止めると、4 tickで燃焼が止まる。原因は冷却不足ではなく電源喪失である。タービンの回転力が失われて軸全体が過負荷で0 RPMになり、電動発電機が`overload`となって炉の電力が0になる。大型フライホイールの伝達上限（約10 MW）は軸の負荷約44.5 MWより小さいので、この停止を支えられない。

- 試験コード内のメッセージ「Losing the steam sink starves the blanket」は、実際の停止理由と異なる。今回は変更していない。
- 電力0の間も制御盤の状態は`heating`のままで、電源喪失を示さない。ゲーム内の表示としては分かりにくい。今回は変更していない。

## 訂正

前回レポートの蒸気喪失の行「4 tick遮断」は誤りだった。遮断時間は1,500 tickで、4 tickは遮断から燃焼停止までの時間である。[fusion-steam-plant-test.md](fusion-steam-plant-test.md)を訂正した。
