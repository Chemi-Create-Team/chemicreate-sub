# 核融合の照射カートリッジと、採掘クレーンの揚鉱塔：完了レポート

ユーザーの指示は2つ。

- 最終目標の案（核融合炉の照射でネザライトの欠片）で進めること
- 採掘クレーンのアイテムの流れを、ヘッドの箱 → 蛇腹のシュート → 垂直の揚鉱塔 → ファンネル → ベルト にすること

## 1. 照射カートリッジ（コミット`71d05b8`）

- **アイテム**
  - 照射カートリッジ（`irradiation_cartridge`）：耐久24,000、1個ずつ。
  - 照射済みカートリッジ（`irradiated_cartridge`）。
  - 見た目は、リチウム鉛ブランケットのテクスチャを塗り替えて作った（`tools/generate_irradiation_cartridge.py`）。照射カートリッジは金とチタンの色、照射済みは暗い中身に青い光。
- **レシピ**
  - 作業台：チタン板4、金インゴット4、使用済みブランケットカートリッジ1。
  - 撹拌槽（加熱）：照射済みカートリッジ1と塩酸1,000 mBから、ネザライトの欠片8、使用済みブランケットカートリッジ1（外殻の再利用）、高レベル放射性廃液250 mB。
- **核融合炉**
  - ブランケットの枠に照射カートリッジも入るようにした。消耗の速さはリチウム鉛と同じで、定格運転なら約6.7時間で使い切る。
  - 三重水素を増殖するのは、リチウム鉛のときだけ（`breedsTritium()`）。照射中は、ためた燃料で運転する。
- **クレーン（核融合の保守）**
  - 倉庫に照射カートリッジがあれば、次の交換でブランケットの代わりにそれを入れる。
  - 照射カートリッジは使い切るまで外さない。途中で外すと収量が無駄になるため。
  - 使い切った物は照射済みカートリッジとして倉庫に戻る。途中で外された物は、その消耗のまま戻り、倉庫から取り出せる。
- **その他**
  - 照射済みカートリッジは、使用済みブランケットと同じ放射線源にした。
  - クリエイティブタブ、Ponder「核融合炉の遠隔保守」の最後の手順、説明書の回転力の章と実績「最後の工場」に、使い方を書いた。
- **確認**
  - GameTest `craneSwapsAUsedUpIrradiationCartridgeForItsYield`：使い切った照射カートリッジを、クレーンがリチウム鉛と交換すること。照射中は増殖しないこと。
  - サバイバルで入手できるかの検査にも追加した。
  - 撹拌槽の全レシピを実際の槽で動かす既存のGameTestで、溶解レシピも動くことを確認した。

## 2. 採掘クレーンの揚鉱塔

> この章の揚鉱塔は、`docs/reports/quarry-drive-belt-flow.md`のクァーリー駆動部と側面ベルトに置き換えて削除した。

### 流れ

1. **ヘッドの箱（9スロット）**：掘った物は、駆動部の倉庫ではなく、ドリルヘッドを囲む箱に入る。箱が満杯なら掘らずに待つ（状態「ヘッドの箱が満杯」）。
2. **蛇腹のシュート**：箱から16個ずつ（10 tickごと、シュート内は6便まで）、ヘッドの位置に追従する曲線のシュートで、揚鉱塔の足元へ送る。速さは毎tick 0.25ブロック。
3. **揚鉱塔**（新ブロック`crane_lift`）：駆動部の真下に2段以上積む。足元に着いた荷は、1段あたり6 tickで最上段まで上がり、出口（9スロット）に入る。
4. **ファンネル**：塔のどの段の側面に付けたファンネルからも、出口の物を取り出せる。ベルトへ出せば、クレーンが範囲を動き回る間も、塔から鉱石が出続ける。

### 設計

- 状態はすべて駆動部の`CraneConveyor`が持ち、揚鉱塔ブロックは状態を持たない。塔のアイテム能力は、上の駆動部の出口（取り出し専用）を返す。
- 塔の段や駆動部が置かれた・壊されたときは、列全体の能力キャッシュを無効にする。
- 荷は順番を守り、前の段が詰まっていれば待つ（消えない）。出口が満杯なら塔で止まり、次にシュート、最後にヘッドの箱が止まる。
- 塔が1段以下のときは掘らない（状態「駆動部の下に揚鉱塔を2段以上積んでください」）。
- 枠を組むときに邪魔なブロックを掘った分は、従来どおり駆動部の倉庫に入る。
- 駆動部を壊すと、箱・シュート・塔・出口の中身をすべて落とす。
- 同期は、荷の開始・乗り換え・到着のときだけ送る。クライアントは開始時刻と所要時間から位置を補間する。
  - サーバーとクライアントの時刻のずれは「Now」で補正する。Ponderの中でも同じように動く。
- ゴーグルに「揚鉱塔の段数、ヘッドの個数、搬送中の便数、出口の個数」を表示する。

### 見た目

- **揚鉱塔のモデル**：安山岩ケーシングの柱と帯に、奥にCreateのベルトを立てた枠。中を上がる荷が見える。
- **ヘッドの箱**：ドリルの軸を囲むケーシングの箱。
- **シュート**：ケーシングの輪とゴムのひだを交互に、二次曲線に沿って並べて描く（`CraneRenderer`）。
- **アイテム**：シュートと塔の中を回転しながら動く。
- テクスチャは、Createの安山岩ケーシング・ベルト・シュートを流用した。

### Ponder「マーカーから採掘場を建てる」

穴が開いた段階で、次の順に見せる手順を足した。

1. 揚鉱塔3段
2. 蛇腹のシュートを流れる荷と、塔を上がる荷
3. 真鍮のファンネル
4. 2ブロックのベルト

### 生成元

- `tools/generate_crane_lift.py`：塔とシュートのモデル、ルートテーブル、レシピ（安山岩ケーシング4とベルトから2個）、つるはしタグ、翻訳。
- `generate_crane_assets.py`の「満杯」の文言も新しい意味に合わせた。

### 確認

- **CraneGameTests**
  - `quarryMinesItsSpanUpTheLiftTower`：掘った土と丸石が、塔の足元のアイテム能力から取れる。
  - `aQuarryWithoutItsLiftTowerWaits`：1段では掘らない。
  - `theChuteAndTowerKeepEveryItemInOrderWhenTheOutletIsFull`：9スタックがすべて出口に届く。満杯の出口で次の荷が塔に留まって消えない。出口を空けると流れる。出口に物を入れられない。
  - `markerBuildsTheFrameThenTheQuarryDigs`：塔の出口で15個を数える。
- **関係する37件**（Crane、PowerPlant、CreativeCatalog、SurvivalReachability、CraftingRecipe、PlantTutorial）：合格。
- **全GameTest**（`runGameTestServer`）：失敗は、以前からある汚れのテスト（`aFouledProcessStopsThenResumesAfterOneManualBrush`）1件だけ。
- **クライアント**：Ponder 141シーンで合格。拡大した画面で、シュート・ヘッドの箱・塔の中の荷・ファンネル・ベルトを確認した。

## 未確認・制約

- **実ワールドで動かしていない：** 長時間の採掘、深い穴での見た目、大きな採掘場での描画負荷は、Ponderとテスト以外では見ていない。シュートは1本あたり最大で数百個の輪を描く。
- **核融合の収量の釣り合い：** 照射カートリッジ1本で欠片8個という釣り合いは、運転時間からの見積もりで、遊んで確かめてはいない。
- **ファンネルとベルト：** 実際のファンネルでベルトへ出せることは、Createのファンネルがアイテム能力から取り出す既存の仕組みに頼っている。GameTestでは能力の取り出しまでを確認し、ファンネルブロックそのものは使っていない。
