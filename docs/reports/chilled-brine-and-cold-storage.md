# 冷やした不凍液の使い道（凝縮・液体塩素・製氷）と、低温の液化ガスの保冷

## 概要

ユーザーの決定（2026-11-07）で、次の3つを実装した。

1. 案A：流体熱交換器で、気体をそれより冷たい流体に当てて凝縮させる。新しい液体として液体塩素を加えた。
2. 案B：流体熱交換器で、0 °Cより冷たい流体に当てて水を凍らせ、氷を作る。
3. 0 °Cより冷たい液化ガスは、保冷配管・保冷タンクを通さないと気化する。

新しいブロックは作っていない。既存の流体熱交換器・タンク・配管の共通処理（`PhaseChange`、`PassiveHeat`、`PassiveTank`）に足した。

- 実装コミット：`ed914448eac21adedf32ef5ce072919e9871192a`

## 実装

### 流体熱交換器での凝縮（`ThermalEquipment.condense`、`PhaseChange.condense`）

- **判定の順番：** 片側の入口に相変化の組の気体（アンモニア・酸素・塩素・ヘリウム）があり、もう片側に冷媒があると、まず凝縮を試す。液体の蒸発（既存）がある場合は、そちらが先に動く。
- **凝縮温度：** 気体の入口バッファの圧力での沸点にした。ラジエーターと同じ求め方。
- **熱量：** 冷媒が奪える熱は `C × (T凝縮 − T冷媒) × (1 − exp(−UA × 0.25 s ÷ C))` とした。`C` はその回に流れる冷媒の熱容量。冷媒は凝縮温度へ近づくだけで、超えない。蒸発の式と対になっている。
- **量：** 凝縮する液体は1 mB単位で、気体は組の比の分だけ減る。質量は増減しない。
- **凝縮しない場合：** 冷媒が凝縮温度より冷たくないとき、または臨界点以上のときは凝縮しない。その場合は従来どおり、気体のまま冷える。
- **ラジエーターとの共通化：** ラジエーターの凝縮も、同じ `liquefy` の計算を使うようにした。結果は以前と変わらない。

### 液体塩素

- **登録した場所：**
  - `CEChlorAlkali.LIQUID_CHLORINE`
  - 物性（`FluidPhase`）：塩素と同じで、液密度は1.5616 kg/L。
  - `FluidThermal`：比熱960 J/(kg·K)。
  - 危険性（`FluidHazards`）：239 K、8 bar。腐食はなし（乾いた液体塩素は鋼を傷めない）。
  - 有毒ガス（`ToxicGas`）：塩素と同じ強さ。スクラバーでも除ける。
  - `PhaseChange` の組：塩素と液体塩素。
- **量の比：** 液密度は、塩素ガスの基準密度0.0032 kg/Lの488倍に決めた。液体塩素1 mBは、塩素ガス488 mBと同じ質量になる。
- **凝縮温度：** 1 barで−34 °C、1.5 barで約−24 °C。冷凍サイクルの不凍液（約−30 °C）で凝縮させるには、少し圧縮する必要がある。外気20 °Cなら、ラジエーターで約7 bar以上にしても液化できる。
- **レシピとの関係：** 塩素を使うレシピは、今までどおり塩素ガスを要る。液体塩素は流体熱交換器で気化させて使う。

### 製氷（`ThermalEquipment.exchange`）

- **凍る条件：** 水を冷やす側の流れが0 °C（凍る温度）で止まった後、冷媒がまだ0 °Cより冷たいと、その差で水が凍る。熱量の求め方は凝縮と同じ形。
- **熱量：** 凍る熱は1 mBあたり334 Jで、冷媒の側が受け取る。凍らなかった水は0 °Cで出る。
- **貯め方：**
  - 水1,000 mBで氷1個。
  - 凍りかけの量（`FrozenMb`、999 mBまで）と氷（最大64個）は、熱交換器に保存する。
  - 64個たまると凍らせない。
- **取り出し方：**
  - 熱交換器の部品（`CEHeating.PART_ENTITY`）に、取り出すだけのアイテムの口を登録した。どの部品からでも、シュートやファンネルで取り出せる。
  - 物は入れられない。
  - 工業用加熱器には口を付けていない。
- **壊したとき：** 熱交換器を壊す（`dismantle`）と、たまった氷は落ちる。凍りかけの分は、水としても氷としても戻らず消える。
- **ゴーグル：** 状態「水を凍らせて氷を作っている」と、氷の数・凍りかけの量を出す。

### 保冷していない配管・タンクでの気化

- **配管（`PassiveHeat.transport`）：**
  - 0 °Cより冷たい液化ガスが外気より冷たいときは、温度はそのままにする。入った熱 `UA × (T外気 − T) × (通過する時間)` の分だけ、蒸発した割合（`vapour_fraction`）を上げる（`PhaseChange.boil`）。
  - 量（質量）は変わらない。割合が1に達すると、その流れは冷やす力を持たない。
  - 保冷配管は `UA = 0` なので変わらない。
- **Createの配管の受け渡し（`PassiveFluidNetworkMixin`）：** 渡す流体を、温度だけでなく、シミュレーションで計算した流体そのもの（蒸発した割合を含む）にした。
- **タンク（`PassiveTank`）：**
  - 0 °Cより冷たい液化ガスは、臨界点より暖かい外気の液化酸素と同じ扱いにした（既存の `workingFluidProjection`）。1 barの沸点まで下がり、外気の熱で沸騰して、全部が気体になる。
  - 0 °C以上の液化ガスは、今までどおり自分の蒸気圧で液体のまま残る。例は、ラジエーターで凝縮させた約26 °Cの液体アンモニア。
  - 蒸発した割合が1の液体は、保冷タンクでも、入ったら同じ質量の気体にする。
- **このMODのタンク（`PlantFluidTankBlockEntity`）：**
  - 液体タンク・水タンク・ステンレス鋼タンク・保冷タンク・気体レシーバーは、外気と熱をやりとりしない `PhaseTank` だった。そのため、ステンレス鋼タンクが冷たい液体をいつまでも保ててしまっていた。
  - Createのタンクと同じ `PassiveTank` に替えた。保冷タンクは、既存の `insulated()` の判定で熱の出入りが0のまま。
  - この変更で、このMODのタンクでも、熱い・冷たい中身が外気の温度へ近づくようになった。

### 0 °Cを境にした理由

ユーザーの指示が「氷点下まで冷やした液体」だったことに合わせた。

もう一つの理由は、昼夜の気温差（±5 K）で、温かく保管している液化ガスが急に沸騰しないようにするためである。

実際の工場も、蒸気圧で保つ常温の液化ガス（加圧貯槽）と、沸点で保つ低温の液化ガス（保冷貯槽）を分けている。

## 影響と注意

- **既存ワールド：**
  - このMODのタンクに入っていた熱い・冷たい中身は、読み込み後に外気の温度へ近づく。
  - 0 °Cより冷たい液化ガスが普通のタンクにあると、沸騰して気体になり、圧力が上がる。
  - 保冷タンクに移しておけば、変わらない。
- **核融合炉の液体ヘリウム：**
  - 普通の配管を通すと、蒸発した割合が上がる。核融合炉は液体ヘリウムの量だけを見ているので、炉の動きは変わらない。
  - 普通のタンクでは、もともと外気が臨界点より暖かいため沸騰していたので、こちらも変わらない。
  - 原子炉関係のコードは変更していない。
- **転炉の液化酸素：** 普通の配管で運ぶと蒸発した割合が上がるが、質量は同じなので、酸素として数える量は変わらない。普通のタンクに貯めると、従来どおり気体になる。
