# 大型フライホイールの蓄勢と動力切替を検証

この報告で確認した蓄勢の頭打ちは `5424df5` で修正済み。再計測は[修正後の検証報告](large-flywheel-charge-fix-2026-11-25.md)を参照。

検証対象は `ea2a0ed`。Minecraft 1.21.1、NeoForge 21.1.219、Create 6.0.10の専用GameTestサーバーで、クリエイティブモーター、レッドストーンで作動するクラッチ、X軸に直結した大型フライホイール3台、シャフト、Createのエンケースドファンをつないだ。

検証後に取り込んだ `2af51ab` はフライホイールの外観とその生成元の変更。回転・蓄勢に関するJavaコードに差分はなかった。

## 実測

| 時点 | 蓄積エネルギー（3台合計） | ローター | 送風機 |
| --- | ---: | ---: | ---: |
| 駆動120 tick目 | 34,957.51 J | 4.81 RPM | 64 RPM |
| 駆動260 tick目 | 34,957.52 J | 4.81 RPM | 64 RPM |
| クラッチ切替の1 tick後 | 34,956.54 J | 4.81 RPM | 4.81 RPM |
| クラッチ切替の160 tick後 | 34,800.82 J | 4.80 RPM | 4.81 RPM |

- クラッチ切替後、モーターが別系統で64 RPMを維持している間、送風機はフライホイールの蓄積エネルギーで回り続けた。切替の1 tick後と160 tick後は過負荷なし。160 tick後の放出表示は5.63 Wだった。3台は同じ回転数と等しいエネルギー分担を保った。
- 実運転中のブロックエンティティを保存し、別インスタンスへ読み込むと蓄積エネルギーと回転数は一致した。
- 1.003 RPM相当の保存データを持つ1台に送風機を接続すると、出力を開始した。ローターが約0.9994 RPMまで減速すると、送風機は0 RPMになり、回転出力と応力容量も0になった。

## 蓄勢の不具合

モーターを64 RPMで回し続けても、120～260 tickの間に3台の蓄積エネルギーが約34.96 kJで頭打ちになった。実装の慣性モーメント91,943.49 kg·m²／台から計算すると、3台が64 RPMに達したときの目標は約6.19 MJ。

Createの `KineticNetwork.getActualCapacityOf` は、各動力源の容量をその動力源自身の回転数で換算する。一方、`LargeFlywheelBlockEntity.tickPhysics` は、フライホイール自身の寄与を軸全体の64 RPMで見積もって差し引く。実測ではネットワーク容量1,133,730.63 SUのうちフライホイールの実際の寄与は85,154.48 SUだったが、蓄勢側の差し引きは1,133,578.13 SUになった。モーターの寄与1,048,576 SUのほとんどが相殺され、表示された入力は14.03 Wまで落ちた。

## 検証範囲

Java 21で `check` と関連GameTest 16件が成功した。既存のモーター撤去後の軸出力、古い逆回転情報からの復旧、染色、保存値の検査、核融合炉の電動発電機への軸接続を含む。追加計測は蓄勢の頭打ちと、そこからの放出・停止を対象にした。クライアント描画、実ワールドのチャンク再読込、最大負荷での長時間運転は未確認。今回のコミットは検証記録。
