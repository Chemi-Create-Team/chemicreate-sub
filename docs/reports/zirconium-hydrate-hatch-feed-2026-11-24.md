# 撹拌槽のハッチから硫酸ジルコニウム溶液を投入する

実装コミットは `df17aae`。

配管側面からの硫酸ジルコニウム溶液500 mBは、修正前にも超加熱で硫酸ジルコニウム水和物になった。通常のバケツ操作は槽本体の貯蔵枠を調べていたため、その枠に異なる液体があると搬入に失敗した。旧実装はこのとき満杯のバケツを固体原料として収納し、流体原料が入らなかった。貯蔵枠に水1,000 mBが入った状態で、サバイバルの右クリック操作から再現した。

`LiddedVesselBlock` は、開いたハッチに液体容器を使ったとき、まず側面配管と同じ撹拌槽の原料ポートへNeoForgeの容器操作で液体を移す。原料ポートに入らない場合は既存の貯蔵操作を使う。どちらも移せないときは容器を手元に保持する。硫酸ジルコニウムのレシピは既存のままで、標準濃度の溶液500 mBあたり水和物1個と蒸気400 mBを生成する。仕様書とPonderの日英中の字幕にハッチの開閉と投入方法を反映した。 [操作とレシピ](../metals.md#精錬)

- 修正前の `ReactorGameTests` は27件中26件が通り、追加したハッチの回帰試験で満杯の溶液入りバケツが固体欄に入ることを確認した。
- 修正後の関連GameTestは87件すべて合格。水が残る槽でバケツが空の耐食バケツとして返り、ハッチの開閉、実際のCreateモーターと超加熱バーナーで水和物2個と蒸気800 mBが生成され、側面のアイテム出力から水和物を取り出せることを確認した。配管経由で以前のバッチの残りがある状態や、処理途中の保存・再開も通過した。
- Java 21で `check jar` が成功。全体GameTestは754件中753件が合格した。反応塔の `solidFeedFillsTheLowestTrayFirstAndKeepsCatalystsOut` は中心部を壊したときのドロップ検証で失敗した。直前の全体検証でも同じテストが失敗している。 [前回の検証](compact-rbmk-mirror-layout-2026-11-24.md)
- クライアントでのPonder再生は未実施。字幕は生成元と各言語の実行時リソースを照合した。
