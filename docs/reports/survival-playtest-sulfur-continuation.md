# サバイバル進行の続き ― 硫黄燃焼

Minecraft 1.21.1、NeoForge 21.1.219、Create 6.0.10。試験開始時の `main` は `ece8dd21`。確認ワールドの実装コミットは `4b390a74`。[初回の試験](survival-playtest.md)と[硫黄粉の修正](netherrack-sulfur-yield.md)に続き、同じ進行の新規フラットワールドで試験した。

## 判定

| 段階 | 判定 | 実機で確認した範囲 |
| --- | --- | --- |
| A　鋼鉄からステンレス鋼板 | 合格 | 鋼鉄3バッチとステンレス鋼4バッチ。板40枚のうち36枚をふた付き槽の9ブロックに使用。 |
| B　硫黄粉の回収と槽の組立 | 合格 | ネザーラックを8個ずつ破砕し、硫黄粉を回収。作業台で槽と撹拌翼を作り、水車で撹拌翼を駆動。 |
| B　開放口からの吸気 | 合格 | 水車で回す気体ポンプで燃焼1回分の空気を吸引。 |
| B　硫黄の連続燃焼 | 不合格 | 2回燃焼し、3回目は硫黄粉と空気が残った状態で停止。 |
| B　希硫酸・浸出・電解、C　その先 | 未実行 | 今回は硫黄燃焼槽で運転を止めた。 |

## 守ることの確認

1. ネザーラックは破砕ホイールからデポとホッパーを通ってチェストに入る。作業台に使う素材と、硫黄粉3個の取り出しはチェストの通常スロットを操作した。硫黄粉は実際に持った物をプレイヤーのドロップ操作で1個ずつ投入口のホッパーへ落とした。槽はホッパーと気体配管から受け取る。各装置のタンクと在庫は計測のみ行った。
2. 水車とCreateの歯車で駆動し、加熱には石炭、超加熱には同じワールドで製造したブレイズケーキを用いた。硫黄燃焼の燃料は石炭ブロック1個。発電工程とクリエイティブ動力は使用していない。
3. 鉄の原石、鉱石、石炭、安山岩、ネザーラック、卵、砂糖、水源、溶岩源を原料として投入した。燃焼用の石炭ブロックも原料の石炭9個から作業台で製作した。槽・撹拌翼と各材料は同ワールドで製造し、水車やホッパーなど既存設備はその時点で製造可能な構成を配置した。材料量は下記の表に記録した。
4. 段階Aで作った板を、回収チェストと作業台を経て段階Bの槽に使用した。段階Bで回収した硫黄粉を同じワールドの燃焼槽へ投入した。燃焼槽の生成物を希硫酸槽へ送る工程は未実行。
5. 鋼鉄3バッチ、ステンレス鋼4バッチ、ネザーラック破砕を少なくとも3バッチ運転した。硫黄燃焼は3回投入し、2回完了。3回目の不合格は下記のとおり。

## 実測

合金の計測は合金工程の開始から数え、破砕・吸気・燃焼は各工程の投入または計測開始から数えた。クライアントと専用サーバーに同じ装置を配置した。クライアントは吸気開始時にtick sprintを終了し、最後まで通常の20 tick/sで運転した。

## 停止の再現と観察

1. ふた付き槽を3×3で置き、ふたを閉めた状態で撹拌翼を回転させる。槽のコントローラーは `(64, -44, 34)`、中央の動力入力は `(65, -44, 35)`。バーナーは `(66, -45, 34)`。
2. `(65, -44, 31)` の気体ポンプを吸気側の配管へつなぎ、北端の前 `(65, -44, 28)` を空ける。上面の生成ガス出口は未接続の状態で試験する。
3. 空気2,400 mBをため、硫黄粉を西のホッパー `(63, -44, 34)` に1個ずつ投入する。1回分の生成物が増えた直後に次を投入する。3回目の投入から1,800 tickまで観察する。

停止時の槽に空気7,600 mB、硫黄粉1個が残り、撹拌翼は32 RPM、バーナーは通常加熱のままだった。内部の停止理由は `materials`。日本語の翻訳は「原料・触媒・生成物バッファの空きを確認してください」。二酸化硫黄1,000 mBと窒素3,800 mBを確認した。

| 槽の枠 | 内容 | mB | 温度等級 |
| ---: | --- | ---: | --- |
| 0 | 空気 | 7,600 | 常温 |
| 2 | 二酸化硫黄 | 500 | 超高温 |
| 3 | 窒素 | 1,900 | 超高温 |
| 4 | 二酸化硫黄 | 500 | 超高温 |
| 5 | 窒素 | 1,900 | 超高温 |

バーナーは出力枠のガスも加熱する。`ReactorMachineBlockEntity.runBatch` は既存の出力と次の生成物について、温度成分も含む完全一致を要求する。1回目と2回目の生成ガスが別々の枠に入り、停止時の生成枠2～6には空きが1枠しかなかった。3回目の常温の生成物2種は格納できず、硫黄粉も消費されなかった。設備の配管は吸気まで確認済みで、生成ガスの搬出先は置いていない。

次に試す構成は、槽の上面から生成ガスを耐食管で別の設備へ搬出する経路。加熱で温度が変わった同種ガスが別の枠を使う場合、停止理由を「出力先が満杯」として表示すると、原料不足と区別しやすい。今回のコミットは試験コードと記録のみ。

## 画面での確認と未実施事項

画面確認は同じ試験ワールドの `runClient`、通常の20 tick/s、NVIDIA GeForce RTX 4060で実施した。撮影と保存まで吸気が続いたため、保存ファイルの空気は14,860 mB。硫黄粉1個、二酸化硫黄1,000 mB、窒素3,800 mBと停止理由は計測の終了時と一致した。[硫黄燃焼槽の配置](../quality/survival-playtest/sulfur-continuation-vessel.jpg)、[停止後の槽の読み取り](../quality/survival-playtest/sulfur-continuation-stall.jpg)

ゴーグル、JEI、Ponder、説明書、実績の実画面は今回未再検証。二酸化硫黄の搬出配管、希硫酸の製造とセラミック管の搬送、CEEの電解セル、浸出と沈殿池での鉄・銅回収、吸収塔、接触法は未実施。通常ワールドの鉱石の探索・採掘時間も未計測。

## 再現

[起動設定](../quality/survival-playtest/progression-client.gradle)と[確認ワールド](../../src/main/java/net/createplant/client/SurvivalProgressionWorld.java)を使用する。配布ZIPの `survival-sulfur-continuation` を `saves` に置くと同じサバイバルワールドを開ける。

```sh
mc-debug bash gradlew --no-daemon -I docs/quality/survival-playtest/progression-client.gradle \
  -DsurvivalSprint=40000 runClient
```

`SurvivalProgressionGameTests` は専用サーバーでも同じ工程を実行する。吸気722 tick、燃焼109 tickと591 tick、3回目投入から1,800 tickでの停止を再現し、停止の理由と出力枠をログに残した。Gradleの `build` は成功した。関連GameTest 17件は13件合格で、失敗は仕様書に記載済みの4件だった。
