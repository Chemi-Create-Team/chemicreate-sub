## A. 等級化の後始末

  - ガスホルダーの、届かない`pressure`の分岐も削除した。

  - 計器の読み値（原子炉の燃料温度、黒鉛温度、ゴーグルの℃表示など）は、方針どおり残した。
- **A5 スクラバー：** 表示名を「排ガススクラバー」（英語はGas Scrubber）にし、状態表示とクラスのコメントを「下面から配管で酸性ガスを送る」役割に合わせた。登録IDとクラス名は変えていない。
  - `ToxicGas`のコメントからも、削除済みの安全弁と破裂の記述を外した。
- **A6 減圧弁：** 出口が何も受け取らなければ待機し、どちらかの口で搬入・搬出があったら再開するようにした。周囲と同じ書き方に直した。
  - GameTest `reducingValveWaitsWhileItsOutletIsFullAndResumesWhenDrained`を追加した。
- **生成スクリプトの修理：** `tools/generate_plant_systems.py`は、Codexの変更で`generate_fusion_assets.body_role`がなくなったため、途中で失敗していた。

## B. 遊ぶ目的

### B1 鉱石の収率（指示書から変えた点あり）

- **金属を取り出す設備：** 電解セルは気体を作るだけの専用処理で、インゴットを出す経路がない。そのため、撹拌槽で水素還元（実在する加圧水素還元法）する方式にした。
- **2段目：** パルス式溶媒抽出塔は使わず、酸素を使う加圧浸出（超加熱）にした。抽出塔は液体だけのレシピで、収率を上げる工程として自然な形にならないため。
- **新しい液体（4種）：** 硫酸鉄、硫酸銅、硫酸亜鉛、塩化金の溶液。`CEMetals`に登録した。腐食性の液体として`FluidHazards`に登録したので、耐食合金のバケツと設置できる液体は既存の仕組みで作られる。
- **レシピ**（`tools/generate_metal_ores.py`、`pressure_reaction/`、溶液100 mBが塊1個分）：

| 工程 | 入力 | 出力 | 熱 |
| --- | --- | --- | --- |
| 浸出 | 粉砕済み鉱石1、硫酸250 mB（金は塩酸250 mBと次亜塩素酸ナトリウム溶液100 mB） | 溶液1,300 mB（塊13個分） | 加熱 |
| 加圧浸出 | 粉砕済み鉱石2、酸2倍、酸素500 mB | 溶液3,600 mB（1個あたり塊18個分）。銅は金塊1個も出る | 超加熱 |
| 還元 | 溶液900 mB、水素450 mB | インゴット1、洗浄排水450 mB | 加熱 |

- **収率の比較：** Create 6.0.10の粉砕では、粗鉱1個から粉砕済み鉱石1個（洗浄で塊9個）になる。粉砕済み鉱石1個あたりでは、Createの1倍、浸出1.44倍、加圧浸出2倍。
  - 鉱石ブロックをシルクタッチで掘って粉砕した場合（粉砕済み鉱石1.75個）、鉱石1個あたり1.75 → 約2.5 → 3.5インゴット。指示書の目安と一致する。
- **酸の扱い：** 酸は還元で戻らないので、酸が無限に増える循環は起きない。
- **撹拌槽のレシピ選び：** 撹拌槽は、反応レシピを読み込み順に試していた。そのため、加圧浸出の材料をそろえても、材料が部分的に重なる浸出が2回動いていた。
  - 反応レシピを、材料の多い順に試すようにした（Createの鉢と、この槽のミキサー用レシピと同じ並べ方）。
  - 同じ並べ方で、「水の予熱」（水だけを使う）が他の水を使うレシピより先に選ばれることもなくなる。
  - 材料が完全に含まれる組み合わせは、浸出の4組と水の予熱だけであることを確認した。
- **Ponder：** 「鉱石を浸出して金属を増やす」を新しく作った（製造工程Ponderの形式。4種の溶液のバケツから開く）。
- **対象外：** 他MODの鉱石。Createの4種（鉄・銅・亜鉛・金）だけに対応した。

### B2 回転力（計算のみ。数値は変えていない）

コードの定数から計算した値。ゲーム内で設備全体を組んだ計測はしていない。1 SUは1 Wとして扱われる（`TurbineFacility.totalSU`）。

| 発電 | 回転力の目安 |
| --- | --- |
| Createの蒸気エンジン | 熱1段階あたり16,384 SU。超加熱のバーナーは2段階なので32,768 SU。最大はボイラー1基で294,912 SU（Createの公開値で、このMODでは計測していない） |
| 管束ボイラー＋タービン、加熱のバーナー1台 | 4,000 J/tick → 高圧蒸気1.6 mB/t → 高圧段500 J＋低圧段250 J → 約24,000 SU（Createの約1.5倍） |
| 管束ボイラー＋タービン、超加熱のバーナー1台 | 8,000 J/tick → 過熱蒸気2.66 mB/t → 1,250 J/mB → 約66,500 SU（Createの約2倍） |
| RBMK（765 MW） | 蒸気約11,200 mB/t → 低圧段だけでも約56,000,000 SU |
| 核融合（定格500 MW） | 熱出力でRBMKより小さい。発電までの全体の運転は未確認 |

- タービンの段階は、指示書の目安（前段の3〜4倍）に届かず、2倍程度。ただし、1 mBあたりの仕事は実際の蒸気のエンタルピーから決めているので、変えなかった。
- 原子力は、Createの工場の需要（数十万SU程度）をけた違いに上回る。回転力を目的にした段階分けは、タービンの段階でほぼ満たされる。原子力より先の目的は、回転力以外（B5など）に置く必要がある。

### B3 範囲肥料

- 肥料のアイテム（`item/FertilizerItem`）はすでにあった。硝酸アンモニウムは骨粉2個分、硫酸アンモニウムは1個分。
- これを、使った作物と、その周囲3×3の作物（`minecraft:crops`タグ）に効くようにした。周囲の草ブロックなどには広がらない。
- 1回あたりの強さは、既存の値を残した。指示書の「骨粉と同じ」とは違い、硝酸アンモニウムは1作物あたり骨粉2個分になる。
- GameTestを2件追加した。手で使うと9株が育ってアイテムが1個減ること、Createのデプロイヤーでも9株が育つこと。
- Ponder「アンモニアから硝酸と肥料を作る」の最後の手順に、使い方を1ページ足した。

### B4 燃料（調査）

- 追加の実装は不要だった。このMODの低硫黄軽油は`c:diesel`タグに入っている。
- 必須依存のCreate Diesel Generatorsは、燃料をタグで判定している（`fuel_type/diesel.json`の`"fluid": "#c:diesel"`）。そのため、ディーゼルエンジン（6,144〜16,384の強さ）とブレイズバーナー（`burner_multiplier`）でそのまま使える。
- 説明書の回転力の章に、そのことを1行足した。

### B5 最終目標（見積もりのみ。ユーザーの決定待ち）

- 増殖ブランケットのカートリッジは耐久24,000。定格出力では1秒に1減る（`blanketDamageDue += fusionWatts / RATED / 20`）ので、約6.7時間でなくなる。
- 案：照射カートリッジ（材料は金とチタン）を、増殖ブランケットの代わりに入れる。消耗の速さは同じにし、使い切るとネザライトの欠片8個（インゴット2個分）。
- 照射カートリッジを入れている間は三重水素を増殖しないので、燃料を事前にためておく必要がある。これが運転の駆け引きになる。
- ブランケットの差し替えはクレーンの核融合保守モード（`CraneDriveBlockEntity`、原子炉担当のクラス）が扱う。そのため、実装には担当者との調整が必要。

### B6 説明書と実績

- 説明書（`tools/generate_manual.py`）を22ページにした。章は目的の順：調べ方、最初に、鉱石から金属を増やす、回転力を増やす、農業、発破、出荷、よい素材、等級と配管、止まったとき。
- 目的の章は、最初の1文で得られるものを書いた。全ページが本の大きさに収まることを、生成時に確認している。
- 実績を18個にした。目的の実績（出荷、金属が増える、回転力が増える、燃料棒、農業、発破）は`goal`の枠、核融合炉の磁石給電盤は`challenge`の枠。
- 「金属が増える」は流体の工程なので、浸出液を耐食合金バケツに汲んだときに達成する。
- `docs/manual.md`と`ManualGameTests`を更新した。

## 残った問題（未対応）

- **生成スクリプトと実ファイルのずれ：** 次のスクリプトは、実行すると削除済みの翻訳キー（温度表示、圧力計の表示など）を戻したり、Ponderの構造やテクスチャを古い内容で書き換えたりする。
  - `generate_plant_systems.py`、`generate_crane_assets.py`、`generate_lidded_vessel_ponder.py`、`generate_industrial_expansion.py`、`generate_fusion_fuel.py`、`generate_world_liquids.py`、`generate_manufacturing_ponder.py`（硝酸の系列の構造）
  - この作業では、自分が変えたキー以外の差分を元に戻してからコミットした。ただし、スクリプトそのものは古いままである。正本を整理する作業が別に必要。
- **汚れのテスト**（`aFouledProcessStopsThenResumesAfterOneManualBrush`）：止めたあとにモーターを置き直しても、槽の回転数が0のまま（状態は「回転不足」、塊・水とも未消費）。
  - 回転数を設定するのを設置の5 tick後にずらしても変わらなかった。そのため、テストの順番の問題ではなく、受け軸に回転が戻らない実装側の問題の可能性がある。原因は特定していない。
- **RBMKの冷態起動の行き過ぎ（207%）：** 原子炉担当のコードのため、触っていない。
- **核融合プラントの全体運転：** 自力で回る構成での通しの運転は、まだ確認していない。
- **ゴーグルの表示の直書き：** `TurbineFacility`のゴーグル表示に、日本語の文言がJavaに直書きされている（翻訳キーの規約違反）。範囲外なので報告のみ。
- **ヘリウムのバケツ名：** 液体ヘリウムのバケツ名（英語）は、生成スクリプトごとに「Bucket of Liquid Helium」と「Liquid Helium Bucket」が食い違っている。今は前者のまま。
