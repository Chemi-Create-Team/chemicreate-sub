# 往復式コンプレッサー（ChatGPT引き継ぎ用）

## 実装内容

Createの蒸気エンジンと同じ形・同じ動きで、白と濃灰の配色にした駆動部を、新規の専用シリンダーに取り付ける往復式コンプレッサーを追加した。蒸気エンジンとしての機能（ボイラー・発電）は持たない。回転を受けると、シリンダー内のガスを圧縮して高温・高圧にする。

| ブロック | ID | 役割 |
| --- | --- | --- |
| 往復式シリンダー | `reciprocating_cylinder` | 吸入室1,000と吐出室250の2室を持つ気体の容器。上面が吸入（充填のみ）、下面が吐出（排出のみ）、側面にポートは無い |
| 往復式コンプレッサー | `reciprocating_compressor` | シリンダーの面に取り付ける駆動部。Createの蒸気エンジンと同じ取付規則（床・壁・天井）とモデル |
| 駆動シャフト | `reciprocating_drive_shaft` | 入手不可。クランク先のCreateシャフトを置き換え、負荷をCreateの回転網へ伝える。エンジンが無くなるとCreateのシャフトへ戻る |

## 主要ファイル

- 登録：`registry/CEReciprocating.java`
- ブロック：`block/ReciprocatingCylinderBlock`、`ReciprocatingCompressorBlock`、`ReciprocatingShaftBlock`
- 動作：`block/entity/ReciprocatingCylinderBlockEntity`（気体室、安全、ポート）、`ReciprocatingCompressorBlockEntity`（圧縮の実行、圧力設定）、`ReciprocatingShaftBlockEntity`（回転網への負荷）
- 描画：`client/ReciprocatingCompressorRenderer.java`（ピストン・ロッド・クランクを、シャフトの実角度に合わせて動かす）
- 資産生成：`tools/generate_reciprocating_compressor.py`。Createの`engine.png`と`cam_linkage.png`を白・濃灰へ再着色し、モデルはCreateの蒸気エンジンのモデルを親にしてテクスチャだけ差し替える
- 圧力連携：`GasCompressorBlockEntity.boundaryPressure`と`PressureSections.pressureAfter`にシリンダーの吸入・吐出の面別圧力を追加

## 使い方

1. 往復式シリンダーを置き、その側面（床・壁・天井の取付は蒸気エンジンと同じ。上面に付けると吸入口を塞ぐ）に往復式コンプレッサーを置く。蒸気エンジンと同じ向きの決まりで、シリンダーが無い面には置けない。
2. エンジンから取付方向へ2ブロック先に、Createのシャフトを置く。シャフトの向きは、エンジンのFACINGに直交する軸でなければならない。置くと1秒以内に駆動シャフトへ置き換わる。
3. シャフトへ回転を与える。シリンダーの上面から気体を入れ、下面から圧縮したガスを取り出す。
4. 目標圧力は、エンジンへのCreateレンチ長押しで設定する（0.1〜100 bar、初期8 bar）。設定値だけで圧力は生成されない。

## 計算方法

既存の小型・大型コンプレッサーと同じ `GasCompression.compress` を使う。同じ流体IDを保ち、移すmB数も保存する。

```text
k = min(0.4, (R / molar_mass) / cp)
DeltaT = Tin × ((Pout / Pin)^k - 1) / efficiency
W = m × cp × DeltaT   （軸仕事は熱として吐出ガスに蓄える）
```

| 項目 | 値 |
| --- | --- |
| 効率 | 0.68（小型0.55、大型0.74） |
| 1tickの移動量上限 | 0.125 × RPM mB（小型0.0625） |
| 使える軸仕事の上限 | 24 × RPM W（小型8） |
| 吸入室・吐出室 | 1,000・250（吐出室が小さいので、同じ量でも圧力が上がる） |
| 最高使用圧力 | 100 bar（シリンダーの圧力容器動作、超過で歪み・破裂） |
| 最高使用温度 | 1200 K（既存の`EquipmentSafety`。超過で損傷） |
| 最低回転数 | 16 RPM |

Createの消費応力は計画仕事Wを`W × 20 / |RPM|`としてシャフトに載せる。1段の圧力比が大きいと吐出ガスが1200 Kを超えて停止するため、実際の高圧化は中間冷却器を挟む多段にする。

## テスト結果

- GameTest：`ReciprocatingCompressorGameTests` 5件を追加し、全体305件が成功（`./gradlew runGameTestServer`）。
  - エンジンはシリンダー上にだけ立つこと、シャフトを引き継ぎ、エンジン撤去でCreateのシャフトへ戻ること
  - 軸の向きが違うシャフトは引き継がないこと
  - シリンダーの面別ポート（上面が吸入、下面が吐出、側面は無し）、SIMULATEで内容物が変わらないこと
  - Createのクリエイティブモーターでシャフトを回すと、吐出が高温・高圧になり、mBが保存され、シャフトに負荷がかかること
  - 回転が無ければ圧縮も負荷も無いこと
- 実クライアント（`-Dcreateplant.reciprocatingClientCheck=true`）：床取付と壁取付の2台が白・濃灰で描画され、ピストン・ロッド・クランクがシャフトの回転に合わせて動くことをスクリーンショットで確認した。

## 計算の見直し（2026-10-29）

- 1段で絞れる圧力比を最大6倍に制限した。圧力比が大きいと吐出ガスが1,000 K超まで加熱され、すぐ停止したため。それ以上の圧力は、シリンダーをつないだ多段圧縮にする。
- 圧縮後の温度は、目標圧力ではなく、吐出室に入った結果の圧力で決める（ほぼ空の吐出室を、目標圧力で圧縮したように加熱していた）。1回の量は、吐出室が上限を超えない量まで半分にして調整する。
- 往復式シリンダー以外でも、Create式タンク系（`PhaseTank`）は、気体を入れるとき、タンク自身の定格圧力を超える量を受け付けないようにした（従来は256倍まで受けてから破裂していた）。

- 往復式シリンダーは、吸入室の圧力が定格（100 bar）を超える量の気体を受け付けない。
- 本MODのタンク（液体・水・ガスレシーバー・断熱）に耐温を追加した。内容物がそれを超えて保持されると、設備の安全処理（`EquipmentSafety`）と同じく、損傷が段階的に進み、部分破損を経て破裂する。耐温は、液体タンク623 K、水タンク473 K、ガスレシーバー773 K、断熱タンク1,000 K。

## 未検証・制約

- 向かい合わせのエンジンは、シャフト自身の回転方向に合わせてクランクが回るよう描画を補正した（コミット後に実機確認）。

- Ponderは追加していない。ゴーグル表示は文言のみで、ゲーム内で読みやすさを確認していない。
- 天井取付と、他のCreate機器（歯車箱・クラッチ等）を挟んだ長い回転網での挙動は未確認。
- シャフトは置き換えが最大1秒遅れる（クランク先は2ブロック離れ、近傍更新が届かないため定期確認で拾う）。
- 1つのシリンダーに複数のエンジンを付けると、同じ吸入室と吐出室を並列で使う。
- ゴーグルの圧力表示とJEI等の外部表示への対応は、シリンダーとエンジンで固有の2行だけ。
- 中間冷却器と脈動抑制槽は既存の合成ガス専用の段間設備のままで、このシリンダーとの段間連携は専用に作っていない。

## 次回の注意

- 駆動シャフトは負荷のためだけの置き換えブロックで、Createの更新でシャフトの状態や`AbstractShaftBlock`が変わると影響する。
