# クァーリーの鉱石回収数の調査

調査・テスト追加コミット: `f4da2163c75b5c26bfef41266beac89872e4c75d`

## 結果

今回の条件では、クァーリー内部で鉱石の個数が減る不具合は再現しなかった。採掘や搬送の本体ロジックは変更せず、回収数を検証するGameTestを2件追加し、回収先の説明を補足した。ユーザーの実際の配置で消失が起きていないと断定する結果ではない。

| 確認 | 条件 | 結果 |
| --- | --- | --- |
| 採掘から外側ベルト終端への搬出 | 5×3、2層に鉱石24ブロック、256 RPM、8作業ステップ/tick | 24個を回収、12種類すべて期待数と一致、対象鉱石の搬送残量0 |
| 搬出待ちの在庫保存・読込 | 鉄の原石320個＋金の原石256個、上昇路120・橋32、400内部tick搬出拒否、NBTを別の搬送インスタンスへ読込 | 読込前後の種類別個数が一致 |
| 読込後の部分搬出 | 上記576個を1回最大7個ずつ搬出 | 576個を回収、残量0、種類別個数も一致 |
| 既存の関連試験 | 建設資材、枠建設時の採掘、搬送満杯、回転方向、土15個の実搬出など | 追加2件を含む9件すべて成功 |

実採掘の鉱石は、バニラの鉄・金・ダイヤモンド・エメラルド・石炭、および本MODのボーキサイト・ペントランド鉱・チタン鉄鉱・ジルコン・クロム鉄鉱・輝水鉛鉱・ウラン鉱石。それぞれ通常版と深層岩版を1個ずつ使用した。確定個数を比較するため、ドロップ数がランダムな銅・ラピスラズリ・レッドストーン・岩塩はこの実搬出試験に含めていない。

## コードから分かった回収経路

- `QuarryDriveBlockEntity.dig` は、幸運・シルクタッチのない鉄のツルハシでドロップを計算し、全量が入ることを確認してから採掘する。通常採掘はドリルヘッドの在庫へ、枠やベルトの建設時の除去は駆動部の在庫へ入る。建設時の分は駆動部からファンネル等で回収する。
- `QuarryConveyor` は搬出先が受け取らなかった残りを保持する。満杯によって直ちにアイテムを捨てる処理は確認できなかった。
- 外側のベルトは標準のCreateベルトで、収納されない荷物は終端からアイテムエンティティとして放出される。地面に放置すれば通常のアイテム消滅が起きる。Minecraft/NeoForgeの既定寿命は6,000 tick、通常の20 TPSで約5分。終端の落下先へシュート・ホッパー等の回収路が必要になる。
- 原石として出る鉱石は、鉱石ブロックそのものではなく原石を数える必要がある。幸運付きツルハシの回収量とも一致しない。

最初の実搬出試験では、終端のすぐ先に通常チェストだけを置いて回収を期待したが、収納されず試験が失敗した。回収が成立しない配置だったため、鉱石消失の再現とは扱っていない。既存の搬出試験と同様に終端から放出されたアイテムを数える形へ修正し、24個の全数回収を確認した。

## 未確認事項と次の調査

- ユーザーの実ワールド、鉱石の種類、設置寸法、搬出先、消失に気付いたタイミングは未確認。
- 32～64マスの分割ベルトをまたぐ実搬送、複数チャンクにまたがる荷物、チャンクのアンロードを伴う実ワールド再読込、サーバー異常終了は今回再現していない。保存試験は搬送在庫のNBT往復であり、ワールド全体の再読込ではない。
- 他MODによるドロップ変更、幸運付き採掘との比較、長時間放置時の地面のアイテム消滅は実測していない。
- 再現配置が分かったら、掘削前のブロック数、駆動部在庫、ヘッド在庫、内部搬送、各外側ベルト、地面、収納先の種類別個数を合算し、どの区間で差が出るか追う。
