# クァーリーのチャンク読み込み・残り時間・隣接枠の検出

2026-11-17（JST）。実装コミットは `842036eb550de5edcbb9cb82bf97a0cefc4ddc92`。

## 動作

- `QuarryChunkLoader` は稼働信号がある間、駆動部・掘削範囲・側面ベルト・出口を含む範囲に NeoForge の ticking ticket を発行する。最大設定では直接のチケットは36チャンク以下。未ロードチャンクへの追加は駆動部ごとに1tickあたり1件に抑える。
- チケットの所有者はワールド内の駆動部の座標。再起動時は駆動部の有無と現在の設定範囲を確認して復元する。採掘後は内部の荷物と側面ベルトが空になるまで保持する。完了・信号停止・駆動部の撤去で解放する。
- `QuarryDriveBlockEntity` は40稼働tick以上のサンプルから通過区画数のレートを測り、残り区画数をそのレートで割る。2回目以降は前回75%、新サンプル25%でならす。秒数への換算は設定tick時間と平均処理時間の大きい方を使う。ゴーグルの通常表示に採掘の残り時間を出し、Shift時は高さと在庫を表示する。
- `CraneStructure.scanConfigured` は設定方向の2本のレール、端の長さと4隅の支持を確認する。隣接枠が先に候補になる問題を防ぐ。通常の門型クレーンは従来の自動検出を使う。
- エリアや地層で予想時間は変動する。完了は採掘後の搬出も含むため、動力・回収先の状態は引き続き稼働条件になる。旧セーブの搬送品・採掘位置は既存の形式で読み込む。

起動時の側面ベルトの回転方向は駆動部の設定方向から計算する。保存した構造を再検証するまでの間にも同じ方向へ回転を伝え、Create が逆向きの回転の衝突としてベルトを外す状態を防ぐ。

## 検証

Java 21、Minecraft 1.21.1、NeoForge 21.1.219、Create 6.0.10。

- Gradleの専用サーバーで `createplant.gameTestClasses=QuarryGameTests,QuarrySpeedGameTests` を指定。プレイヤー不在で64×64の遠端がtickすること、信号停止・再開・撤去・搬出完了時のチケット、ゴーグルの4行と残り時間、左右の枠と反転配置、枠の欠け・長さ・脚の検出を確認。
- 実際に専用サーバーを終了して再起動した隔離ワールドでも、クァーリーのチケットだけで採掘が進んだ。採掘位置は `Layer=-53` の `Cell=2` から `Cell=3` に進み、信号停止後の保存にクァーリーのチケットは残らなかった。
- 既存の45ブロックの速度試験、24個の鉱石回収、11,683便の保存・搬出、Ponderの言語とチュートリアル検証を実施。
- 稼働環境のNeoForge 21.1.259についてはチケットAPIのシグネチャを確認。本番ワールドへの適用、実機での残り時間の精度、多数台同時運転時の負荷は未計測。上流の素材分類チェックには既知の未分類項目がある。 [上流の検証記録](gas-liquid-separator-drum.md)
