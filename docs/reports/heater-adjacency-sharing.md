# 隣接する電熱線ヒーターの給電・設定共有

2026-11-13。実装コミット：`e2ce7c368421471ed78ac4e68f621f09b6d46be0`。

## 実装

同じ高さで辺が接するヒーターの同じ番号の端子を、EEの内部抵抗配線（片側0.001 Ω）で接続する。1台の端子2本へ給電すれば、隣接する全台へ電気が届く。各台は従来の可変抵抗による並列負荷であり、供給電力を複製しない。斜めだけの接触・上下方向では共有しない。1×2、2×2、2×3、3×3の外周8台と全面9台に対応する。

どのダイヤルを操作しても、ロード済みの連結部分すべてへ同じ0～100％の設定を適用する。0.1％刻み・Shift中1％刻みを維持した。設定値と蓄熱は引き続き各台に保存する。熱の受け渡し上限、直上の加熱対象、レッドストーン停止、入力表示は各台で計算する。停止した台の内部配線は隣への通電を妨げない。

新設・ロード時に設定を合わせる。すでに動作している台の設定を優先し、複数候補があれば座標順（Z、X）で選ぶ。切断後は各部分が最後の設定を保持する。電気の接続判定は各台で東・南の2隣接だけを調べ、同じ接続を二重に登録しない。毎tickの全体探索は行わない。設定の全体探索は操作時と接続への加入時のみで、上限4,096台。上限超過時は部分適用せず設定変更を拒否する。未ロードのチャンクは読み込まない。

400 V・100％で9台なら理想合計36 kW。電源・外部電線の容量、電圧降下、焼損の既存仕様を維持するため、単独ヒーターより太い配線や十分な電源が必要になる。ゴーグルの入力電力はその1台分。

主な変更：

- `block/entity/ElectricHeaterBlockEntity.java`：設定の共有、追加・ロード時の設定統一。
- `compat/electro/ElectricUtilityDevice.java`：ヒーターだけの内部2極配線。ポンプには追加しない。
- `ponder/ElectricUtilityPonderScenes.java`、`tools/generate_electric_utilities.py`：2台の隣接・1か所の給電・共有設定を示すPonderと日英中の短い説明。
- `gametest/HeaterGroupGameTests.java`：以下の最小限の2試験。
- `docs/electric-utilities.md`、`DESIGN.md`：操作と給電の条件。

## 未確認と次回の注意

- 実プレイでの描画、Ponder表示、マルチプレイ、チャンク境界での保存・再読込、長時間運転、大量設置の性能は未確認。既存の単独ヒーター51件の試験群は今回再実行していない。
- 電気の実配線試験は3×3の9台。その他4配置では設定共有を確認した。9台の400 V運転や外部配線の耐久は今回の試験条件ではない。
- 蓄熱を共有在庫へ移す処理は追加していない。各ヒーター直上への熱は、その台に供給された実電力と有限の蓄熱だけから支払う。
- 内部抵抗配線の追加はEE 1.21.1-1.1.4の実JARの`BridgeCollector.Builder.resistor(Node, Node, double)`を確認して実装した。端子0同士・1同士を接続し、給電経路を二重登録しないこと。
