# 配管コンフィギュレーター

実装コミットは `073ad871fa85942fd8613764b729049fc835f833`。Minecraft 1.21.1、NeoForge 21.1.219、Create 6.0.10（Modrinth UjX6dr61、Createコミット `ac0c444d`）で確認した。

## 操作と対象

- 真鍮板3枚、流体パイプ1本、安山岩合金1個から作る。手に持ち、2本の管の間に伸びる継手を狙って右クリックする。その接続だけが切れる。オレンジの切断跡に照準を戻すと、右クリックで再接続できる。
- Createの銅管、軸の合うガラス管、および登録された本Modの同型材質管を操作できる。被覆管は隣の露出アームから操作する。全面を覆う大型ガス管など、露出したアームを持たない面は直接選択しない。ポンプ、バルブ、装置ポートは通常の動作を使う。
- 再接続の表示と操作音を用意した。日本語、英語、簡体字中国語に対応し、アイテムとCreate標準の流体パイプからPonderで操作を確認できる。

## Createとの連携

- 解決済みアーティファクトを調べた。銅管は `FluidPipeBlock.updateBlockState` が `canConnectTo` で方向を判定してから、片側・孤立時の形状を補完する。`PipeAttachmentModel` は中央とアームを各方向の形状・輸送Behaviourから描画する。標準のブロックRaycastはブロック全体の選択結果を返すため、狙ったアームの立体と視線を個別に交差判定した。
- `transport/PipeArm.java` はプレイヤーの射程内で、通常のブロックに遮られるより手前のアームを探す。`item/PipeConfiguratorItem.java` はクライアントとサーバーで同じ判定を行い、サーバーで両端を検証して切り替える。切断跡の位置は通常の選択形状が空でも同じ操作ができる。
- `transport/PipeConnections.java` は辺の負側の座標と軸を1件だけディメンションの `SavedData` に保存する。配置方向から同じ辺を引けるので両端で設定が分かれない。チャンクに入る配管データに6面の状態を添え、変更時は両端を同期する。切断設定はワールド上の継手位置に属し、同じ場所に管を置き直しても残る。
- Createに永続的な方向別拒否の公開APIは見つからなかった。標準パイプの自動接続判定・補完処理と標準／ガラスの流体Behaviourに限定してMixinを適用し、切断面を拒否する。閉じた面から空気や水へ放出しない。操作時は両端の状態を更新してからCreateの `FluidPropagator.propagateChangedPipe` を双方から呼び、既存ポンプと経路の再構築を使う。ワールドやネットワークを毎tick探索しない。
- ガラス管の切断側はモデルと形状を短縮する。全方向を閉じた銅管にもCreateの中央部が残る。手持ちのときはCatnipのアウトライナーで対象を示す。レシピと16×16ピクセルのアイコンを同梱し、`tools/generate_pipe_configurator_assets.py` からPonder構造とアイコンを再生成できる。

## 検証

- Gradle `build` と専用サーバーの関連51件が成功した。新規テストはアームと管本体の判別、遮蔽、隣接更新・管交換後の保持、銅管とガラス管の切断・両端の輸送インターフェース、稼働中のポンプ・別分岐・再接続、被覆後の形状と再接続を確認する。
- RTX 4060の日本語クライアントで通常の右クリック操作を実行し、金色の対象枠、銅管とガラス管の間の隙間、オレンジの再接続枠を確認した。
- 配管をX=-1とX=0のチャンク境界に作り、切断して保存し、別のクライアント起動で同じワールドへ入った。ディスクから切断設定が復元され、両端のサーバー流路とクライアントの目印が一致した。境界の両チャンクのアンロードイベントを確認して戻り、切断跡を通常の右クリックで再接続できた。
- Ponder言語、翻訳、チュートリアルの静的検証が成功した。クライアント環境ではOpenALデバイスが開かなかったため、操作音の実聴は未確認。
- ポンプの分岐試験では初回操作前に既存経路で供給量と受取量に差が出た。切断直前の在庫を基準に、切断中と再接続操作時に増減がないことを検証した。無操作時の既存分岐の挙動は別件。
- 配布JARはZIPの圧縮だけを変え、標準ビルドと全エントリーの内容が一致することを確認した。
