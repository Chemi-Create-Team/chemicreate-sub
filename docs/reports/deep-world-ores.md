# 深いワールドでの鉱石生成の実装報告

実施日: 2026-11-18

実装コミットID: `79e4abf30cbdb2b4e4e9435c56eb3bcbc0deb457`

## 経緯と原因

Tectonicなどでオーバーワールドの底を−192にすると、−64より下の洞窟に自Modの鉱石がほとんど出なかった。配置の高さがすべて絶対値（例：ウラン −48～32）で、ワールドの底が深くなっても範囲が変わらないため。高さの基準を底からの相対値に変えるだけでは、元の範囲の鉱石が薄くなるか、下へずれる。深さに応じて試行回数も増やす必要があり、バニラの配置データだけでは書けない。

## 実装内容

- 配置修飾子`create_refinery_n_reactors:deep_layer`（`worldgen/DeepLayerPlacement.java`、登録は`registry/CEWorldgen.java`）を追加した。`min_inclusive`～`max_inclusive`（VerticalAnchor）の範囲に、`per_16_blocks`×範囲の高さ÷16回（端数は確率で切り上げ）、一様な高さで試行する。範囲が逆転していれば何もしない。
- 元の下端が−32以下の深い鉱石4種（ウラン・クロム鉄鉱・チタン鉄鉱・ペントランド鉱）に`<鉱石>_deep`の配置を追加し、既存のbiome modifierの`features`へ並べた。範囲は底から8ブロック上～−64。密度は元の範囲の平均（回数×16÷高さ）で、ウラン0.79、クロム鉄鉱・チタン鉄鉱0.59、ペントランド鉱0.66。既存の配置（元の分布）は変えていない。
- 底が−64の通常のワールドでは、範囲が−56～−64と逆転するため空になる。
- 生成スクリプト`tools/generate_uranium_assets.py`に`deep_layer()`を追加し、`tools/generate_metal_ores.py`からも使うようにした。スクリプト全体は他の大量のアセットを再生成するため実行せず、同じ関数で書いたJSONが今回のファイルと一致することを確かめた。
- `docs/metals.md`に、深いワールドでの生成とデータパックでの変更方法を追記した。

## 確認結果

確認には開発用の専用サーバー（`runServer`）を使い、ゲームディレクトリを作業用フォルダに切り替えた。シード12345の通常ワールドで、スポーン周辺と256×256ブロック（449チャンク）を生成し、リージョンファイルを解析してブロック単位で高さ別に数えた。

- `compileJava` 成功。
- 深いワールドは、Tectonicを入れる代わりに、バニラのオーバーワールドのdimension_typeとnoise_settingsを`min_y` −192・高さ512へ変えたデータパックで再現した。−192～−65に4種が生成した（32ブロックごとに各2000～3000個前後）。元の範囲（−32～−1）の個数は変更前と同程度だった。

- 通常の深さのワールドで、変更前後を同じシード・同じ範囲で比べた。−64より下は存在せず、各高さ帯の個数は、個数の多い帯で変更前と±6%以内だった。個数の少ない−64～−33帯ではウラン493→573など最大16%の差がある。差は、地物の並びに配置が加わり、後続の地物の乱数がずれたため。「Empty height range」の警告は0件。

## 制約・未検証事項と次回の注意

- Tectonic本体と「CFS」では試していない。dimension_typeとnoise_settingsを深くした同等のワールドで確かめた。Tectonicの地形が−64より下で石・深層岩以外（独自の岩など）を使う場合、鉱石の置換対象（`stone_ore_replaceables`・`deepslate_ore_replaceables`）に入らず、生成されない。
- 深い範囲の上端は−64で、その上の−64～−33は元の台形分布の裾のため、深い範囲より少ない（通常のワールドと同じ）。
- 元の下端が−16以上の鉱石（ボーキサイト・ジルコン・錫石・輝水鉛鉱・岩塩・蛇紋岩）は浅い鉱石なので、深い範囲は追加していない。
- 配置が加わったため、新しく生成するチャンクでは後続の地物の乱数が変わり、同じシードでも鉱石の位置が以前と変わる。生成済みのチャンクには影響しない。
- シングルプレイのクライアントでは確認していない。GameTest全体は実行していない。
