- 実装コミット：`dddd84e`（機能追加）、`f3d26a1`（実機試験の作り直し）。通常のオーバーワールドで通す試験の元になった `950dc19` も同じブランチにある。
- 作業ブランチ：`verify/plant-playtest`（`main` を土台に、`work` の未プッシュ分を載せたローカルブランチ）
- Minecraft 1.21.1 / NeoForge 21.1.219 / Create 6.0.10 / Java 21

## 実装内容

### 1. クレーンの上限を拡張（4×4チャンクの掘削）

`CraneStructure` の上限を、レール長32→64、レール間隔18→65 にした。採掘範囲は「全長 × (レール間隔−1)」なので、最大で64×64ブロック（4×4チャンク）を掘れる。構造判定の探索量は上限に比例して増えるが、走査は未形成時と40 tickごとだけである。仕様書、日英翻訳と生成スクリプトの数値を一致させた。

### 2. 採掘範囲マーカー（新ブロック `quarry_marker`）と自動建設

支柱やレールを手で組む手間をなくすため、範囲を指定して置くだけで枠組みを建てる。

- マーカーを駆動部の隣、駆動部の軸の延長上に、掘る側へ向けて置く。レンチのValue Settingsで、上面に長さ（5～64）、正面に幅（3～64）を設定する。独自GUIは無い。
- 駆動部は、レッドストーン信号がある間、2 tickごとに1部材ずつ、四隅の脚3段、手前のレール、奥のレールの順に設置する。部材は駆動部の格納庫から消費する。
- マーカーは最初のレールに置き換わり、マーカーのアイテムは格納庫へ戻る。採掘モードに自動で切り替わる。
- 枠組みの位置の地形は、鉄のツルハシ相当で掘って格納庫へ入れる。掘れないブロック、満杯、材料不足、未ロードのときは止まり、状態と位置をゴーグルに出す。
- 枠組みが完成して構造が形成されると、格納庫のメカニカルドリルを自動で取り付け、レールの真下から掘り始める。
- 駆動部の搬入口は、ガントリーシャフト、クレーンの脚、メカニカルドリルも受け付ける（ファンネル等で補給できる）。

## 計算方法・仕様

- 枠組み：手前のレールは起点（マーカー位置）から長さ分、奥のレールは幅＋1ブロック離して同じ長さ。脚は四隅のレール位置の真下に3段（`MIN_LEGS`）。構造判定が要求する「四隅の脚の高さが等しい」を満たす。脚を先に置くのは、地面がレールを支える場所でレールだけで構造が形成され、脚が置かれずに建設が止まるのを避けるため（実機試験で見つかった）。
- 部材の総数：レール `2 × 長さ` ＋ 脚 12。64×64なら128＋12。
- 建設の周期：2 tickごとに1部材（最大140部材で約280 tick）。部材の位置が未ロードなら止まる。
- 進行はブロックの実在から毎回数え直すため、途中で壊されても続きを建てる。完成して形成されると建設計画は破棄する。

- GameTest（`tools/test_fuel_pool.ps1`、燃料プール・クレーンの関連）：17件すべて成功。新規は次の2件。

## 2×2チャンク（32×32）のクォーリー実機試験

`tools/create_rbmk_playtest.ps1 -Scenario quarry`（広さは `-Dcreateplant.quarryChunks`、既定2）。通常のオーバーワールド（ダークフォレスト）の2×2チャンクの敷地を、最も高い地面にそろえて整地し、駆動部とマーカー（32×32）、材料（ガントリーシャフト64、脚12、ドリル1）を入れてレッドストーン信号を与える。

| 項目 | 結果 |
| --- | --- |
| 自動建設 | 123 tickで枠組みが完成。レール長32、レール間隔33、脚の高さ3。マーカーは最初のレールになり、ドリルは自動で装着され、採掘モードになった |
| 掘削 | 範囲の上3層（掘れるブロック2,988個）を16,636 tickで掘り切り、2,968個を回収（掘れないブロックを除く） |
| 画像 | 建設中（手前のレールが伸びる様子）と完了後（32×32が掘り下がった様子）を撮影 |

この試験で、次の不具合が実機で見つかり、直した。

- 地面がレールを直接支える場所では、レールだけで構造が形成され、脚が置かれる前に建設が止まる。建設順を「脚、手前のレール、奥のレール」に変え、全部材が揃ってから形成されるようにした。
- 炉のない試験で、100 tickごとの記録が炉心を参照して例外になる（試験側の不具合）。炉心がないときは記録しないようにした。

回収が2,968個で、掘れる2,988個に20個足りないのは、ドロップのないブロックと、掘削中の枝や草などによる差とみられる。内訳は確認していない。

## 「最上段の1マスだけ掘って止まる」報告について

ユーザー報告のこの症状は、再現できていない。診断ログ付きの実機試験では、64×65の枠で1マスを約6 tickで掘り続け、停止しなかった。ログには、試験側の途中で内容物を空にする搬出（ファンネル相当）を含む。原因が手組みの構造（脚や支持の不備）か、別の条件かは未特定である。再発したときは、ゴーグルの状態表示（`status`）を確認すること。

## 未検証・制約

- **ゲーム内での実際の操作**（マーカーの設置、レンチでの設定、ゴーグルの表示、建設中の見た目）は、実クライアントで操作して確認していない。GameTestとPonderの描画での確認に留まる。
- **マーカーのモデルとゴーグルの表示**は、実クライアントの画面では確認していない（Ponderのアイコンのみ）。
- 64×64の採掘は、内容物が27スロットしかなく、ファンネルなどで搬出し続けないと満杯で止まる。試験は搬出役を置いた。
- 複数のクォーリー同時稼働のMSPT、チャンク境界をまたぐ長時間運転は測っていない。
- 枠組みを自動建設する範囲に、既存のレールや脚が混在している場合の挙動（正しい向きのものは再利用、違う向きは「掘れない」で停止）は、試験で確認していない。
- 既存の手組みの方法と、原子炉保守の動作は変更していない（原子炉保守の関連GameTestは成功）。
