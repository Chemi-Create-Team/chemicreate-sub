# ガスホルダー撤去・磁石レシピ復元・鉱物画像の適用

**訂正:** この作業で伸縮式まで撤去したのは誤りでした。ユーザーの追加指定に従い、伸縮式とその機能を復元しました。[復元レポート](telescopic-gas-holder-restoration.md)を参照してください。以下は撤去時点の履歴です。

実施日: 2026-11-12。開始点: `28a33dd7`。実装コミット: `f07738ea53de2ed3b8be6d7d264e18fb5dd39791`。

## 変更内容

伸縮式と旧球形のガスホルダーを廃止した。ブロック・アイテム・BlockEntity・可動筒エンティティ・Contraption・組立イベント・描画・計器出力・組立ガイド・Ponder・レシピ・モデル・テクスチャ・翻訳・タグを撤去した。ガスホルダーだけが生成していた汚染混合ガスと、その物性Component・特例処理も撤去した。既存の通常タンク、気体レシーバー、耐圧タンク、配管、フレアスタックは維持する。

廃止済みの製法を生成スクリプトが復活させないよう、関連する生成処理も削除した。通常タンクの実クライアント確認用コードからも、球形ホルダーの組立・撮影部分を除いた。過去の完了レポートとその画像・計測データは履歴として残す。[旧ホルダーの案内](../gas-bell.md)と[球形方式の案内](../gas-holder.md)は廃止を示すページへ変更した。

電磁石について、このリポジトリで上書きしていた対象は **Create Electro Energetics 1.21.1-1.1.4** の `electroenergetics:crafting/magnet_block`。解決済みの依存JAR内の原本を確認し、こちらの同名データパックJSONを削除した。鋼鉄インゴット4個を使わせる変更がなくなり、MOD本来の **Create鋼材ブロック4個＋安山岩合金1個→磁石4個** に戻る。Aeronautics本体のレシピへ新しい上書きは加えていない。

## 添付画像の適用

原石の表と画像のピクセル数には不一致があったため確認し、ユーザーから「画像の形を優先」の回答を得た。描き直さず、添付PNGの拡大ドット絵をそのまま16×16へ切り出した。AIによる再生成、補間、色数の追加、輪郭の水増しは行っていない。

- 鉱石用画像: 4列×4行。1タイル240 px、間隔248 px。先頭8枚が石版、後半8枚が深層岩版。
- 原石用画像: 4列×2行。1タイル256 px、間隔264 px。
- 背景の単色グレーだけを透過する。鉱石ブロックの母岩には引き続きMinecraft標準の石／深層岩を使う。
- 石版と深層岩版にはそれぞれの模様を登録。従来の共通オーバーレイから、8種類の深層岩用オーバーレイを分けた。
- 元画像は `tools/data/minerals/` に保存。`tools/mineral_reference_assets.py` がImageMagickで切出し・最近傍の縮小・背景透過を行う。既存の金属・塩素アルカリ・ウラン用生成処理からも同じ取込処理を呼ぶ。

## 検証

| 確認 | 結果 |
| --- | --- |
| Java・`build` | 成功。Gradleの全体終了コードは下記の既存GameTest失敗により1 |
| 全GameTest | 613件中612件合格。ガスホルダー用29件を撤去。残る失敗は既知の槽清掃試験1件 |
| 磁石の復元 | ロード後のレシピがCreate鋼材4個・安山岩合金1個・出力4個であることを確認 |
| 廃止・通常タンクの回帰 | 旧ブロック・BlockEntity・可動筒・流体の登録なし。球状に並べた鋼鉄も専用外殻へ変化しない。既存タンク・配管・フレアの試験を含む |
| 翻訳・Ponder | 日英中2,515キー、139シーン。旧ホルダー2シーンの撤去と参照・翻訳の整合を確認 |
| テクスチャ | 24枚とも元画像の可視RGB・透過境界と一致。再生成でバイト列も変わらない |
| 配布JAR | 旧設備のコード・アセット・磁石レシピ上書きの実ファイルが含まれず、深層岩モデル8種が専用模様を参照することを確認 |
| 実クライアント | NVIDIA RTX 4060で実行。24モデルの読込と、鉱石16ブロック・原石8個の額縁表示を実画面で確認。全139シーンのコンパイル・実行時翻訳と蛍石Ponderの描画を確認 |

既知の失敗は `VesselFoulingGameTests.aFouledProcessStopsThenResumesAfterOneManualBrush`。[前回の報告](belt-forging-and-fluorite.md)でも記録済みで、今回は清掃処理・その試験を変更していない。全GameTest正常終了とは扱わない。

初回の全体実行では、新しい「鋼鉄が自動変換されない」確認が、BlockEntityが存在しない場合に例外を出すGameTest用ヘルパーを使って失敗した。ワールドへの通常照会へ直し、全体を再実行して上記613件中612件の結果を得た。

実クライアントの[表示画像](../quality/gas-retirement/minerals-in-game.png)、[モデル確認結果](../quality/gas-retirement/client-mineral-result.json)、[Ponder確認結果](../quality/gas-retirement/client-ponder-result-ja_jp.json)、[試験ログ抜粋](../quality/gas-retirement/verification.txt)を保存した。画像はComputer Useで取得した。

クライアント内の確認は完了したが、終了時には既知の `libEGL_nvidia.so.0` 内のSIGSEGVが再発し、`runClient` のGradleタスクは終了コード134で失敗した。確認成功のログとプロセス終了障害を分け、正常終了とは扱わない。

再現用のコマンド:

```sh
bash gradlew --no-daemon -I docs/quality/gas-retirement/server.gradle build runGameTestServer
mc-debug bash gradlew --no-daemon -I docs/quality/gas-retirement/client.gradle runClient
python3 tools/mineral_reference_assets.py
python3 tools/validate_translations.py
python3 tools/validate_ponder_language.py
python3 tools/validate_plant_tutorials.py
```

Java 21と既存のGradle Wrapperを使用した。画像取込にはImageMagickの `convert` が必要。

## 制約・引き継ぎ

- 廃止した設備・アイテム・汚染混合ガスの自動移行は追加していない。旧設備のあるワールドは、更新前の版でガスを回収・設備を解体する。ユーザーの実ワールドは本作業で開いていない。
- 原石の不透明ピクセル数を表へ合わせる輪郭の変更は、ユーザーが選んだ方針に従い実施していない。
- 鉱石の採掘ドロップ、鉱床生成、製錬・化学レシピは変更していない。
- 過去のレポートの記述・画像・実行結果は当時の履歴であり、現行設備の一覧には含めない。
