# 旧mod IDの互換エイリアスの実装報告

実施日: 2026-11-18

実装コミットID: `eb01beca8b36f940a6a429e5549851b36d2aeb2c`

## 経緯と原因

mod IDを `create_heavy_indusstry` から `create_refinery_n_reactors` へ変えた `89354871` の後、改名前のワールドを開くと、自Modの鉱石がすべて消えた。チャンクには旧IDでブロックが保存されており、旧IDが未登録になったため、読み込み時に `Unknown registry key … -> using default` として空気へ置き換わっていた。置き換わったチャンクは、次の保存で空気のまま記録される。

「新しいチャンクにも鉱石が出ない」という報告は、改名後の版では再現しなかった。生成設定・jarの内容・データパックの有効化（NeoForgeの `mod_data` に一括で入る）に問題はない。旧版で探索した範囲の外周には、旧版が鉱石配置まで済ませた未完成チャンクが残る。改名後はそこで旧鉱石が空気になり、鉱石配置も再実行されないため、外周1〜2チャンク幅だけ鉱石がない。

## 実装内容

- `registry/CELegacyIds.java` を追加し、`CreatePlant` から登録した。
- 各 `RegisterEvent` の最後（`EventPriority.LOWEST`）に、その登録表の `create_refinery_n_reactors:<名前>` すべてに対して、`create_heavy_indusstry:<名前>` からのNeoForgeエイリアスを追加する。ブロック・アイテム・BlockEntity・流体・データコンポーネントなど、自Modが登録する静的な登録表すべてが対象になる。
- エイリアスは、旧IDが登録されていないときだけ新IDへ解決される。読み込み時にだけ参照され、tick処理や通信量は増えない。NeoForgeの登録スナップショットにも含まれる。
- AGENTS.mdの方針を、ID変更時に旧IDの互換処理を残すように改めた（`7497a932`）。

## 確認結果

確認には開発用の専用サーバー（`runServer`）を使い、ゲームディレクトリを作業用フォルダに切り替えた。シード12345の通常ワールドで行った。

- `compileJava` 成功。
- 改名直前の `60bae8ce`（`89354871` の親）で通常ワールドを作り、256×256ブロックを生成した。旧IDの鉱石10種と深層岩版が保存されていることを、リージョンファイルの解析で確認した。
- エイリアスなしの改名後の版でこのワールドを開くと、旧IDの鉱石ごとに未知IDのエラーが出て、空気へ置き換わった（再現）。離れた未生成範囲には、新IDの鉱石が新規ワールドと同程度に生成された。
- 同じワールドの改名前の複製を、エイリアスを入れた版で開いた。旧IDの未知IDエラーは0件だった。
  - 探索済みの完成チャンク（36,36）では、`fill … replace` で新IDの蛇紋岩247個・岩塩鉱石55個・イルメナイト鉱石15個・ウラン鉱石2個・深層岩ウラン鉱石12個・深層岩ペントランド鉱4個が見つかった。
  - 旧版が鉱石配置まで済ませていた外周の未完成チャンク（48,48）でも、蛇紋岩211個・岩塩鉱石46個・深層岩クロム鉄鉱14個が新IDで残っていた。

## 制約・未検証事項と次回の注意

- 改名後の版（エイリアスなし）で一度読み込まれ、保存されたチャンクの鉱石は空気として記録済みのため、エイリアスでは戻らない。戻すには改名前のバックアップが必要。
- 確認したのは鉱石ブロックだけ。チェスト・持ち物の中のアイテム、BlockEntity（装置の内容物）、タンク内の流体も同じ仕組みで解決されるはずだが、実際には確かめていない。
- 対応付けるのは直前のmod ID `create_heavy_indusstry` だけ。それより前の `create_plant`・`creators_electrolysis` のワールドは対象外。
- 改名と同時に名前（パス）が変わった登録は、新しい名前が別のため対応付けられない。
- 進捗・レシピ本などの、登録表ではなくデータパック由来のIDは対象外。
- シングルプレイのクライアント、他メンバーの実際のプレイ用ワールドでは確認していない。
- GameTest全体は実行していない。登録の追加だけで既存の処理を変えていないため、コンパイルと上記のサーバー確認に絞った。
