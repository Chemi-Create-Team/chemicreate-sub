# 装置内部の実温度（案A）

2026-11-23のユーザー指定による仕様書：「すべての装置に案Aを適用する」。案Aでは、装置の中だけ実際の温度（ケルビンの小数）と熱量で計算する。配管・バケツ・他Mod・表示・レシピ条件には、今の17段階を使う。[流体の状態](fluid-states.md)の温度の部分を更新する。圧力は今の17段階のまま変えない。

「要確認」と書いた項目は、ユーザーの指定がなく、仕様書を書く際に決めたもの。変更してよい。

2026-11-23のユーザー決定：蒸発熱を扱う。バーナーは点火中1 MW・超加熱2 MW（台数分を足す）。対向流の効率は0.9。反応熱を入れる。

## 決定事項

| 項目 | 決定 |
| --- | --- |
| 実温度を持つ場所 | 流体をためる装置とタンクの中（バッファー・在庫ごと） |
| 流体スタックのデータ | 今と同じ17段階の温度・圧力。細かい値は付けない |
| 配管 | 今と同じ。流体は段階のまま運ばれ、配管の中で温度は変わらない |
| 入ってきた流体 | その段階の代表温度として受け取り、中身と熱量で混ぜる |
| 出ていく流体 | 中身の実温度にもっとも近い段階で出す。丸めの差は中身の熱量に戻す |
| 相（液体・気体） | 装置の中では実温度と沸点で決める。出すときに相が変わらない段階を選ぶ |
| 表示 | ゴーグル・目盛り・計器は今と同じ17段階。実温度の数値は見せない |
| レシピの条件 | 今と同じ17段階。中身の実温度を段階に丸めて判定する |
| 蒸発熱・反応熱 | 扱う（ユーザー決定） |
| 対象外 | RBMK・核融合炉の内部計算は今のまま（すでに連続値）。圧力 |

## 1. 実温度の持ち方

- 装置の中の流体1つごとに（タンク1基、バッファー1つ、混合物なら混合物全体で1つ）、実温度`kelvin`（小数）を持つ。
- 熱容量は `量(mB) × 密度(kg/L) / 1000 × 比熱(J/kg/K)` で求める。密度・比熱は今の`FluidThermal`の表を使う。未登録の物質は水と同じ値を使う（要確認）。
- 気体の量は今と同じく常圧換算のmBで数え、密度も常圧の値を使う。
- ふだん液体の物質（ナフサ、冷えたオレフィンなど）が気体になっているときは、液体の密度を相変化の量の比率（`PhaseChange.ratio`）で割った値を使う。同じ質量が気体の体積に広がるので、相変化の前後で質量と熱容量が保たれる。水だけは、ゲームの換算が水1 mB＝蒸気1 mBなので液体の値のまま（2026-11-24の修正）。

### 1.1 入るとき

- 入ってきた流体の温度は、その段階の代表温度（`FluidState.kelvin(level)`）とする。
- すでに中身があれば、熱容量で重み付けした平均を新しい実温度にする。
  `T = (C中身 × T中身 + C入力 × T入力) / (C中身 + C入力)`
- 混ぜたあとで沸点をまたいだら、相を決め直す（3章）。

### 1.2 出るとき

- 出す段階は、中身の実温度にもっとも近い段階とする（`FluidState.temperatureLevel(kelvin)`）。
- 出した流体が持ち出す熱量は、その段階の代表温度で数える。中身の実温度と代表温度の差の熱量は、残った中身に戻す。
  `T残り = (C全体 × T − C出力 × T出力代表) / C残り`
- 連続して出すと、隣り合う2段階が交互に出る。平均すると、実温度どおりの熱量が運ばれる（誤差拡散）。
- 出す段階の相が中身の相と違う場合は、同じ相になるもっとも近い段階で出す。例：101 ℃の水蒸気はレベル9（94 ℃、液体）ではなく、レベル10（163 ℃、気体）で出す。
- 中身をすべて出す場合、戻し先がない差の熱量は「残熱」として装置に残す（1.3）。

### 1.3 残熱

- 残熱は、装置が持つ熱量（J、正にも負にもなる）。次に入ってきた流体に、入るときの熱量として足す。
- 中身1つ分の丸め誤差は、最大で段階の半分の幅にあたる熱量にとどまる。残熱はこの大きさを超えないように上限をかける。超えた分は捨てる（要確認）。
- 装置を壊したり、構造が解体されたりしたら、残熱は捨てる。
- 残熱があることで、出し入れを繰り返して熱を作ったり消したりすることはできない。

### 1.4 保存と互換

- 実温度は、装置のNBTのバッファーごとに`Kelvin`として保存する。残熱は`ResidualHeat`として保存する。
- `Kelvin`がない既存のワールドは、中身の段階の代表温度から始める。移行の処理はこれだけで、既存のブロック・中身は失われない。
- 実温度はクライアントへ送らない。表示は今と同じく段階を使うので、通信量は増えない。
- 段階が変わったときだけ、今と同じ経路で中身の変化を通知・同期する。実温度だけが変わったときは保存要求（`setChanged`）だけを出す。

## 2. 共通部品

- `thermal/`に、実温度・残熱・熱量計算・入出時の丸めをまとめた部品を1つ置く（仮名`HeatContent`）。
- 今の`ThermalFluidTank`は、この部品を中に持つ。`fill`・`drain`の中で1.1・1.2の処理を行う。今の量で重み付けした段階の平均（`FluidState.average`）は、この処理に置き換える。
- Createの流体タンク（`GradeTankMixin`）、タンクケーシング、横置きタンクなど、`ThermalFluidTank`を使わない在庫にも同じ部品を付ける。
- 照会とシミュレーション（`FluidAction.SIMULATE`）では、実温度も残熱も変えない。シミュレーションで返す段階は、実行したときと同じにする。

## 3. 相の決定

- 装置の中では、実温度と、圧力の段階から求めた沸点（今の`FluidState.boilingKelvin`）を比べて、相を決める。
- **蒸発熱**（ユーザー決定）：相が変わるときは蒸発熱（`chemistry/fluids.json`の`vaporizationHeat`、未登録ならトルートンの規則）を出し入れする。
  - 中身1つは相を1つしか持てない（タンクの在庫は1種類の流体のため）。そこで、沸点にある中身は、実温度を沸点に止めたまま「乾き度」（気体になった割合、0〜1）をためる。
  - 液体の中身を加熱し続けると、沸点で温度が止まり、乾き度が蒸発熱の分だけ上がる。乾き度が1になったら、中身全体を気体へ換算する（量の比率は今の`PhaseChange`）。冷却では逆に、気体が沸点で止まり、乾き度が0になったら液体へ換算する。
  - 乾き度の途中で中身を出した場合、出した分は今の相のまま、同じ乾き度の熱量を持ち出す（熱量は減った量に比例して減る）。
  - 換算で割り切れない分は元の相のまま残す（今と同じ）。
  - 熱交換器・ラジエーターなど通過型の装置は、1回の処理の生成物を出口バッファーへ入れる。出口バッファーも同じ規則（乾き度）で持つ。熱交換器の水蒸気の凝縮（`SteamCondensate`）は、凝縮熱を含めて今の水の取り出し口へ出す。
  - 乾き度は実温度と同じくNBTの`Quality`として保存し、クライアントには送らない。
- 混合気体は、今と同じく混合物全体で1つの温度を持ち、成分ごとの凝縮は扱わない（熱交換器の水蒸気の凝縮だけは上記のとおり残す）。

| 熱交換器（`ThermalEquipment`） | 段階の平均、または入れ替え | 2つの流れの熱容量と温度差から熱量を求めて移す |

| Createのボイラー（`TankBoiler`） | Createの熱量で蒸気を作る | 蒸気の生産量はCreateの規則のまま（互換）。出す蒸気の実温度を装置で持つ |

| RBMK・核融合炉 | 内部は連続値、出入口は段階 | 変更なし |

### 4.1 ブレイズバーナーによる加熱

- 底面の下で燃えているバーナー1台ごとに、熱出力を足す（今は何台あっても速さは同じ）。
- 熱出力（ユーザー決定）：点火中（加熱）1台で1 MW、超加熱で2 MW。8,000 mBの常温の水で、今とほぼ同じ時間（約2.5秒で1段階）になる値。
- 沸点では蒸発熱のぶん時間がかかる。例：8,000 mBの水は、1 MWで約18秒かけて気体になる。
- 量が多いタンクほど、比熱が大きい物質ほど、ゆっくり温まる。
- 上限は今と同じく超高温の代表温度（800 ℃）。
- 今の「同じ中身の加熱を続けた時間」（`HeatingTicks`・`HeatingBatch`）は使わなくなる。読み込み時には捨てる。
- ふた付き槽（撹拌反応槽を含む）の液体の水は、沸点に達した後の余った熱で、1 mBずつ蒸発する（2026-11-24）。1 mBに必要な熱は2,257 J（`Concentration.JOULES_PER_MB`）で、端数は次のtickへ持ち越す。沸騰中だけ毎tick（それ以外は10 tickごと）に計算するので、蒸気は一度に塊で出ず、バーナーの出力と残りの水量の分だけ出続ける。蒸気は槽のガス空間へ入り（ふたが開いていれば逃げる）、水は蒸気になった分だけ減る。反応の途中（撹拌の処理中や他の供給がある間）は、溶液の煮詰めと同じく蒸発させない。Createタンク・タンクケーシングなど他の容器は今まで通り（`TankHeating.boilWater`は既定でオフ）。

### 4.2 熱交換器

- 処理量は今と同じく、1回あたり`構造の段数 × 100 mB`を両方の流れから取る。
- 両方の流れの熱容量を`C1`・`C2`、小さい方を`Cmin`、温度差を`ΔT`とする。相が変わらない流れでは次の式になる。
  - **並行流**：両方が同じ温度になるまで熱を移す。`Q = C1 × C2 / (C1 + C2) × ΔT`
  - **対向流**：`Q = ε × Cmin × ΔT`。効率`ε`は0.9とする（ユーザー決定）。並行流より多く移せる。
- 途中で沸騰・凝縮する流れがあるときは、熱容量×温度差の代わりに、蒸発熱を含めた熱量（エンタルピー差）で同じ規則を使う（2026-11-24の修正）。
  - 対向流：熱い流れが冷たい入口温度まで冷えて出せる熱と、冷たい流れが熱い入口温度まで温まって受け取れる熱の、少ない方の0.9倍を移す。
  - 並行流：両側に同じ熱量を出し入れし、出口の温度が最初に一致するまでの移動量を求める。両側が同じ沸点に達した時点で熱交換は止まる。片側だけが沸点にある間は、乾き度の変化に使われる潜熱も計算する。
  - 顕熱だけで計算すると、気体（1 mBあたりの熱容量が液体の約1000分の1）の凝縮熱を移せず、液体の冷媒をいくら流しても凝縮しないため。
- 両方の流れから同じmBを取るので、気体の熱で同じ体積の液体を沸かすことはできない（10 mBの熱い水素の熱は、10 mBの液体窒素の蒸発熱の数百分の1）。液体を沸かすには、熱い液体を使う。
- 液体と気体では1 mBあたりの熱容量が約1000倍違うため、気体を冷やしても冷媒の水はあまり温まらない。
- 蒸気を冷やすと、凝縮熱も冷媒へ移る（3章）。
- 両方の出口に入りきることを確認してから一度だけ確定する、という今の規則は変えない。
- ゴーグルの出口温度の表示は、今と同じく段階名で出す。

### 4.3 ラジエーター・冷却塔

- ラジエーター：今の処理量の決め方（ファンの回転数×季節）を、放熱量（W）に読み替える。1回の処理で取り除く熱量を超えない範囲で、常温（25 ℃）に向かって下げる。常温より下げない。
- 放熱量の換算（要確認、案）：今の処理量で、水がおよそ1段階下がる熱量に合わせる。
- 冷却塔：今の処理量で、常温まで下げきれる放熱量とする（要確認）。

### 4.4 コールドボックス

- 冷凍能力（W）は、今の回転動力の計算（`WATTS_PER_RPM`）から求める。
- 気体の顕熱を取り除いて沸点まで下げ、凝縮熱を取り除いて液体にする。液化した分を出す。
- 取り除いた熱量と使った動力の和を、冷却水の熱量に足す（今の「常温寄りで出す」を置き換える）。

## 5. 反応熱

- レシピのJSONに、任意の`reaction_heat`（1バッチあたりのJ。発熱が正、吸熱が負）を足せるようにする。
- 値の正本は`tools/data/reaction_heat.json`（レシピ名→J）。生成スクリプトはここからレシピのJSONへ書き写すので、スクリプトを再実行しても消えない（2026-11-24）。
- `reaction_heat`のあるレシピ：生成物は、指定の段階ではなく、反応した時点の中身の実温度で入れる。そのうえで反応熱を中身に足す（吸熱なら引く）。指定の段階と反応熱を二重に数えないため。
- `reaction_heat`のないレシピ：今と同じく、生成物を指定の段階の代表温度で入れる。
- 吸熱反応で中身が冷えても、バーナーの加熱条件（加熱・超加熱）による判定は今のまま。
- 値は標準生成エンタルピーから、1バッチの物質量（mBを密度・分子量でmolに換算）を使って求める。登録するのは、反応熱が工程に効く主なレシピに限る（アンモニア合成、燃焼、FT合成、メタノール合成、水性ガスシフト、中和、焼成、水蒸気改質など）。登録したレシピと値は完了レポートに一覧で残す。
- JEIでは、反応熱のあるレシピに「発熱」「吸熱」とだけ表示する（数値は出さない）。

## 6. 性能

- 実温度の計算は、今も装置が中身を処理しているtickの中でだけ行う。止まっている装置、空の装置では計算しない。
- 1バッファーにつき小数2つ（実温度・残熱）と、相の量を増やすだけ。高頻度の経路で新しいオブジェクトは作らない。
- クライアントへの通信は増えない（1.4）。

## 9. 受け入れ条件

- 段階が同じ流体は、今と同じく Create・NeoForge・他Modのタンクで混ざる。流体スタックに新しいデータが付いていない。
- 熱量の保存：装置へ入れた熱量と、出した熱量、中身と残熱の合計が一致する。出し入れを繰り返しても、熱が増えない。
- 熱交換器に一定の流れを送ると、出口の段階の平均が、熱量の計算どおりの温度になる。
- 量の違うタンクで、温まる時間が熱容量に比例する。
- シミュレーションと照会で、実温度・残熱・中身が変わらない。
- 保存して読み込み直すと、実温度と残熱が保たれる。`Kelvin`のない既存のワールドを読み込むと、代表温度から動き始める。
- 構造の解体・再形成で、熱が増えない。
- 沸点で温度が止まり、蒸発熱の分の時間をかけて相が変わる。
- 反応熱を登録したレシピで、発熱反応は中身を温め、吸熱反応は冷やす。
- 専用サーバーで読み込める（クライアント専用のクラスを参照しない）。

- 圧縮による温度上昇。圧力の連続値。
- 混合気体の成分ごとの凝縮、臨界点。
- 実温度の数値の表示。
